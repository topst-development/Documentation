# 2. 視訊輸出
---
AI-G 支援透過 MIPI DSI-2 介面進行視訊輸出。
它透過 15-pin FFC 接頭提供 2-lane DSI 連接，適合連接相容的 MIPI DSI LCD 面板。此介面可在嵌入式顯示器上流暢呈現圖形使用者介面、視訊播放以及即時 AI 視覺化畫面。
<br/><br/><br/>

## 2.1 MIPI DSI
---
DSI 代表 Display Serial Interface，是由 MIPI Alliance 制定的標準，用於將顯示資料從處理器傳輸至外部螢幕。它可提供高速、低功耗的通訊，適用於嵌入式 LCD 面板。  
如上所述，AI-G 透過 15-pin FFC 接頭提供 2-lane DSI 連接，可連接相容的 MIPI DSI 顯示模組，用於 GUI 呈現、視訊播放或即時推論視覺化。
<br/><br/>

### 2.1.1 5 吋 DSI 顯示器
Elecrow 5 吋 DSI 顯示器是一款 800×480 解析度的 LCD，採用 IPS 面板並支援電容式觸控，專為搭配 Raspberry Pi 的 MIPI DSI 介面而設計。由於具備隨插即用功能，無須額外安裝驅動程式。此顯示器透過 15-pin MIPI DSI 接頭連接至 AI-G 開發板，並直接由該介面供電，因此不需要外接電源。  
此模組適用於 AI-G 平台上以 GUI 為基礎的應用程式、即時監控以及互動式 AI 展示。

DSI 顯示器的規格如下：

| 規格 | 說明 |
| ------------------- | -------------------------------------------|
| 顯示器尺寸 | 5 吋 |
| 解析度 | 800 x 480 |
| 更新率 | 60 Hz |
| 介面（顯示器） | MIPI DSI |
| 介面（面板） | RGB888 連接埠 |
| 工作電壓 | 3.3V |
| 工作溫度範圍 | -20 °C 至 70 °C |
| 排線類型 | Flat Flexible Cable (FFC)（15-pin） |
| 相容性 | Raspberry Pi 與 AI-G（透過 MIPI DSI 介面） |

# 3. 攝影機連接
---
AI-G 支援透過 MIPI CSI-2 介面進行攝影機輸入。
預設情況下，它透過 15-pin 接頭提供 2-lane CSI 連接。對於需要更高頻寬的應用，例如高解析度或高影格率的 AI 視覺任務，亦可透過選購的 20-pin 接頭支援 4-lane 設定。
<br/><br/><br/>

## 3.1 MIPI CSI
---
CSI 代表 Camera Serial Interface，是由 MIPI Alliance 制定的標準介面，用於將攝影機模組連接至主處理器。它可讓影像資料以高速、低功耗的方式從攝影機傳輸至處理器。  
如上所述，AI-G 預設提供 2-lane CSI 連接，並可選擇透過 20-pin 接頭支援 4-lane 設定，以獲得更高的資料吞吐量。  

目前 AI-G 僅支援 ArduCam（5 MP）與 Raspberry Pi v1 Camera（5 MP）模組。
<br/><br/>

### 3.1.1 ArduCam
ArduCam 是專為嵌入式系統與 AI 應用設計的多功能攝影機模組。它支援多種影像感測器與介面，包括 MIPI CSI，因此適合與 AI-G 這類開發板整合。  
AI-G 支援具備 2-lane 或 4-lane MIPI CSI 介面的 ArduCam 模組，可為物件偵測與影像分類等 AI 視覺任務提供穩定的影像輸入。由於相容於 FFC 排線，ArduCam 模組可輕鬆連接至 AI-G 開發板的 CSI 接頭，為邊緣 AI 系統中的即時攝影機輸入提供可靠的解決方案。

ArduCam 模組的規格如下：

| 規格 | 說明 |
| ------------------------ | ------------------------------------------- |
| 感測器 | OV5647（500 萬畫素） |
| 解析度 | 2592 × 1944（完整 5MP） |
| 支援的輸出格式 | RAW、YUV、JPEG（視感測器而定） |
| 介面 | MIPI CSI |
| 影格率 | 1080p 最高 30fps，720p 最高 60fps |
| 鏡頭座 | 定焦鏡頭（標準） |
| 視野角（FOV） | 約 54° 至 70°（依型號而異） |
| 連接類型 | FFC |
| 工作電壓 | 3.3V（典型值） |
| 外型規格 | 精巧 PCB，約 25 mm x 24 mm |
| 相容性 | Raspberry Pi 與 AI-G（透過 MIPI CSI 連接埠） |
| 其他特性 | 低功耗、隨插即用模組 |

# 4. 儲存裝置連接
---
本章說明如何將 AI-G 開發板連接至各種儲存裝置。支援的儲存選項包括透過 PCIe 連接的外接儲存裝置。
<br/><br/><br/>

## 4.1 NVMe M.2 SSD
---
AI-G 支援透過其 PCIe 插槽連接 M.2 SSD 儲存裝置。

#### 步驟 1. 連接 SSD
- NVMe SSD (M.2 PCIe)：請將 NVMe M.2 SSD 插入 AI-G 開發板的 PCIe 插槽。 

<p align="center"><img src="https://raw.githubusercontent.com/topst-development/Documentation/refs/heads/main/Assets/TOPST%20AI-G/Available%20Applications/4.2.1%20AI-G%20NVME%20M.2%20SSD%20connection.png" width="600"></p>
<p align="center"><strong>圖 4.1 將 NVMe M.2 SSD 連接至 AI-G 開發板 </strong></p><br/>

#### 步驟 2. 啟動 AI-G
執行 **reboot** 命令後，請觀察開機記錄，確認系統已辨識到 PCIe 裝置。
請尋找類似 **"telechips-pcie: Link up"** 的訊息，這表示 PCIe 連結已成功建立。

```
$ reboot
...
Starting kernel ...

[    1.207844] telechips-pcie 12000000.pcie: invalid resource
[    1.232395] telechips-pcie 12000000.pcie: Link up
[    1.521983] debugfs: Directory '18300000.dma' with parent 'dmaengine' already present!
[    1.531159] debugfs: Directory '18310000.dma' with parent 'dmaengine' already present!
[    1.540282] debugfs: Directory '18320000.dma' with parent 
...
ai-g-topst login: 
```

#### 步驟 3. 確認 SSD 是否被辨識

```
root@ai-g-topst:~# lspci
00:00.0 PCI bridge: Synopsys, Inc. Device 750b (rev 01)
01:00.0 Non-Volatile memory controller: Silicon Motion, Inc. SM2263EN SM2263XT SSD Controller (rev 03)
```

#### 步驟 4. 掛載 SSD
```
$ fdisk /dev/nvme0n1
Welcome to fdisk (util-linux 2.37.4).
Changes will remain in memory only, until you decide to write them.
Be careful before using the write command.

Command (m for help): 
```

請在 fdisk 提示字元中依序輸入下列按鍵：

- o — 建立新的空白 DOS 分割區表（選用，會清除現有的分割區表）

- n — 新增一個分割區

- p — 選擇主要分割區

- 1 — 將分割區編號設為 1

- 按下 Enter — 接受預設的起始磁區

- 按下 Enter — 接受預設的結束磁區（使用整顆磁碟）

- w — 寫入分割區表並離開

```
$ mkfs.ext4 /dev/nvme0n1p1

$ mkdir -p /mnt/nvme

$ mount /dev/nvme0n1p1 /mnt/nvme
```

#### 步驟 5. 執行結果
此輸出確認系統已成功偵測到 NVMe SSD 裝置 (/dev/nvme0n1p1)，並將其掛載於 /mnt/nvme。

# 5. 乙太網路連接
---
AI-G 支援透過板載 RJ45 乙太網路連接埠進行網路連線。這讓開發板可使用標準 TCP/IP 通訊協定與區域網路或網際網路通訊。乙太網路常用於部署需要遠端存取、資料串流或軟體更新的 AI 應用程式。
<br/><br/><br/>

## 5.1 透過路由器連接網路
---
此方法使用標準路由器將 AI-G 連接至區域網路。開發板可透過 DHCP 自動取得 IP 位址，或設定為靜態 IP 位址。
<br/><br/>

### 5.1.1 將根檔案系統重新掛載為可讀寫
根檔案系統是以唯讀方式掛載。請使用下列命令以寫入權限重新掛載，以便編輯設定檔：

```
$ mount -o remount,rw /
```
<br/><br/>


### 5.1.2 建立網路設定檔
1. 透過 DHCP 取得動態 IP
請以下列內容建立或編輯 /etc/systemd/network/20-wired.network 檔案，以在 eth0 介面上啟用 DHCP。

```
$ vi /etc/systemd/network/20-wired.network
 
[Match]
Name=eth0
 
[Network]
DHCP=yes
```

此設定會指示 systemd-networkd 為 eth0 介面透過 DHCP 自動取得 IP 位址。

2. 靜態 IP 設定
若您想指定靜態 IP 位址（例如直接與 PC 連接，或沒有可用的 DHCP 伺服器時），請以下列內容編輯同一個檔案：
```
$ vi /etc/systemd/network/20-wired.network

[Match]
Name=eth0

[Network]
Address=192.168.137.2/24
Gateway=192.168.137.1
DNS=8.8.8.8
```

這會將 IP 位址設為 192.168.137.2，並使用 192.168.137.1 作為閘道（Windows ICS 常見的設定），同時設定 Google DNS。
<br/><br/>


### 5.1.3 重新啟動網路服務
請重新啟動 systemd-networkd 服務以套用新的網路設定：

```
sudo systemctl restart systemd-networkd
```
<br/><br/>

# 6. 40-pin GPIO 排針
---
AI-G 配備 40-pin GPIO 排針，可為各種硬體專案提供彈性的 I/O 功能。
此排針相容於通用輸入／輸出（GPIO）操作，可用於連接感測器、LED、按鈕及其他周邊裝置。

每個腳位依設定可支援數位 I/O、I2C、SPI 或 UART 功能。

## 6.1 GPIO 數位輸入／輸出
---
AI-G 開發板可透過 40-pin 排針支援數位輸入與輸出（GPIO），讓使用者能與按鈕、LED 及感測器等外部裝置互動。 
<br/><br/><br/>

### 6.1.1 LED
---
控制 LED 是最簡單也最常見的 GPIO 輸出範例之一。  
為了示範數位輸出，可將 LED 連接至 40-pin 排針上的其中一個 GPIO 腳位。在此範例中，LED 的陰極（短腳）連接至 AI-G 開發板上的 GND 腳位，陽極（長腳）則直接連接至 GPIO72。

#### 步驟 1. 硬體需求
- AI-G 開發板 (x1)
- 麵包板 (x1)
- LED (x1)
- 公對母杜邦線 (x2)
- DC 5V 電源供應器 (x1)
- USB 轉 TTL 序列傳輸線 (x1)

#### 步驟 2. 範例電路
- LED
    - (+) 腳位連接至 AI-G 開發板上的 pin 26。
    - (-) 腳位連接至 AI-G 開發板上作為 GND 的 pin 14。

#### 步驟 3. 執行方式
若要操作連接至 AI-G 開發板 GPIO72 的 LED，請執行下列程式碼：

```bash
#!/bin/bash

GPIO=72
INTERVAL=1

# GPIO export
if [ ! -e /sys/class/gpio/gpio$GPIO ]; then
    echo "$GPIO" > /sys/class/gpio/export
    sleep 0.1
fi

echo "out" > /sys/class/gpio/gpio$GPIO/direction

trap "echo $GPIO > /sys/class/gpio/unexport; echo -e '\nGPIO$GPIO unexported. Exit.'; exit" SIGINT

echo "Toggling GPIO$GPIO every $INTERVAL second(s). Press Ctrl+C to stop."

while true; do
    echo 1 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
    echo 0 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
done
```

#### 步驟 4. 執行結果
請使用下列命令執行程式碼。
```
$ ./AI_GPIO_LED_TEST
```

此腳本會將 GPIO72 設定為數位輸出，並每隔 1 秒持續切換其狀態。執行後，連接至 GPIO72 的 LED 會反覆閃爍，亮 1 秒後再熄滅 1 秒，如此無限循環。

若要停止腳本，請按 **[Ctrl+C]**。  
腳本結束時，GPIO72 會自動取消匯出並完成清理。  
執行前請確認已賦予腳本執行權限：
```bash
$ chmod +x AI_GPIO_LED_TEST
```

**註**：此配置未包含限流電阻。雖然短時間測試可能可以運作，但建議在 LED 上串聯一顆電阻，以避免可能損壞 GPIO 腳位。

## 6.2 I2C
---
AI-G 透過 40-pin GPIO 排針提供 I2C 通訊，可與感測器、顯示器與擴充模組等各種周邊裝置介接。Inter-integrated Circuit (I2C) 是一種雙線式通訊協定，由一條資料線 (SDA) 與一條時脈線 (SCL) 組成，可讓多個裝置在共用匯流排上進行通訊。

I2C 通訊採用主從式架構，由一個主控裝置控制通訊，同一匯流排上最多可連接 127 個從屬裝置。SDA 線同時用於傳送與接收資料，而 SCL 線則負責同步資料傳輸的時序。此同步通訊模式可讓裝置以協調一致、由時脈驅動的方式交換資訊。
<br/><br/><br/>

以下是一個簡單的範例 (I2C_TEST.c)：

```
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <linux/i2c-dev.h>
#include <sys/ioctl.h>
#include <unistd.h>

#define I2C_DEV "/dev/i2c-1"
#define I2C_ADDR 0x27

// RS: 0 = command, 1 = data
void lcd_send_byte(int fd, unsigned char data, unsigned char mode) {
    unsigned char high = mode | (data & 0xF0) | 0x08; // backlight on
    unsigned char low  = mode | ((data << 4) & 0xF0) | 0x08;
    unsigned char buf[4] = { high | 0x04, high, low | 0x04, low }; // toggle EN bit

    for (int i = 0; i < 4; i++) {
        if (write(fd, &buf[i], 1) != 1) {
            perror("I2C write error");
        }
        usleep(1000); // 1ms delay
    }
}

void lcd_command(int fd, unsigned char cmd) {
    lcd_send_byte(fd, cmd, 0x00);
}

void lcd_data(int fd, unsigned char data) {
    lcd_send_byte(fd, data, 0x01);
}

void lcd_init(int fd) {
    usleep(50000); // wait for LCD power on
    lcd_command(fd, 0x33); // init
    lcd_command(fd, 0x32); // 4-bit mode
    lcd_command(fd, 0x28); // 2 line, 5x8 font
    lcd_command(fd, 0x0C); // display on, cursor off
    lcd_command(fd, 0x06); // entry mode
    lcd_command(fd, 0x01); // clear display
    usleep(2000);
}

void lcd_print(int fd, const char* str) {
    while (*str) {
        lcd_data(fd, *str++);
    }
}

int main() {
    int fd = open(I2C_DEV, O_RDWR);
    if (fd < 0) {
        perror("Failed to open I2C device");
        return 1;
    }

    if (ioctl(fd, I2C_SLAVE, I2C_ADDR) < 0) {
        perror("Failed to set I2C address");
        close(fd);
        return 1;
    }

    lcd_init(fd);
    lcd_print(fd, "test pass!");

    close(fd);
    return 0;
}
```

## 6.3 SPI
---
AI-G 透過 40-pin GPIO 排針支援 Serial Peripheral Interface (SPI) 通訊，可在外部裝置與開發板之間交換資料。  

SPI 是一種同步序列通訊協定，可實現全雙工通訊，亦即資料能同時傳送與接收。它使用四條主要訊號線：Master Out Slave In (MOSI)、Master In Slave Out (MISO)、Serial Clock (SCLK) 與 Slave Select (SS)。

與使用共用訊號線連接多個裝置的 I2C 不同，SPI 需要為每個從屬裝置提供專用的 SS 線。此一對多的架構使 SPI 速度快且易於實作，但在連接多個裝置時會需要較多的實體接線。
<br/><br/><br/>

```
#include <stdio.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>
#include <linux/spi/spidev.h>
#include <sys/ioctl.h>
#include <string.h>

#define SPI_DEV "/dev/spidev3.0"

int spi_fd = -1;

void spi_send(uint8_t address, uint8_t data) {
    uint8_t tx[2] = { address, data };
    struct spi_ioc_transfer tr = {
        .tx_buf = (uintptr_t)tx,
        .rx_buf = 0,
        .len = 2,
        .delay_usecs = 0,
        .speed_hz = 1000000,
        .bits_per_word = 8,
    };

    if (ioctl(spi_fd, SPI_IOC_MESSAGE(1), &tr) < 1) {
        perror("SPI send failed");
    }
}

void max7219_init() {
    spi_send(0x09, 0x00); // Decode mode off
    spi_send(0x0A, 0x08); // Brightness (0x00 ~ 0x0F)
    spi_send(0x0B, 0x07); // Scan limit: display all 8 digits
    spi_send(0x0C, 0x01); // Shutdown register: normal operation
    spi_send(0x0F, 0x00); // Display test: off
}

void max7219_clear() {
    for (int i = 1; i <= 8; i++) {
        spi_send(i, 0x00);
    }
}


const uint8_t letter_P[8] = {
    0b00000000,  
    0b01111110, 
    0b01000010,  
    0b01000010,  
    0b01111110,  
    0b01000000,  
    0b01000000,  
    0b01000000   
};


void draw_letter_P() {
    for (int row = 0; row < 8; row++) {
        spi_send(row + 1, letter_P[row]);
    }
}

int main() {
    spi_fd = open(SPI_DEV, O_RDWR);
    if (spi_fd < 0) {
        perror("Failed to open SPI device");
        return 1;
    }

    max7219_init();
    max7219_clear();
    draw_letter_P();

    close(spi_fd);
    return 0;
}
```

## 6.4 UART
---
AI-G 透過其 40-pin GPIO 排針支援 Universal Asynchronous Receiver/Transmitter (UART) 通訊，可與序列主控台及其他微控制器等裝置進行序列通訊。  

UART 是一種廣泛使用的非同步通訊協定，透過兩條訊號線 TX（傳送）與 RX（接收）逐位元傳輸資料。與 I2C 或 SPI 不同，UART 不使用時脈線，而是必須讓兩個裝置採用共同的通訊速率作為時序依據。
<br/><br/><br/>

### 6.4.1 UART 回送測試
---
UART 回送測試是驗證 AI-G 上 UART 通訊是否正常運作的簡便方法。  
將 TX 與 RX 腳位相互連接後，從開發板送出的任何資料都會立即被接收回來。  
此測試可在 Linux 終端機中執行，方式是將資料寫入 UART 裝置後再讀回。

- AI-G 開發板 (x1)
- 母對母杜邦線 (x1)

#### 步驟 3. 執行方式
此腳本會將測試訊息傳送至 UART 連接埠，並檢查是否收到相同的訊息。  
若要在 AI-G 上測試 UART 回送，請在將 TX 與 RX 腳位相互連接後執行以下腳本。

```bash
#!/bin/bash
# ===================== user setting =====================
UART_DEV="/dev/ttyAMA1"       # uart
BAUD=115200                   # Baudrate
TEST_MSG="Hello from UART"    # msg
TEMP_FILE="/tmp/uart_rx.txt"  # file
# =====================================================

if [ ! -e "$UART_DEV" ]; then
    echo "Error: $UART_DEV does not exist"
    exit 1
fi

chmod 666 $UART_DEV

stty -F $UART_DEV $BAUD cs8 -cstopb -parenb -icanon -echo -ixon -ixoff
echo "UART setup complete: port=$UART_DEV, speed=$BAUD"

cat $UART_DEV > $TEMP_FILE &
RX_PID=$!

sleep 0.2
echo -n "$TEST_MSG" > $UART_DEV
echo "Transmission complete: \"$TEST_MSG\""

sleep 1
kill $RX_PID 2>/dev/null

if [ -f "$TEMP_FILE" ]; then
    RECEIVED=$(cat $TEMP_FILE)
    rm $TEMP_FILE
    if [ "$RECEIVED" = "$TEST_MSG" ]; then
        echo "Loopback Success! Received Message: \"$RECEIVED\""
    else
        echo "Received mismatch"
        echo "Sent: \"$TEST_MSG\""
        echo "Received: \"$RECEIVED\""
    fi
else
    echo "Failed to receive: No received file"
fi
```

#### 步驟 4. 執行結果
請使用下列命令執行程式碼。
```
$ ./AI_UART_LOOPBACK_TEST
```

此腳本會設定指定的 UART 連接埠並傳送測試訊息。若 TX 與 RX 腳位連接正確，相同的訊息會被接收回來並列印至終端機，確認 UART 的傳送與接收運作正常。

執行前請確認已賦予腳本執行權限：
```bash
$ chmod +x AI_UART_LOOPBACK_TEST
```
