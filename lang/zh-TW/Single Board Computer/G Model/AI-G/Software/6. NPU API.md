# 1. 簡介
---
Neural Processing Unit (NPU) 是硬體類神經網路加速器，AI-G 中的 NPU 已針對視覺應用（例如物件偵測、影像分類與人臉偵測）的 
類神經網路推論進行最佳化。NPU 驅動程式 
提供控制 NPU 的介面，讓使用者空間中的類神經網路應用程式能夠在嵌入式 Linux 環境中使用 AI-G NPU 進行類神經網路 
推論。

本文件說明如何使用 AI-G SDK 中隨附的 NPU 驅動程式與 NPU API。
<br/><br/><br/><br/>


# 2. NPU Linux 驅動程式
---
NPU 驅動程式負責控制：

- NPU 硬體的初始化
- 將編譯後的類神經網路傳送至 NPU 硬體
- NPU 硬體的執行
- 讀取 NPU 硬體的處理（推論）結果。

NPU 驅動程式使用的緩衝區（code、weight、work、input 與 output）需要連續的實體記憶體空間。基於此 
原因，記憶體上的緩衝區是在內部使用 Continuous Memory Allocator (CMA) 進行配置。
NPU 驅動程式接收編譯後類神經網路的命令檔案與 weight/bias 檔案作為輸入，以產生網路 
檔案描述子 (fd)。它也會配置類神經網路的輸入以及用於儲存結果的緩衝區，並產生 buffer fd 以存取 
每個緩衝區。 

若要執行推論，
1. 請對輸入緩衝區的 buffer fd 執行 mmap，以取得可從使用者空間存取的輸入緩衝區位址。
2. 請使用步驟 1 中取得的輸入緩衝區位址，將輸入影像儲存至輸入緩衝區。
3. 請將名為 NPU_NET_IOCTL_RUN 的 IOCTL 傳送至 network fd。

當執行兩個以上的類神經網路時，NPU 驅動程式會以分時演算法執行類神經網路。 
在此情況下，類神經網路會依照使用者空間要求的順序執行，因為執行順序是在內部 
使用 queue.f 命令進行排程。

## 2.2 Device Tree
---
以下範例是在 AI-G 中使用 NPU 驅動程式的 device tree。

```
# NPU device tree example

 npu0: npu@11000000 {
                compatible = "telechips,npu";
                reg = <0x0 0x11000000 0x0 0x400>;
                interrupts = <GIC_SPI 153 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_0_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_0_CCLK &fbus_npu FBUS_NPU_0_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };


npu1: @11000400 {
                compatible = "telechips,";
                reg = <0x0 0x11000400 0x0 0x400>;
                interrupts = <GIC_SPI 154 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_1_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_1_CCLK &fbus_npu FBUS_NPU_1_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };

```

<br/>

|     屬性         |              說明                     |
|------------------|---------------------------------------|
| compatible       | 固定為 “telechips,npu”              |
| reg              | NPU 暫存器的基底位址與大小                   |
| disable-ue-fail  | 停用因 UE 錯誤造成的失敗。 <br>若 disable-ue-fail 為 0，偵測到 UE 錯誤時會回傳失敗。 <br>或 <br>若 disable-ue-fail 為 0x7，則忽略 UE 錯誤。                                      |
| disable-ce-fail  | 停用因 CE 錯誤造成的失敗。 <br>若 disable-ce-fail 為 0，偵測到 CE 錯誤時會回傳失敗。 <br>或 <br>若 disable-ce-fail 為 0x7，則忽略 CE 錯誤。                                           |
| disable-wdt      |  停用 watchdog 計時器                 |
| wdt-timeout-count| Watchdog 逾時計數                     |
| wdt-rearm-count  | Watchdog 重新啟動計數<br>此值應小於 watchdog 逾時計數。   |
| reg-names        | NPU 暫存器名稱                        |
| work-buffer-size | Work 緩衝區配置大小                   |
| interrupt-parent | 中斷控制器的 device tree 節點         |
| interrupts       | 中斷編號                              |

### 2.3.1 NPU 檔案描述子的 IOCTL 命令

NPU 檔案描述子可透過開啟 NPU 裝置檔案取得，例如
/dev/npu0 與 /dev/npu1。可用的 IOCTL 命令如下。


|      命令              |        引數             |        說明             |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req*  | 配置 CMA 緩衝區          |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req*   | 載入網路                 |
| NPU_IOCTL_READ_REG     | struct reg_access_req* | 從暫存器讀取數值         |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req* | 將數值寫入暫存器         |
| NPU_IOCTL_RESET_NPU    | struct npu_init_req*   | 重設 NPU                 |
| NPU_IOCTL_WRITE_TEST_CFG| test_cfg_wr_req_t*    | 寫入 ecc_test           |
| NPU_IOCTL_READ_NPU_ERR | npu_err_rd_req_t*      | 讀取 ECC 與 WDT          |

<br/>

NPU_IOCTL_ALLOC_BUFFER 命令 
- 使用透過結構 buffer_alloc_req 傳遞的
size 值配置 CMA 緩衝區，並且
- 回傳緩衝區檔案描述子。

NPU_IOCTL_LOAD_NETWORK 命令 
- 配置 CMA 緩衝區以儲存透過結構 net_load_req 傳遞的參數，
- 將參數複製至所配置的 CMA 緩衝區，並且 
- 回傳網路檔案描述子。

NPU_IOCTL_WRITE_TEST_CFG 與 NPU_IOCTL_READ_NPU_ERR 是透過 
test_cfg_wr_req_t 傳送的 NPU 測試參數值，兩者皆用於讀取測試結果值。

### 2.3.2 網路檔案描述子的 IOCTL 介面

網路檔案描述子可透過將
NPU_IOCTL_LOAD_NETWORK 命令傳遞給 NPU 檔案描述子來建立。它支援
poll 與 close 等操作。可用的 IOCTL 命令如
下。

<br/>

|         命令               |         引數             |         說明             |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req*     | 執行推論                 |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req* | 分析推論週期             |
| NPU_NET_IOCTL_SET_COLOR_FMT | int                      | 設定輸入色彩格式         |

<br/>

執行 NPU_NET_IOCTL_RUN 時，NPU 驅動程式會將執行網路的命令
傳送至 NPU 硬體，而推論結束的時間點可透過呼叫 poll
來確認。

### 2.3.3 緩衝區檔案描述子的 IOCTL 介面

緩衝區檔案描述子： 
- 可透過將 NPU_IOCTL_ALLOC_BUFFER 命令傳送至 NPU 檔案描述子來產生。 
- 支援 mmap、close 等操作。 
- 不支援 IOCTL 命令 
- 透過 mmap 操作從使用者模式取得 CMA 緩衝區
- 透過 close 操作釋放 CMA 緩衝區。
