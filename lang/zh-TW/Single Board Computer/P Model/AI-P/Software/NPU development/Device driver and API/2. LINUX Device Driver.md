# 2. NPU LINUX 裝置驅動程式

TOPST AI 的 NPU 是硬體類神經網路加速器。它針對視覺應用的
類神經網路推論進行最佳化，例如物件偵測、影像分類
與人臉偵測。
「TOPST-AI-Common-SW-NPU-Toolkit Guide」文件說明如何
使用 NPU Toolkit。

1.  NPU 裝置驅動程式負責控制 NPU HW 的初始化、將編譯後的類神經網路傳送至 NPU HW、執行 NPU
    HW，以及讀取 NPU HW 的處理（推論）結果。
2.  NPU 裝置所使用的緩衝區（code、weight、work、input 與 output）
    需要連續的實體記憶體空間。
    因此，記憶體上的緩衝區會在內部使用
    Continuous Memory Allocator (CMA) 進行配置。
3.  NPU 裝置驅動程式接收編譯後類神經網路的 command 檔案與
    weight/bias 檔案作為輸入，以產生 network 檔案描述子
    (fd)。
4.  它同時負責配置類神經網路的輸入以及用來儲存結果的
    緩衝區，並產生可存取各緩衝區的
    buffer fd。
5.  若要執行推論，首先對輸入緩衝區的 buffer fd 執行 mmap，
    以取得可從 user space 存取的輸入緩衝區位址；
    接著將輸入影像儲存至以此方式取得的輸入緩衝區；
    最後將 **名為 NPU_NET_IOCT_RUNCT
    的 IOL** 傳送至 network fd。
6.  當執行兩個以上的類神經網路時，NPU 裝置驅動程式會
    以分時演算法執行類神經網路。
7.  在此情況下，由於執行順序是在內部使用 command queue
    進行排程，因此類神經網路會依照 user space 要求的
    順序執行。

## 2.2 Device Tree

在 TOPST AI 中，使用 NPU 裝置驅動程式所需的資訊是透過
device tree 依下列方式設定。

```
# NPU device tree example

npu0: npu0 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000000 0x0 0x200>;
		interrupts = <GIC_SPI 146 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};

npu1: npu1 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000200 0x0 0x200>;
		interrupts = <GIC_SPI 147 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};
```

<br/>

|     屬性         |              說明                     |
|------------------|---------------------------------------|
| compatible       | 固定為「telechipss, npu」              |
| reg              | NPU 暫存器基底位址、大小              |
| reg-names        | NPU 暫存器名稱                        |
| work-buffer-size | Work 緩衝區配置大小                   |
| interrupt-parent | 中斷控制器 device tree 節點           |
| interrupts       | 中斷編號                              |

### 2.3.1 IOCTL 命令

開啟 /dev/npu0 與 /dev/npu1 等 NPU 裝置檔案即可取得 NPU
檔案描述子。可用的 IOCTL 命令如下。

<br/>

|      命令              |        引數             |        說明             |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req\*  | 配置 CMA 緩衝區         |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req\*   | 載入 Network            |
| NPU_IOCTL_INIT_MLX     | struct mlx_init_req\*   | 初始化 MLX              |
| NPU_IOCTL_READ_REG     | struct reg_access_req\* | 從暫存器讀取值          |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req\* | 將值寫入暫存器          |
| NPU_IOCTL_RESET_NPU    |                         | 重設 NPU                |

<br/>

NPU_IOCTL_ALLOC_BUFFER 命令會使用透過結構 buffer_alloc_req
傳入的 size 值配置 CMA 緩衝區，並回傳
buffer 檔案描述子。
NPU_IOCTL_LOAD_NETWORK 命令會配置 CMA 緩衝區以儲存透過結構
net_load_req 傳入的參數，將這些參數複製至
所配置的 CMA 緩衝區，並回傳 network 檔案
描述子。

### 2.3.2 Network 檔案描述子的 IOCTL 介面

將 NPU_IOCTL_LOAD_NETWORK 命令傳送至 NPU 檔案描述子，即可建立
Network 檔案描述子。它支援 poll 與 close 等操作。
可用的 IOCTL 命令如下
所示。

<br/>

|         命令               |         引數             |         說明             |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req\*     | 執行推論                 |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req\* | 分析推論週期數           |
| PU_NET_IOCTL_SET_COLOR_FMT | int                      | 設定輸入色彩格式         |

<br/>

執行 NPU_NET_IOCTL_RUN 時，NPU 驅動程式會將執行 network 的命令
傳送至 NPU HW，並可透過呼叫 poll 來確認
推論結束的時間點。

### 2.3.3 Buffer 檔案描述子的 IOCTL 介面

將 NPU_IOCTL_ALLOC_BUFFER 命令傳送至 NPU 檔案描述子，
即可產生 Buffer 檔案描述子。

Buffer 檔案描述子支援 mmap、close 等操作。

Buffer 檔案描述子不支援 IOCTL 命令。請透過 mmap 從 user mode
取得 CMA 緩衝區，並透過 close 釋放 CMA 緩衝區。
