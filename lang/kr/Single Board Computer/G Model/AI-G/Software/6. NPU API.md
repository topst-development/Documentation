# 1. 소개
---
Neural Processing Unit(NPU)은 HW 신경망 가속기이며, AI-G의 NPU는 객체 검출, 이미지 분류, 
얼굴 검출과 같은 비전 애플리케이션용 신경망의 추론에 최적화되어 있습니다. NPU 디바이스 드라이버는 
사용자 공간의 신경망 애플리케이션이 AI-G NPU를 사용하여 임베디드 Linux 환경에서 신경망 추론을 
수행할 수 있도록 NPU를 제어하는 인터페이스를 제공합니다.

이 문서에서는 AI-G SDK에 포함된 NPU 디바이스 드라이버와 NPU API의 사용 방법을 설명합니다.
<br/><br/><br/><br/>


# 2. NPU Linux 디바이스 드라이버
---
NPU 디바이스 드라이버는 다음을 제어합니다.

- NPU HW 초기화
- 컴파일된 신경망을 NPU HW로 전달
- NPU HW 실행
- NPU HW 처리(추론) 결과 읽기

NPU 디바이스 드라이버가 사용하는 버퍼(code, weight, work, input, output)에는 연속된 물리 메모리 공간이 필요합니다. 이러한 
이유로 메모리상의 버퍼는 내부적으로 Continuous Memory Allocator(CMA)를 사용하여 할당됩니다.
NPU 디바이스 드라이버는 컴파일된 신경망의 command 파일과 weight/bias 파일을 입력으로 받아 네트워크 파일 디스크립터 
(fd)를 생성합니다. 또한 신경망 입력과 결과가 저장될 버퍼를 할당하고, 각 버퍼에 접근하기 위한 버퍼 fd를 
생성합니다. 

추론을 실행하려면 다음을 수행합니다.
1. 입력 버퍼의 buffer fd에 대해 mmap을 실행하여 사용자 공간에서 접근할 수 있는 입력 버퍼 주소를 얻습니다.
2. 1단계에서 얻은 입력 버퍼 주소를 사용하여 입력 이미지를 입력 버퍼에 저장합니다.
3. NPU_NET_IOCTL_RUN이라는 IOCTL을 network fd로 전달합니다.

두 개 이상의 신경망을 실행하는 경우, NPU 디바이스 드라이버는 시분할 알고리즘으로 신경망을 실행합니다. 
이 경우 실행 순서가 내부적으로 queue.f 명령을 사용하여 스케줄링되므로, 신경망은 사용자 공간에서 요청한 
순서대로 실행됩니다.

## 2.2 디바이스 트리
---
다음은 AI-G에서 NPU 디바이스 드라이버를 사용하기 위한 디바이스 트리 예제입니다.

```
# NPU device tree example

 npu0: npu@11000000 {
                compatible = "telechips,npu";
                reg = <0x0 0x11000000 0x0 0x400>;
                interrupts = <GIC_SPI 153 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_0_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_0_CCLK &fbus_npu FBUS_NPU_0_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };


npu1: @11000400 {
                compatible = "telechips,";
                reg = <0x0 0x11000400 0x0 0x400>;
                interrupts = <GIC_SPI 154 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_1_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_1_CCLK &fbus_npu FBUS_NPU_1_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };

```

<br/>

| 속성 | 설명 |
|------------------|---------------------------------------|
| compatible       | “telechips,npu”로 고정 |
| reg              | NPU 레지스터의 기본 주소와 크기 |
| disable-ue-fail  | UE 오류에 의한 실패를 비활성화합니다. <br>disable-ue-fail이 0이면 UE 오류가 감지될 때 fail이 반환됩니다. <br>또는 <br>disable-ue-fail이 0x7이면 UE 오류가 무시됩니다. |
| disable-ce-fail  | CE 오류에 의한 실패를 비활성화합니다. <br>disable-ce-fail이 0이면 CE 오류가 감지될 때 fail이 반환됩니다. <br>또는 <br>disable-ce-fail이 0x7이면 CE 오류가 무시됩니다. |
| disable-wdt      |  워치독 타이머 비활성화 |
| wdt-timeout-count| 워치독 타임아웃 카운트 |
| wdt-rearm-count  | 워치독 재무장 카운트<br>이 값은 워치독 타임아웃 카운트보다 작아야 합니다. |
| reg-names        | NPU 레지스터 이름 |
| work-buffer-size | 작업 버퍼 할당 크기 |
| interrupt-parent | 인터럽트 컨트롤러 디바이스 트리 노드 |
| interrupts       | 인터럽트 번호 |

### 2.3.1 NPU 파일 디스크립터용 IOCTL 명령

NPU 파일 디스크립터는 /dev/npu0, /dev/npu1과 같은 NPU 디바이스 파일을 열어
얻을 수 있습니다. 사용 가능한 IOCTL 명령은 다음과 같습니다.


| 명령 | 인수 | 설명 |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req*  | CMA 버퍼 할당 |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req*   | 네트워크 로드 |
| NPU_IOCTL_READ_REG     | struct reg_access_req* | 레지스터에서 값 읽기 |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req* | 레지스터에 값 쓰기 |
| NPU_IOCTL_RESET_NPU    | struct npu_init_req*   | NPU 리셋 |
| NPU_IOCTL_WRITE_TEST_CFG| test_cfg_wr_req_t*    | ecc_test 쓰기 |
| NPU_IOCTL_READ_NPU_ERR | npu_err_rd_req_t*      | ECC 및 WDT 읽기 |

<br/>

NPU_IOCTL_ALLOC_BUFFER 명령은 
- 구조체 buffer_alloc_req를 통해 전달된 size 값을 사용하여
CMA 버퍼를 할당하며
- 버퍼 파일 디스크립터를 반환합니다.

NPU_IOCTL_LOAD_NETWORK 명령은 
- 구조체 net_load_req를 통해 전달된 파라미터를 저장할 CMA 버퍼를 할당하고,
- 할당된 CMA 버퍼로 파라미터를 복사하며, 
- 네트워크 파일 디스크립터를 반환합니다.

NPU_IOCTL_WRITE_TEST_CFG와 NPU_IOCTL_READ_NPU_ERR는 test_cfg_wr_req_t를 통해 전달되는 NPU 테스트 파라미터 
값이며, 두 명령 모두 테스트 결과 값을 읽는 데 사용됩니다.

### 2.3.2 네트워크 파일 디스크립터를 위한 IOCTL 인터페이스

네트워크 파일 디스크립터는 NPU 파일 디스크립터에
NPU_IOCTL_LOAD_NETWORK 명령을 전달하여 생성할 수 있습니다. 이 디스크립터는
poll, close 등의 동작을 지원합니다. 사용 가능한 IOCTL 명령은 다음과
같습니다.

<br/>

|         명령            |         인자         |         설명      |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req*     | 추론 실행            |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req* | 추론 사이클 프로파일링 |
| NPU_NET_IOCTL_SET_COLOR_FMT | int                      | 입력 컬러 포맷 설정   |

<br/>

NPU_NET_IOCTL_RUN이 실행되면 NPU 드라이버는 네트워크를 실행하기 위한
명령을 NPU HW로 전송하며, 추론이 종료되는 시점은
poll을 호출하여 확인할 수 있습니다.

### 2.3.3 버퍼 파일 디스크립터를 위한 IOCTL 인터페이스

버퍼 파일 디스크립터: 
- NPU 파일 디스크립터에 NPU_IOCTL_ALLOC_BUFFER 명령을 전송하여 생성할 수 있습니다. 
- mmap, close 등의 동작을 지원합니다. 
- IOCTL 명령은 지원하지 않습니다. 
- mmap 동작을 통해 사용자 모드에서 CMA 버퍼를 가져옵니다.
- close 동작을 통해 CMA 버퍼를 해제합니다.
