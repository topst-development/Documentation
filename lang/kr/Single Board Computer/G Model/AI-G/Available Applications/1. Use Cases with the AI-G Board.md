# 2. 비디오 출력
---
AI-G는 MIPI DSI-2 인터페이스를 통한 비디오 출력을 지원합니다.
15핀 FFC 커넥터를 통해 2-레인 DSI 연결을 제공하며, 호환되는 MIPI DSI LCD 패널을 연결하기에 적합합니다. 이 인터페이스를 사용하면 임베디드 디스플레이에서 그래픽 사용자 인터페이스 렌더링, 비디오 재생, 실시간 AI 시각화를 원활하게 수행할 수 있습니다.
<br/><br/><br/>

## 2.1 MIPI DSI
---
DSI는 Display Serial Interface의 약자로, 프로세서에서 외부 화면으로 디스플레이 데이터를 전송하기 위해 MIPI Alliance가 정의한 표준입니다. 임베디드 LCD 패널에 적합한 고속 저전력 통신을 지원합니다.  
앞서 설명한 대로 AI-G는 15핀 FFC 커넥터를 통해 2-레인 DSI 연결을 제공하므로, 호환되는 MIPI DSI 디스플레이 모듈을 연결하여 GUI 렌더링, 비디오 재생 또는 실시간 추론 시각화를 수행할 수 있습니다.
<br/><br/>

### 2.1.1 5인치 DSI 디스플레이
Elecrow 5인치 DSI 디스플레이는 IPS 패널과 정전식 터치를 지원하는 800×480 해상도의 LCD로, Raspberry Pi의 MIPI DSI 인터페이스에서 사용하도록 설계되었습니다. 플러그 앤 플레이 기능을 지원하므로 별도의 드라이버 설치가 필요하지 않습니다. 이 디스플레이는 15핀 MIPI DSI 커넥터를 통해 AI-G 보드에 연결되며, 해당 인터페이스로 직접 전원을 공급받으므로 외부 전원 공급 장치가 필요하지 않습니다.  
이 모듈은 AI-G 플랫폼에서 GUI 기반 애플리케이션, 실시간 모니터링, 대화형 AI 데모에 적합합니다.

DSI 디스플레이의 사양은 다음과 같습니다:

| 주사율        | 60 Hz                                      |

| 호환성       | Raspberry Pi 및 AI-G (MIPI DSI 인터페이스를 통해)|

# 3. 카메라 연결
---
AI-G는 MIPI CSI-2 인터페이스를 통한 카메라 입력을 지원합니다.
기본적으로 15핀 커넥터를 통해 2-레인 CSI 연결을 제공합니다. 고해상도 또는 고프레임률 AI 비전 작업과 같이 더 높은 대역폭이 필요한 애플리케이션을 위해 옵션인 20핀 커넥터를 통한 4-레인 구성도 지원합니다.
<br/><br/><br/>

## 3.1 MIPI CSI
---
CSI는 Camera Serial Interface의 약자로, 카메라 모듈을 호스트 프로세서에 연결하기 위해 MIPI Alliance가 정의한 표준 인터페이스입니다. 카메라에서 프로세서로 이미지 데이터를 고속 저전력으로 전송할 수 있습니다.  
위에서 설명한 대로 AI-G는 기본적으로 2-레인 CSI 연결을 제공하며, 더 높은 데이터 처리량을 위해 20핀 커넥터를 통한 4-레인 구성을 옵션으로 지원합니다.  

현재 AI-G는 ArduCam (5 MP)과 Raspberry Pi v1 Camera (5 MP) 모듈만 지원합니다.
<br/><br/>

### 3.1.1 ArduCam
ArduCam은 임베디드 시스템과 AI 애플리케이션을 위해 설계된 다목적 카메라 모듈입니다. MIPI CSI를 포함한 다양한 이미지 센서와 인터페이스를 지원하므로 AI-G와 같은 개발 보드에 통합하기에 적합합니다.  
AI-G는 2-레인 또는 4-레인 MIPI CSI 인터페이스를 갖춘 ArduCam 모듈을 지원하여 객체 검출 및 이미지 분류와 같은 AI 비전 작업에 안정적인 이미지 입력을 제공합니다. FFC 케이블과 호환되므로 ArduCam 모듈을 AI-G 보드의 CSI 커넥터에 쉽게 연결할 수 있으며, 엣지 AI 시스템에서 실시간 카메라 입력을 위한 신뢰성 높은 솔루션을 제공합니다.

- w — 파티션 테이블을 기록하고 종료합니다

```
$ mkfs.ext4 /dev/nvme0n1p1

$ mount /dev/nvme0n1p1 /mnt/nvme
```

# 5. 이더넷 연결
---
AI-G는 온보드 RJ45 이더넷 포트를 통해 이더넷 연결을 지원합니다. 이를 통해 보드는 표준 TCP/IP 프로토콜을 사용하여 로컬 네트워크 또는 인터넷과 통신할 수 있습니다. 이더넷은 원격 액세스, 데이터 스트리밍 또는 소프트웨어 업데이트가 필요한 AI 애플리케이션을 배포하는 데 일반적으로 사용됩니다.
<br/><br/><br/>

## 5.1 라우터를 통한 네트워크 연결
---
이 방법은 표준 라우터를 사용하여 AI-G를 로컬 네트워크에 연결합니다. 보드는 DHCP를 통해 IP 주소를 자동으로 할당받거나 고정 IP 주소로 구성할 수 있습니다.
<br/><br/>

### 5.1.1 루트 파일 시스템을 읽기/쓰기로 다시 마운트하기
루트 파일 시스템은 읽기 전용으로 마운트되어 있습니다. 구성 파일을 편집할 수 있도록 다음 명령을 사용하여 쓰기 권한으로 다시 마운트하십시오:

```
$ mount -o remount,rw /
```
<br/><br/>


### 5.1.2 네트워크 구성 파일 생성
1. DHCP를 통한 동적 IP
eth0 인터페이스에서 DHCP를 활성화하려면 다음 내용으로 /etc/systemd/network/20-wired.network 파일을 생성하거나 편집하십시오.

```
$ vi /etc/systemd/network/20-wired.network
 
[Match]
Name=eth0
 
[Network]
DHCP=yes
```

이 구성은 systemd-networkd가 eth0 인터페이스에 대해 DHCP를 통해 IP 주소를 자동으로 획득하도록 지시합니다.

2. 고정 IP 구성

# 6. 40핀 GPIO 헤더

#### 단계 3. 실행 방법
AI-G 보드의 GPIO72에 연결된 LED를 동작시키려면 다음 코드를 실행하십시오:

```bash
#!/bin/bash

GPIO=72
INTERVAL=1

# GPIO export
if [ ! -e /sys/class/gpio/gpio$GPIO ]; then
    echo "$GPIO" > /sys/class/gpio/export
    sleep 0.1
fi

echo "out" > /sys/class/gpio/gpio$GPIO/direction

trap "echo $GPIO > /sys/class/gpio/unexport; echo -e '\nGPIO$GPIO unexported. Exit.'; exit" SIGINT

echo "Toggling GPIO$GPIO every $INTERVAL second(s). Press Ctrl+C to stop."

while true; do
    echo 1 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
    echo 0 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
done
```

#### 단계 4. 실행 결과
다음 명령으로 코드를 실행하십시오.
```
$ ./AI_GPIO_LED_TEST
```

이 스크립트는 GPIO72를 디지털 출력으로 구성하고 1초마다 상태를 계속 전환합니다. 실행하면 GPIO72에 연결된 LED가 1초 동안 켜졌다가 1초 동안 꺼지는 동작을 무한 루프로 반복하며 깜박입니다.

스크립트를 중지하려면 **[Ctrl+C]**를 누르십시오.  
스크립트가 종료되면 GPIO72는 자동으로 unexport되고 정리됩니다.  
실행하기 전에 스크립트에 실행 권한을 부여했는지 확인하십시오:
```bash
$ chmod +x AI_GPIO_LED_TEST
```

**참고**: 이 구성에는 전류 제한 저항이 포함되어 있지 않습니다. 단기간 테스트에는 동작할 수 있지만, GPIO 핀의 손상을 방지하기 위해 LED와 직렬로 저항을 사용하는 것을 권장합니다.

## 6.2 I2C
---
AI-G는 40핀 GPIO 헤더를 통해 I2C 통신을 제공하므로 센서, 디스플레이, 확장 모듈 등 다양한 주변 장치와 인터페이스할 수 있습니다. I2C(Inter-integrated Circuit)는 데이터 라인(SDA)과 클록 라인(SCL)으로 구성된 2선식 통신 프로토콜로, 여러 장치가 공유 버스를 통해 통신할 수 있게 합니다.

I2C 통신은 마스터-슬레이브 구조를 따르며, 하나의 마스터 장치가 통신을 제어하고 동일한 버스에 최대 127개의 슬레이브 장치를 연결할 수 있습니다. SDA 라인은 데이터 송신과 수신에 모두 사용되며, SCL 라인은 데이터 전송 타이밍을 동기화합니다. 이러한 동기식 통신 모델을 통해 장치는 클록에 따라 정렬된 방식으로 정보를 교환할 수 있습니다.
<br/><br/><br/>

#### 단계 3. 실행 방법

다음은 간단한 예제(I2C_TEST.c)입니다:

```
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <linux/i2c-dev.h>
#include <sys/ioctl.h>
#include <unistd.h>

#define I2C_DEV "/dev/i2c-1"
#define I2C_ADDR 0x27

// RS: 0 = command, 1 = data
void lcd_send_byte(int fd, unsigned char data, unsigned char mode) {
    unsigned char high = mode | (data & 0xF0) | 0x08; // backlight on
    unsigned char low  = mode | ((data << 4) & 0xF0) | 0x08;
    unsigned char buf[4] = { high | 0x04, high, low | 0x04, low }; // toggle EN bit

    for (int i = 0; i < 4; i++) {
        if (write(fd, &buf[i], 1) != 1) {
            perror("I2C write error");
        }
        usleep(1000); // 1ms delay
    }
}

void lcd_command(int fd, unsigned char cmd) {
    lcd_send_byte(fd, cmd, 0x00);
}

void lcd_data(int fd, unsigned char data) {
    lcd_send_byte(fd, data, 0x01);
}

void lcd_init(int fd) {
    usleep(50000); // wait for LCD power on
    lcd_command(fd, 0x33); // init
    lcd_command(fd, 0x32); // 4-bit mode
    lcd_command(fd, 0x28); // 2 line, 5x8 font
    lcd_command(fd, 0x0C); // display on, cursor off
    lcd_command(fd, 0x06); // entry mode
    lcd_command(fd, 0x01); // clear display
    usleep(2000);
}

void lcd_print(int fd, const char* str) {
    while (*str) {
        lcd_data(fd, *str++);
    }
}

int main() {
    int fd = open(I2C_DEV, O_RDWR);
    if (fd < 0) {
        perror("Failed to open I2C device");
        return 1;
    }

    if (ioctl(fd, I2C_SLAVE, I2C_ADDR) < 0) {
        perror("Failed to set I2C address");
        close(fd);
        return 1;
    }

    lcd_init(fd);
    lcd_print(fd, "test pass!");

    close(fd);
    return 0;
}
```

## 6.3 SPI
---
AI-G는 40핀 GPIO 헤더를 통해 SPI(Serial Peripheral Interface) 통신을 지원하여 외부 장치와 보드 간의 데이터 교환을 가능하게 합니다.  

SPI는 동기식 직렬 통신 프로토콜로, 전이중 통신을 지원하므로 데이터를 동시에 송신하고 수신할 수 있습니다. SPI는 MOSI(Master Out Slave In), MISO(Master In Slave Out), SCLK(Serial Clock), SS(Slave Select)의 네 가지 주요 라인을 사용합니다.

여러 장치가 라인을 공유하는 I2C와 달리, SPI는 각 슬레이브 장치마다 전용 SS 라인이 필요합니다. 이러한 일대다 구조는 SPI를 빠르고 구현하기 쉽게 만들지만, 여러 장치를 사용할 경우 더 많은 물리적 배선이 필요할 수 있습니다.
<br/><br/><br/>

### 6.3.1 도트 매트릭스
---
8x8 도트 매트릭스 디스플레이는 임베디드 시스템에서 간단한 텍스트나 패턴 출력을 위해 일반적으로 사용됩니다. AI-G에서는 MAX7219와 같은 드라이버 칩을 통해 SPI로 도트 매트릭스 모듈을 제어할 수 있습니다.

MAX7219는 행과 열 스캔을 내부적으로 처리하므로, 마이크로컨트롤러는 MOSI(DIN), SCLK, CS(LOAD)의 몇 가지 SPI 신호만으로 전체 디스플레이를 제어할 수 있습니다. 연결한 후에는 사용자 정의 스크립트나 라이브러리를 사용하여 SPI 통신으로 디스플레이를 제어할 수 있습니다.

- AI-G 보드 (x1)
- 8x8 도트 매트릭스
- 암-암 점퍼 와이어 (x5)
- DC 5V 전원 어댑터 (x1)
- USB-TTL 시리얼 케이블 (x1)

#### 단계 3. 실행 방법
AI-G에서 SPI 장치와 통신하려면 spidev 인터페이스를 사용하는 C 프로그램을 작성하고 대상 아키텍처에 맞게 크로스 컴파일해야 합니다.  
다음은 MAX7219 LED 매트릭스 디스플레이로 데이터를 전송하는 간단한 예제(SPI_TEST.c)입니다:

```
#include <stdio.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>
#include <linux/spi/spidev.h>
#include <sys/ioctl.h>
#include <string.h>

#define SPI_DEV "/dev/spidev3.0"

int spi_fd = -1;

void spi_send(uint8_t address, uint8_t data) {
    uint8_t tx[2] = { address, data };
    struct spi_ioc_transfer tr = {
        .tx_buf = (uintptr_t)tx,
        .rx_buf = 0,
        .len = 2,
        .delay_usecs = 0,
        .speed_hz = 1000000,
        .bits_per_word = 8,
    };

    if (ioctl(spi_fd, SPI_IOC_MESSAGE(1), &tr) < 1) {
        perror("SPI send failed");
    }
}

void max7219_init() {
    spi_send(0x09, 0x00); // Decode mode off
    spi_send(0x0A, 0x08); // Brightness (0x00 ~ 0x0F)
    spi_send(0x0B, 0x07); // Scan limit: display all 8 digits
    spi_send(0x0C, 0x01); // Shutdown register: normal operation
    spi_send(0x0F, 0x00); // Display test: off
}

void max7219_clear() {
    for (int i = 1; i <= 8; i++) {
        spi_send(i, 0x00);
    }
}


const uint8_t letter_P[8] = {
    0b00000000,  
    0b01111110, 
    0b01000010,  
    0b01000010,  
    0b01111110,  
    0b01000000,  
    0b01000000,  
    0b01000000   
};


void draw_letter_P() {
    for (int row = 0; row < 8; row++) {
        spi_send(row + 1, letter_P[row]);
    }
}

int main() {
    spi_fd = open(SPI_DEV, O_RDWR);
    if (spi_fd < 0) {
        perror("Failed to open SPI device");
        return 1;
    }

    max7219_init();
    max7219_clear();
    draw_letter_P();

    close(spi_fd);
    return 0;
}
```

## 6.4 UART
---
AI-G는 40핀 GPIO 헤더를 통해 UART(Universal Asynchronous Receiver/Transmitter) 통신을 지원하여 시리얼 콘솔 및 다른 마이크로컨트롤러와 같은 장치와의 직렬 통신을 가능하게 합니다.  

UART는 TX(송신)와 RX(수신)의 두 개 라인을 통해 데이터를 한 번에 1비트씩 전송하는, 널리 사용되는 비동기 통신 프로토콜입니다. I2C나 SPI와 달리 UART는 클럭 라인을 사용하지 않습니다. 대신 두 장치는 타이밍을 위해 공통의 통신 속도를 사용해야 합니다.
<br/><br/><br/>

#### 단계 3. 실행 방법
이 스크립트는 UART 포트로 테스트 메시지를 전송한 후 동일한 메시지가 수신되는지 확인합니다.  
AI-G에서 UART 루프백을 테스트하려면 TX 핀과 RX 핀을 서로 연결한 후 다음 스크립트를 실행하십시오.

```bash
#!/bin/bash
# ===================== user setting =====================
UART_DEV="/dev/ttyAMA1"       # uart
BAUD=115200                   # Baudrate
TEST_MSG="Hello from UART"    # msg
TEMP_FILE="/tmp/uart_rx.txt"  # file
# =====================================================

if [ ! -e "$UART_DEV" ]; then
    echo "Error: $UART_DEV does not exist"
    exit 1
fi

chmod 666 $UART_DEV

stty -F $UART_DEV $BAUD cs8 -cstopb -parenb -icanon -echo -ixon -ixoff
echo "UART setup complete: port=$UART_DEV, speed=$BAUD"

cat $UART_DEV > $TEMP_FILE &
RX_PID=$!

sleep 0.2
echo -n "$TEST_MSG" > $UART_DEV
echo "Transmission complete: \"$TEST_MSG\""

sleep 1
kill $RX_PID 2>/dev/null

if [ -f "$TEMP_FILE" ]; then
    RECEIVED=$(cat $TEMP_FILE)
    rm $TEMP_FILE
    if [ "$RECEIVED" = "$TEST_MSG" ]; then
        echo "Loopback Success! Received Message: \"$RECEIVED\""
    else
        echo "Received mismatch"
        echo "Sent: \"$TEST_MSG\""
        echo "Received: \"$RECEIVED\""
    fi
else
    echo "Failed to receive: No received file"
fi
```
