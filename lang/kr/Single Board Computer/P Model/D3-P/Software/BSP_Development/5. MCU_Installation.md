## 5.1 소프트웨어 아키텍처

그림 5.1은 TCC8050 MCU BSP의 소프트웨어 구성 요소를 보여줍니다. TCC8050 MCU BSP는 디바이스 드라이버, RTOS(Real Time Operating System), SAL(System Adaptation Layer) 및 샘플 애플리케이션으로 구성됩니다. MCU BSP는 용도에 따라 세 가지 유형(Sample, 3rd party, TC Support)으로 분류됩니다. Sample은 디바이스 드라이버를 테스트하기 위한 샘플 코드입니다. 샘플 코드를 참조하여 자체 솔루션을 구현할 수 있으나 품질은 보장되지 않습니다. MCU BSP에는 RTOS와 같은 서드파티 소프트웨어가 포함되어 있지만, 이 MCU BSP는 RTOS 자체에 대한 기술 지원은 제공하지 않습니다. 디바이스 드라이버와 SAL 인터페이스는 Telechips에서 지원합니다(TC Support).

## 5.4 기능 설명

### 5.4.1 UART 지원

TCC8050 MICOM 서브 시스템은 5채널 UART를 갖추고 있으며, 각 UART 채널은 하나의 ARM® PrimeCell™ UART(PL011) 컨트롤러와 하나의 ARM® PrimeCell™ DMA 컨트롤러(PL081)로 구성됩니다. UART 통신을 통해 송수신되는 데이터는 UART 전용 DMA 컨트롤러에 의해 내부 메모리(SRAM-0 또는 SRAM-1)와 주고받을 수 있습니다.

### 5.4.1.1 특징

<br/>

### 5.4.1.1.1 UART 컨트롤러

UART 컨트롤러의 특징은 다음과 같습니다:

- 프로그래밍 가능한 UART 입출력 사용
- CPU 인터럽트를 줄이기 위한 32×8 송신 및 32×12 수신 FIFO(First-In, First-Out) 메모리 버퍼 분리.
- 1바이트 깊이를 위한 프로그래밍 가능한 FIFO 비활성화.
- 프로그래밍 가능한 보드 레이트 생성기. 이를 통해 3.6864 MHz를 초과하는 기준 클록 주파수의 분주가 가능합니다.
- 표준 비동기 통신 비트(시작, 정지, 패리티).
- 송신 FIFO, 수신 FIFO, 수신 타임아웃, 모뎀 상태 및 오류 조건 인터럽트의 독립적인 마스킹.
- DMA(Direct Memory Access) 지원.
- 잘못된 시작 비트 검출
- 라인 브레이크 생성 및 검출.
- 프로그래밍 가능한 하드웨어 흐름 제어: CTS 및 RTS의 모뎀 제어 기능
- 완전히 프로그래밍 가능한 직렬 인터페이스 특성:
- 데이터는 5, 6, 7 또는 8비트로 프로그래밍할 수 있습니다
- 짝수, 홀수, 스틱 또는 무패리티 비트 생성 및 검출
- 1개 또는 2개의 정지 비트 생성
- 최대 UARTCLK/16까지의 보드 레이트 생성
- UART를 고유하게 식별하는 식별 레지스터. 운영 체제가 자동으로 구성하는 데 사용할 수 있습니다.

<br/>

### 5.4.1.1.2 UART DMA 컨트롤러

UART DMA 컨트롤러의 특징은 다음과 같습니다:

- 메모리-메모리, 메모리-UART, UART-메모리 전송
- DMA 컨트롤러는 두 개의 채널을 가집니다.
- 연결 리스트를 사용한 스캐터 또는 개더 DMA 지원. 즉, 소스 영역과 대상 영역이 연속된 메모리 영역을 차지할 필요가 없습니다.
- 데이터 전송을 위한 하나의 AHB 버스 마스터. 이 인터페이스는 DMA 요청이 발생할 때 데이터를 전송합니다
- 32비트 AHB 마스터 버스 폭.
- 소스 및 대상에 대한 증가 또는 비증가 주소 지정.
- 프로그래밍 가능한 DMA 버스트 크기. DMA 버스트 크기를 프로그래밍하여 데이터를 보다 효율적으로 전송할 수 있습니다. 일반적으로 버스트 크기는 주변 장치 FIFO 크기의 절반으로 설정됩니다.
- 채널당 내부 4워드 FIFO.
- 빅 엔디안 및 리틀 엔디안 지원. DMA 컨트롤러는 리셋 시 리틀 엔디안 모드로 기본 설정됩니다.
- DMA 오류 인터럽트 요청과 DMA 카운트 인터럽트 요청의 결합. DMA 오류가 발생하거나 DMA 카운트가 0에 도달하면 프로세서에 인터럽트를 생성할 수 있습니다. 이는 일반적으로 전송이 완료되었음을 나타내는 데 사용됩니다. 세 개의 인터럽트 요청 신호가 이를 수행합니다:
- INTTC는 전송이 완료되면 신호를 발생시킵니다.
   * **참고**: INTTC 신호는 인터럽트 컨트롤러에 입력되지 않지만, 상태 레지스터를 통해 상태를 확인할 수 있습니다.
- INTERR는 오류가 발생하면 신호를 발생시킵니다.
   * **참고**: INTERR 신호는 인터럽트 컨트롤러에 입력되지 않지만, 상태 레지스터를 통해 상태를 확인할 수 있습니다.
- INTR은 INTTC와 INTERR 인터럽트 요청 신호를 모두 결합합니다. INTR 신호는 인터럽트 컨트롤러에 입력됩니다.
- 인터럽트 마스킹: DMA 오류 및 DMA 터미널 카운트 인터럽트 요청을 마스킹할 수 있습니다.
- Raw 인터럽트 상태: 마스킹 이전의 DMA 오류 및 DMA 카운트 raw 인터럽트 상태를 읽을 수 있습니다.

sint32 UART_Open
(
    uint8                               ucCh,
    uint32                              uiPriority,     // Interrupt Priority
    uint32                              uiBaudrate,     // Baudrate
    uint8                               ucMode,         // polling or interrupt or udma
    uint8                               ucCtsRts,       // on/off
    uint8                               ucPortCfg,      // port selection
    uint8                               ucWordLength,   // 5~6 bits
    uint8                               ucFIFO,         // on/off
    uint8                               uc2StopBit,     // on/off
    uint8                               ucParity,       // space, even, odd, mark
    GICIsrFunc                       fnCallback      // callback function
)
{
    SNORRomInfo_t   *rom_header;
    uint32          header_addr;
    uint8           port_cfg;   //config of debug port
    sint32          ret = -1;

    UART_StatusInit(ucCh);

    rom_header  = (SNORRomInfo_t *)MCU_BSP_SNOR_BASE;
    port_cfg  = 0;

    if (ucCh == UART_DEBUG_CH)
    {
        // Find Debug port from special location of SNOR Flash.
        if (rom_header->riRomId != SNOR_ROM_ID)
        {
            /* Secondary SNOR ROM Header */
            header_addr = (MCU_BSP_SNOR_BASE + 0x1000UL);
            rom_header  = (SNORRomInfo_t *)(header_addr);

            if (rom_header->riRomId != SNOR_ROM_ID)
            {
                port_cfg = ucPortCfg;
            }
            else
            {
                port_cfg = (uint8)rom_header->riDebugPort;
            }
        }
        else
        {
            port_cfg = (uint8)rom_header->riDebugPort;
        }
    }
    else if (ucCh < UART_CH_MAX)
    {
        port_cfg = ucPortCfg;
    }
    else
    {
        port_cfg = 0xFF;    //Error
    }

### 5.4.2 CAN 애플리케이션

CAN(Controller Area Network)은 ISO 11898-1(Bosch CAN 프로토콜 사양 2.0 part A, B와 동일)에 따라 통신을 수행합니다. 또한 CAN은 CAN FD(Flexible Data-rate) 프로토콜 사양 1.0에 따른 통신을 지원합니다.

메시지를 처리하는 모든 기능은 Rx 핸들러와 Tx 핸들러에 의해 구현됩니다.

Rx 핸들러는 메시지 수락 필터링과 수신된 메시지를 CAN 코어에서 Message RAM으로 전송하는 작업을 관리하며, 수신 메시지 상태 정보를 제공합니다.

Tx 핸들러는 Message RAM에서 CAN 코어로 송신 메시지를 전송하는 작업을 담당하며, 송신 상태 정보를 제공합니다. 또한 시간 스케줄 및 글로벌 시스템 시간에 관한 모든 기능을 구현합니다.

수락 필터링은 최대 128개의 필터 요소 조합으로 구현되며, 각 요소는 범위, 비트 마스크 또는 전용 ID 필터로 구성할 수 있습니다.

TCC8050 MICOM 서브 시스템에는 총 3개의 CAN FD 컨트롤러가 통합되어 있습니다. CPU는 AHB to APB host I/F를 통해 각 CAN 컨트롤러를 구성할 수 있습니다. 각 CAN FD 컨트롤러는 AHB 버스 매트릭스를 통해 MICOM 서브 시스템에 통합된 SRAM-0 또는 SRAM-1에 접근하며, SRAM-0 또는 SRAM-1을 메시지 메모리로 사용합니다.

### 5.4.2.1 기능

CAN 애플리케이션의 기능은 다음과 같습니다.

- CAN 프로토콜 버전 2.0 part A, B (ISO 11898-1), Bosch CAN FD 사양 V1.0, ISO 16845 준수
- 최대 64 데이터 바이트의 CAN FD 지원
- CAN 오류 검출 및 로깅 (Stuff/Bit/Format/CRC/ACK)
- 향상된 수락 필터링
- 구성 가능한 2개의 수신 FIFO
- 높은 우선순위 메시지 수신 시 별도의 시그널링
- 최대 64개의 전용 수신 버퍼
- 최대 32개의 전용 송신 버퍼
- 구성 가능한 송신 FIFO
- 구성 가능한 송신 큐
- 구성 가능한 송신 이벤트 FIFO
- 프로그래밍 가능한 루프백 테스트 모드
- 마스킹 가능한 모듈 인터럽트
- 2개의 클럭 도메인 (CAN 클럭 및 버스 클럭)

CANErrorType_t CAN_DrvInitChannel
(
    CANController_t *                   psControllerInfo
)
{
    uint8               ucCh;
    uint32              uiMemSize;
    uint32              uiMemAddr;
    CANRegBaseAddr_t *  psConfigBaseRegAddr;
    CANErrorType_t      ret;

    uiMemAddr           = 0UL;
    ret                 = CAN_ERROR_NONE;

    if( ( psControllerInfo != NULL_PTR ) && ( psControllerInfo->cMode == CAN_MODE_NO_INITIALIZATION ) )
    {
        /* Set Config */
        ucCh = psControllerInfo->cChannelHandle;
        psControllerInfo->cRegister = ( CANControllerRegister_t * ) CAN_PortingGetControllerRegister( ucCh );

        /* Set HW_Init */
        ( void ) CAN_PortingInitHW( psControllerInfo );
        ( void ) CAN_PortingSetControllerClock( psControllerInfo, CAN_CONTROLLER_CLOCK );
        ( void ) CAN_PortingResetDriver( psControllerInfo );

        /* Set Memory */
        uiMemSize = CAN_DrvGetSizeOfRamMemory( psControllerInfo );

        if( 0UL < uiMemSize )
        {
            uiMemAddr = CAN_PortingAllocateNonCacheMemory( ucCh, uiMemSize );
        }

        if( uiMemAddr != 0UL )
        {
            psConfigBaseRegAddr = ( CANRegBaseAddr_t * ) CAN_PortingGetMessageRamBaseAddr( ucCh );

            if( psConfigBaseRegAddr != NULL_PTR )
            {
                psConfigBaseRegAddr->rFReg.rfBASE_ADDR = ( SALReg32 ) ( ( uint32 ) ( uiMemAddr >> ( uint32 ) 16UL ) & ( uint32 ) 0xFFFFUL );
            }

            ( void ) CAN_DrvRegisterParameterAll( psControllerInfo );

            ( void ) CAN_DrvStartConfigSetting( psControllerInfo );
            ( void ) CAN_DrvSetControlConfig( psControllerInfo );

            /* Set Buffer */
            ( void ) SAL_MemSet( ( void * ) uiMemAddr, 0, uiMemSize );
            ( void ) CAN_DrvInitBuffer( psControllerInfo, uiMemAddr, uiMemSize );
            ( void ) CAN_MsgInit( psControllerInfo );

            /* Set Filter */
            ( void ) CAN_DrvSetFilterConfig( psControllerInfo );

            /* Set Timing */
            ( void ) CAN_DrvInitTiming( psControllerInfo );

            /* Set Interrupt */
            ( void ) CAN_DrvSetInterruptConfig( psControllerInfo );

            /* Set TimeStamp */
            ( void ) CAN_DrvSetTimeStamp( psControllerInfo );

            /* Set TimeOut */
            ( void ) CAN_DrvSetTimeoutValue( psControllerInfo );

            /* Set WatchDog */
            ( void ) CAN_DrvSetWatchDog( psControllerInfo );

            ( void ) CAN_DrvFinishConfigSetting( psControllerInfo );

            psControllerInfo->cMode = CAN_MODE_OPERATION;
        }
        else
        {
            ret = CAN_ERROR_ALLOC;
        }
    }
    else
    {
        ret = CAN_ERROR_BAD_PARAM;
    }

    return ret;
}
