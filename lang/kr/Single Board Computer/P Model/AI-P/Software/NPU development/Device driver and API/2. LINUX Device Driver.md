# 2. NPU LINUX 디바이스 드라이버

TOPST AI의 NPU는 HW 신경망 가속기입니다. 객체 검출, 이미지 분류, 얼굴
검출과 같은 비전 애플리케이션 신경망의 추론에 최적화되어
있습니다. “TOPST-AI-Common-SW-NPU-Toolkit Guide” 문서는 NPU Toolkit을
사용하는 방법을
설명합니다.

1.  NPU 디바이스 드라이버는 NPU HW의 초기화, 컴파일된 신경망의 NPU HW 전달, NPU
    HW의 실행, NPU HW 처리(추론) 결과의 읽기를 제어합니다.
2.  NPU 디바이스에서 사용하는 버퍼(code, weight, work, input, output)는
    연속된 물리 메모리 공간을 필요로 합니다.
    이를 위해 메모리상의 버퍼는 Continuous Memory Allocator (CMA)를 사용하여
    내부적으로 할당됩니다.
3.  NPU 디바이스 드라이버는 컴파일된 신경망의 command 파일과 weight/bias 파일을
    입력으로 받아 네트워크 파일 디스크립터(fd)를
    생성합니다.
4.  또한 신경망의 입력과 결과가 저장될 버퍼를 할당하고, 각 버퍼에
    접근하기 위한 버퍼 fd를 생성하는 역할도
    담당합니다.
5.  추론을 실행하려면 먼저 입력 버퍼의 버퍼 fd에 대해 mmap을 실행하여
    유저 스페이스에서 접근할 수 있는 입력 버퍼 주소를 획득하고,
    다음으로 이렇게 획득한 입력 버퍼에 입력 이미지를 저장한 후,
    마지막으로 네트워크 fd에 **NPU_NET_IOCT_RUNCT라는
    IOL**을 전달합니다.
6.  두 개 이상의 신경망이 실행되는 경우, NPU 디바이스 드라이버는
    시분할 알고리즘으로 신경망을 실행합니다.
7.  이 경우 실행 순서가 command queue를 사용하여 내부적으로 스케줄링되므로
    신경망은 유저 스페이스에서 요청한 순서대로
    실행됩니다.

## 2.2 디바이스 트리

TOPST AI에서 NPU 디바이스 드라이버를 사용하기 위한 정보는 다음과 같이
디바이스 트리를 통해 설정됩니다.

```
# NPU device tree example

npu0: npu0 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000000 0x0 0x200>;
		interrupts = <GIC_SPI 146 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};

npu1: npu1 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000200 0x0 0x200>;
		interrupts = <GIC_SPI 147 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};
```

<br/>

|       속성       |                 설명                  |
|------------------|---------------------------------------|
| compatible       | “telechipss, npu” 고정                |
| reg              | NPU 레지스터 base address, size       |
| reg-names        | NPU 레지스터 이름                     |
| work-buffer-size | Work 버퍼 할당 크기                   |
| interrupt-parent | 인터럽트 컨트롤러 디바이스 트리 노드  |
| interrupts       | 인터럽트 번호                         |

## 2.3 IOCTL 명령어

<br/>

### 2.3.1 IOCTL 명령어

NPU 파일 디스크립터는 /dev/npu0, /dev/npu1과 같은 NPU 디바이스 파일을 열어
획득할 수 있습니다. 사용 가능한 IOCTL 명령어는 다음과 같습니다.

<br/>

|        명령어          |          인자           |          설명           |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req\*  | CMA 버퍼 할당           |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req\*   | 네트워크 로드           |
| NPU_IOCTL_INIT_MLX     | struct mlx_init_req\*   | MLX 초기화              |
| NPU_IOCTL_READ_REG     | struct reg_access_req\* | 레지스터에서 값 읽기    |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req\* | 레지스터에 값 쓰기      |
| NPU_IOCTL_RESET_NPU    |                         | NPU 리셋                |

<br/>

NPU_IOCTL_ALLOC_BUFFER 명령어는 구조체 buffer_alloc_req를 통해 전달된
size 값을 사용하여 CMA 버퍼를 할당하고 버퍼 파일 디스크립터를
반환합니다.
NPU_IOCTL_LOAD_NETWORK 명령어는 구조체 net_load_req를 통해 전달된
파라미터를 저장할 CMA 버퍼를 할당하고, 할당된 CMA 버퍼로 해당
파라미터를 복사한 후 네트워크 파일 디스크립터를
반환합니다.

### 2.3.2 네트워크 파일 디스크립터용 IOCTL 인터페이스

네트워크 파일 디스크립터는 NPU 파일 디스크립터에
NPU_IOCTL_LOAD_NETWORK 명령어를 전달하여 생성할 수 있습니다. poll, close와
같은 동작을 지원합니다. 사용 가능한 IOCTL 명령어는 다음과
같습니다.

<br/>

|          명령어            |           인자           |           설명           |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req\*     | 추론 실행                |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req\* | 추론 사이클 프로파일링   |
| PU_NET_IOCTL_SET_COLOR_FMT | int                      | 입력 컬러 포맷 설정      |

<br/>

NPU_NET_IOCTL_RUN이 실행되면 NPU 드라이버는 네트워크를 실행하는 명령을
NPU HW로 전송하며, 추론이 종료되는 시점은 poll을 호출하여
확인할 수 있습니다.

### 2.3.3 버퍼 파일 디스크립터용 IOCTL 인터페이스

버퍼 파일 디스크립터는 NPU 파일 디스크립터에 NPU_IOCTL_ALLOC_BUFFER
명령어를 전달하여 생성할 수 있습니다.

버퍼 파일 디스크립터는 mmap, close 등의 동작을 지원합니다.

버퍼 파일 디스크립터는 IOCTL 명령어를 지원하지 않습니다. 유저 모드에서는
mmap을 통해 CMA 버퍼를 획득합니다. CMA 버퍼는 close로 해제합니다.
