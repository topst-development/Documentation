# 2. NPU LINUX デバイスドライバ

TOPST AI の NPU は HW ニューラルネットワークアクセラレータです。物体検出、
画像分類、顔検出などのビジョンアプリケーションのニューラルネットワークの
推論に最適化されています。「TOPST-AI-Common-SW-NPU-Toolkit Guide」ドキュメントでは、
NPU Toolkit の使用方法について
説明します。

1.  NPU デバイスドライバは、NPU HW の初期化、コンパイルされたニューラルネットワークの NPU HW への転送、NPU
    HW の実行、および NPU HW の処理（推論）結果の読み出しを制御します。
2.  NPU デバイスが使用するバッファ（code、weight、work、input、output）は、
    連続した物理メモリ空間を必要とします。
    そのため、メモリ上のバッファは Continuous Memory Allocator (CMA) を使用して
    内部的に割り当てられます。
3.  NPU デバイスドライバは、コンパイルされたニューラルネットワークの command ファイルと weight/bias ファイルを
    入力として受け取り、ネットワークファイルディスクリプタ（fd）を
    生成します。
4.  また、ニューラルネットワークの入力および結果が格納されるバッファを割り当て、各バッファに
    アクセスするためのバッファ fd を生成する役割も
    担います。
5.  推論を実行するには、まず入力バッファのバッファ fd に対して mmap を実行し、
    ユーザ空間からアクセスできる入力バッファアドレスを取得します。次に、
    このようにして取得した入力バッファに入力画像を格納し、
    最後にネットワーク fd へ **NPU_NET_IOCT_RUNCT という
    IOL** を渡します。
6.  2 つ以上のニューラルネットワークが実行される場合、NPU デバイスドライバは
    時分割アルゴリズムでニューラルネットワークを実行します。
7.  この場合、実行順序は command queue を使用して内部的にスケジューリングされるため、
    ニューラルネットワークはユーザ空間から要求された順序で
    実行されます。

## 2.2 デバイスツリー

TOPST AI では、NPU デバイスドライバを使用するための情報は次のように
デバイスツリーを通じて設定されます。

```
# NPU device tree example

npu0: npu0 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000000 0x0 0x200>;
		interrupts = <GIC_SPI 146 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};

npu1: npu1 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000200 0x0 0x200>;
		interrupts = <GIC_SPI 147 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};
```

<br/>

|    プロパティ    |                 説明                  |
|------------------|---------------------------------------|
| compatible       | 「telechipss, npu」固定               |
| reg              | NPU レジスタの base address、size     |
| reg-names        | NPU レジスタ名                        |
| work-buffer-size | Work バッファの割り当てサイズ         |
| interrupt-parent | 割り込みコントローラのデバイスツリーノード |
| interrupts       | 割り込み番号                          |

## 2.3 IOCTL コマンド

TOPST AI の NPU を使用するために提供される IOCTL コマンドは次のとおりです。

<br/>

### 2.3.1 IOCTL コマンド

NPU ファイルディスクリプタは、/dev/npu0 や /dev/npu1 などの NPU デバイスファイルを
オープンして取得できます。使用可能な IOCTL コマンドは次のとおりです。

<br/>

|        コマンド        |          引数           |          説明           |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req\*  | CMA バッファの割り当て  |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req\*   | ネットワークのロード    |
| NPU_IOCTL_INIT_MLX     | struct mlx_init_req\*   | MLX の初期化            |
| NPU_IOCTL_READ_REG     | struct reg_access_req\* | レジスタから値を読み出す |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req\* | レジスタへ値を書き込む  |
| NPU_IOCTL_RESET_NPU    |                         | NPU のリセット          |

<br/>

NPU_IOCTL_ALLOC_BUFFER コマンドは、構造体 buffer_alloc_req を通じて渡された
size 値を使用して CMA バッファを割り当て、バッファファイルディスクリプタを
返します。
NPU_IOCTL_LOAD_NETWORK コマンドは、構造体 net_load_req を通じて渡された
パラメータを格納する CMA バッファを割り当て、割り当てた CMA バッファへ
パラメータをコピーし、ネットワークファイルディスクリプタを
返します。

### 2.3.2 ネットワークファイルディスクリプタ用 IOCTL インターフェース

ネットワークファイルディスクリプタは、NPU ファイルディスクリプタに
NPU_IOCTL_LOAD_NETWORK コマンドを渡すことで生成できます。poll や close などの
操作をサポートします。使用可能な IOCTL コマンドは次のとおり
です。

<br/>

|          コマンド          |           引数           |           説明           |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req\*     | 推論の実行               |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req\* | 推論サイクルのプロファイル |
| PU_NET_IOCTL_SET_COLOR_FMT | int                      | 入力カラーフォーマットの設定 |

<br/>

NPU_NET_IOCTL_RUN が実行されると、NPU ドライバはネットワークを実行するコマンドを
NPU HW へ送信し、推論が終了する時点は poll を呼び出すことで
確認できます。

### 2.3.3 バッファファイルディスクリプタ用 IOCTL インターフェース

バッファファイルディスクリプタは、NPU ファイルディスクリプタに
NPU_IOCTL_ALLOC_BUFFER コマンドを渡すことで生成できます。

バッファファイルディスクリプタは、mmap や close などの操作をサポートします。

バッファファイルディスクリプタは IOCTL コマンドをサポートしません。ユーザモードからは
mmap を通じて CMA バッファを取得します。CMA バッファは close で解放します。
