# 2. ビデオ出力
---
AI-G は MIPI DSI-2 インタフェースによるビデオ出力に対応しています。
15 ピン FFC コネクタを介して 2 レーンの DSI 接続を提供し、対応する MIPI DSI LCD パネルの接続に適しています。このインタフェースにより、組み込みディスプレイ上でグラフィカルユーザーインタフェースの描画、ビデオ再生、リアルタイムの AI 可視化を滑らかに実行できます。
<br/><br/><br/>

## 2.1 MIPI DSI
---
DSI とは Display Serial Interface の略称で、プロセッサから外部画面へディスプレイデータを伝送するために MIPI Alliance が定めた規格です。組み込み LCD パネルに適した高速かつ低消費電力の通信を実現します。  
前述のとおり、AI-G は 15 ピン FFC コネクタを介して 2 レーンの DSI 接続を提供し、対応する MIPI DSI ディスプレイモジュールを接続して GUI の描画、ビデオ再生、リアルタイム推論の可視化を行うことができます。
<br/><br/>

### 2.1.1 5 インチ DSI ディスプレイ
Elecrow 5 インチ DSI ディスプレイは、IPS パネルと静電容量式タッチに対応した 800×480 解像度の LCD で、Raspberry Pi の MIPI DSI インタフェース向けに設計されています。プラグアンドプレイに対応しているため、追加のドライバのインストールは不要です。本ディスプレイは 15 ピン MIPI DSI コネクタを介して AI-G ボードに接続され、このインタフェースから直接給電されるため、外部電源は必要ありません。  
本モジュールは、AI-G プラットフォーム上の GUI ベースのアプリケーション、リアルタイム監視、インタラクティブな AI デモに適しています。

DSI ディスプレイの仕様は次のとおりです。

| 仕様                | 説明                                |
| ------------------- | -------------------------------------------|
| ディスプレイサイズ        | 5 インチ                                     |
| 解像度          | 800 x 480                                  |
| リフレッシュレート        | 60 Hz                                      |
| インタフェース (ディスプレイ) | MIPI DSI                                   |
| インタフェース (パネル)   | RGB888 ポート                                |
| 動作電圧   | 3.3V                                      |
| 動作温度範囲| -20 °C ～ 70 °C                            |
| ケーブル種類          | Flat Flexible Cable (FFC) (15 ピン)                               |
| 互換性       | Raspberry Pi および AI-G (MIPI DSI インタフェース経由)|

# 3. カメラ接続
---
AI-G は MIPI CSI-2 インタフェースによるカメラ入力に対応しています。
既定では、15 ピンコネクタを介して 2 レーンの CSI 接続を提供します。高解像度や高フレームレートの AI ビジョン処理など、より広い帯域幅が必要なアプリケーション向けに、オプションの 20 ピンコネクタによる 4 レーン構成にも対応しています。
<br/><br/><br/>

## 3.1 MIPI CSI
---
CSI とは Camera Serial Interface の略称で、カメラモジュールをホストプロセッサに接続するために MIPI Alliance が定めた標準インタフェースです。カメラからプロセッサへ画像データを高速かつ低消費電力で伝送できます。  
前述のとおり、AI-G は既定で 2 レーンの CSI 接続を提供し、より高いデータスループットのために 20 ピンコネクタによる 4 レーン構成をオプションでサポートします。  

現在、AI-G は ArduCam (5 MP) および Raspberry Pi v1 Camera (5 MP) モジュールのみに対応しています。
<br/><br/>

### 3.1.1 ArduCam
ArduCam は、組み込みシステムおよび AI アプリケーション向けに設計された汎用性の高いカメラモジュールです。MIPI CSI を含むさまざまなイメージセンサーとインタフェースに対応しているため、AI-G のような開発ボードへの統合に適しています。  
AI-G は 2 レーンまたは 4 レーンの MIPI CSI インタフェースを備えた ArduCam モジュールに対応しており、物体検出や画像分類などの AI ビジョン処理に安定した画像入力を提供します。FFC ケーブルに対応しているため、ArduCam モジュールを AI-G ボードの CSI コネクタに簡単に接続でき、エッジ AI システムにおけるリアルタイムカメラ入力の信頼性の高いソリューションとなります。

ArduCam モジュールの仕様は次のとおりです。

| 仕様                     | 説明                                 |
| ------------------------ | ------------------------------------------- |
| センサー                   | OV5647 (500 万画素)                        |
| 解像度               | 2592 × 1944 (Full 5MP)                      |
| 対応出力フォーマット | RAW, YUV, JPEG (センサーにより異なる)           |
| インタフェース                | MIPI CSI                                    |
| フレームレート               | 1080p で最大 30fps、720p で 60fps         |
| レンズマウント               | 固定焦点レンズ (標準)                 |
| 画角 (FOV)      | 約 54° ～ 70° (モデルにより異なる)         |
| 接続方式          | FFC                   |
| 動作電圧        | 3.3V (代表値)                              |
| 形状              | 小型 PCB、約 25 mm x 24 mm                   |
| 互換性            | Raspberry Pi および AI-G (MIPI CSI ポート経由)      |
| 追加機能      | 低消費電力、プラグアンドプレイモジュール |

fdisk のプロンプトで次のキーを順に入力してください。

- o — 新しい空の DOS パーティションテーブルを作成する (任意、既存のテーブルを消去)

- p — 基本パーティションを選択する

- 1 — パーティション番号を 1 に設定する

- Enter キーを押す — 既定の開始セクタを使用する

- w — パーティションテーブルを書き込んで終了します

```
$ mkdir -p /mnt/nvme

$ mount /dev/nvme0n1p1 /mnt/nvme
```

# 5. イーサネット接続
---
AI-G は、オンボードの RJ45 イーサネットポートを介したイーサネット接続をサポートします。これにより、ボードは標準の TCP/IP プロトコルを使用してローカルネットワークやインターネットと通信できます。イーサネットは、リモートアクセス、データストリーミング、ソフトウェア更新を必要とする AI アプリケーションを展開する際に一般的に使用されます。
<br/><br/><br/>

## 5.1 ルーター経由のネットワーク接続
---
この方法では、標準的なルーターを使用して AI-G をローカルネットワークに接続します。ボードは DHCP によって IP アドレスを自動的に取得するか、静的 IP アドレスを設定することができます。
<br/><br/>

### 5.1.1 ルートファイルシステムを読み書き可能で再マウントする
ルートファイルシステムは読み取り専用でマウントされています。設定ファイルを編集できるように、次のコマンドを使用して書き込み権限付きで再マウントしてください。

```
$ mount -o remount,rw /
```
<br/><br/>


### 5.1.2 ネットワーク設定ファイルの作成
1. DHCP による動的 IP
eth0 インターフェースで DHCP を有効にするには、次の内容で /etc/systemd/network/20-wired.network ファイルを作成または編集してください。

```
$ vi /etc/systemd/network/20-wired.network
 
[Match]
Name=eth0
 
[Network]
DHCP=yes
```

この設定により、systemd-networkd は eth0 インターフェース用の IP アドレスを DHCP 経由で自動的に取得します。

2. 静的 IP の設定
静的 IP アドレスを割り当てたい場合 (例: PC と直接接続する場合や DHCP サーバーが利用できない場合) は、同じファイルを次の内容で編集してください。
```
$ vi /etc/systemd/network/20-wired.network

[Match]
Name=eth0

[Network]
Address=192.168.137.2/24
Gateway=192.168.137.1
DNS=8.8.8.8
```

この設定では、IP アドレスを 192.168.137.2 に設定し、192.168.137.1 をゲートウェイ (Windows ICS で一般的) として使用し、Google DNS を構成します。
<br/><br/>


### 5.1.3 ネットワークサービスの再起動
systemd-networkd サービスを再起動して、新しいネットワーク設定を適用してください。

```
sudo systemctl restart systemd-networkd
```
<br/><br/>

## 6.2 I2C
---
AI-G は 40 ピン GPIO ヘッダーを通じて I2C 通信を提供し、センサー、ディスプレイ、拡張モジュールなどのさまざまな周辺機器と接続できます。Inter-integrated Circuit (I2C) は、データ線 (SDA) とクロック線 (SCL) で構成される 2 線式通信プロトコルであり、複数のデバイスが共有バス上で通信できるようにします。

I2C 通信はマスター/スレーブ方式に従い、1 台のマスターデバイスが通信を制御し、同一バス上に最大 127 台のスレーブデバイスを接続できます。SDA 線はデータの送信と受信の両方に使用され、SCL 線はデータ転送のタイミングを同期します。この同期通信モデルにより、デバイスはクロックに基づいて協調的に情報を交換できます。
<br/><br/><br/>

#### ステップ 3. 実行方法
AI-G ボードで I2C デバイスにアクセスするには、i2c-dev インターフェイスを使用する C プログラムを作成し、ターゲットアーキテクチャ向けにクロスコンパイルする必要があります。  
以下は簡単な例 (I2C_TEST.c) です。

```
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <linux/i2c-dev.h>
#include <sys/ioctl.h>
#include <unistd.h>

#define I2C_DEV "/dev/i2c-1"
#define I2C_ADDR 0x27

// RS: 0 = command, 1 = data
void lcd_send_byte(int fd, unsigned char data, unsigned char mode) {
    unsigned char high = mode | (data & 0xF0) | 0x08; // backlight on
    unsigned char low  = mode | ((data << 4) & 0xF0) | 0x08;
    unsigned char buf[4] = { high | 0x04, high, low | 0x04, low }; // toggle EN bit

    for (int i = 0; i < 4; i++) {
        if (write(fd, &buf[i], 1) != 1) {
            perror("I2C write error");
        }
        usleep(1000); // 1ms delay
    }
}

void lcd_command(int fd, unsigned char cmd) {
    lcd_send_byte(fd, cmd, 0x00);
}

void lcd_data(int fd, unsigned char data) {
    lcd_send_byte(fd, data, 0x01);
}

void lcd_init(int fd) {
    usleep(50000); // wait for LCD power on
    lcd_command(fd, 0x33); // init
    lcd_command(fd, 0x32); // 4-bit mode
    lcd_command(fd, 0x28); // 2 line, 5x8 font
    lcd_command(fd, 0x0C); // display on, cursor off
    lcd_command(fd, 0x06); // entry mode
    lcd_command(fd, 0x01); // clear display
    usleep(2000);
}

void lcd_print(int fd, const char* str) {
    while (*str) {
        lcd_data(fd, *str++);
    }
}

int main() {
    int fd = open(I2C_DEV, O_RDWR);
    if (fd < 0) {
        perror("Failed to open I2C device");
        return 1;
    }

    if (ioctl(fd, I2C_SLAVE, I2C_ADDR) < 0) {
        perror("Failed to set I2C address");
        close(fd);
        return 1;
    }

    lcd_init(fd);
    lcd_print(fd, "test pass!");

    close(fd);
    return 0;
}
```

## 6.3 SPI
---
AI-G は 40 ピン GPIO ヘッダーを通じて Serial Peripheral Interface (SPI) 通信をサポートし、外部デバイスとボード間のデータ交換を可能にします。  

SPI は同期式シリアル通信プロトコルであり、全二重通信が可能なため、データを同時に送信および受信できます。SPI は、Master Out Slave In (MOSI)、Master In Slave Out (MISO)、Serial Clock (SCLK)、Slave Select (SS) の 4 本の主要な線を使用します。

複数のデバイスで線を共有する I2C とは異なり、SPI では各スレーブデバイスに専用の SS 線が必要です。この 1 対多の構造により SPI は高速で実装が容易になりますが、複数のデバイスを接続する場合は物理的な配線が多くなることがあります。
<br/><br/><br/>

#### ステップ 3. 実行方法
AI-G で SPI デバイスと通信するには、spidev インターフェイスを使用する C プログラムを作成し、ターゲットアーキテクチャ向けにクロスコンパイルする必要があります。  
以下は、MAX7219 LED マトリクスディスプレイにデータを送信する簡単な例 (SPI_TEST.c) です。

```
#include <stdio.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>
#include <linux/spi/spidev.h>
#include <sys/ioctl.h>
#include <string.h>

#define SPI_DEV "/dev/spidev3.0"

int spi_fd = -1;

void spi_send(uint8_t address, uint8_t data) {
    uint8_t tx[2] = { address, data };
    struct spi_ioc_transfer tr = {
        .tx_buf = (uintptr_t)tx,
        .rx_buf = 0,
        .len = 2,
        .delay_usecs = 0,
        .speed_hz = 1000000,
        .bits_per_word = 8,
    };

    if (ioctl(spi_fd, SPI_IOC_MESSAGE(1), &tr) < 1) {
        perror("SPI send failed");
    }
}

void max7219_init() {
    spi_send(0x09, 0x00); // Decode mode off
    spi_send(0x0A, 0x08); // Brightness (0x00 ~ 0x0F)
    spi_send(0x0B, 0x07); // Scan limit: display all 8 digits
    spi_send(0x0C, 0x01); // Shutdown register: normal operation
    spi_send(0x0F, 0x00); // Display test: off
}

void max7219_clear() {
    for (int i = 1; i <= 8; i++) {
        spi_send(i, 0x00);
    }
}


const uint8_t letter_P[8] = {
    0b00000000,  
    0b01111110, 
    0b01000010,  
    0b01000010,  
    0b01111110,  
    0b01000000,  
    0b01000000,  
    0b01000000   
};


void draw_letter_P() {
    for (int row = 0; row < 8; row++) {
        spi_send(row + 1, letter_P[row]);
    }
}

int main() {
    spi_fd = open(SPI_DEV, O_RDWR);
    if (spi_fd < 0) {
        perror("Failed to open SPI device");
        return 1;
    }

    max7219_init();
    max7219_clear();
    draw_letter_P();

    close(spi_fd);
    return 0;
}
```

何も表示されない場合やパターンが崩れている場合は、次の点を確認してください。
- SPI ピン (MOSI、SCK、CS) の配線が正しいことを確認します。
- MAX7219 モジュールに電源 (5V、GND) が正しく供給され、すべてのデータ線とクロック線が安定していることを確認します。

## 6.4 UART
---
AI-G は 40 ピン GPIO ヘッダーを通じて Universal Asynchronous Receiver/Transmitter (UART) 通信をサポートし、シリアルコンソールや他のマイクロコントローラなどのデバイスとのシリアル通信を可能にします。  

UART は、TX（送信）と RX（受信）の 2 本のラインを介してデータを 1 ビットずつ転送する、広く使用されている非同期通信プロトコルです。I2C や SPI とは異なり、UART はクロックラインを使用しません。その代わりに、2 つのデバイスはタイミングを合わせるために共通の通信速度を使用する必要があります。
<br/><br/><br/>

#### ステップ 3. 実行方法
このスクリプトは、UART ポートにテストメッセージを送信し、同じメッセージが受信されるかどうかを確認します。  
AI-G で UART ループバックをテストするには、TX ピンと RX ピンを接続してから次のスクリプトを実行してください。

```bash
#!/bin/bash
# ===================== user setting =====================
UART_DEV="/dev/ttyAMA1"       # uart
BAUD=115200                   # Baudrate
TEST_MSG="Hello from UART"    # msg
TEMP_FILE="/tmp/uart_rx.txt"  # file
# =====================================================

if [ ! -e "$UART_DEV" ]; then
    echo "Error: $UART_DEV does not exist"
    exit 1
fi

chmod 666 $UART_DEV

stty -F $UART_DEV $BAUD cs8 -cstopb -parenb -icanon -echo -ixon -ixoff
echo "UART setup complete: port=$UART_DEV, speed=$BAUD"

cat $UART_DEV > $TEMP_FILE &
RX_PID=$!

sleep 0.2
echo -n "$TEST_MSG" > $UART_DEV
echo "Transmission complete: \"$TEST_MSG\""

sleep 1
kill $RX_PID 2>/dev/null

if [ -f "$TEMP_FILE" ]; then
    RECEIVED=$(cat $TEMP_FILE)
    rm $TEMP_FILE
    if [ "$RECEIVED" = "$TEST_MSG" ]; then
        echo "Loopback Success! Received Message: \"$RECEIVED\""
    else
        echo "Received mismatch"
        echo "Sent: \"$TEST_MSG\""
        echo "Received: \"$RECEIVED\""
    fi
else
    echo "Failed to receive: No received file"
fi
```

```
$ ./AI_UART_LOOPBACK_TEST
```

このスクリプトは、指定した UART ポートを設定してテストメッセージを送信します。TX ピンと RX ピンが正しく接続されていれば、同じメッセージが受信されてターミナルに表示され、UART の送受信が正常に動作していることを確認できます。

実行する前に、スクリプトに実行権限が付与されていることを確認してください。

