# 1. はじめに
---
Neural Processing Unit（NPU）は HW ニューラルネットワークアクセラレータであり、AI-G の NPU は物体検出、画像分類、
顔検出などのビジョンアプリケーション向けニューラルネットワークの推論に最適化されています。NPU デバイスドライバは、
ユーザー空間のニューラルネットワークアプリケーションが組み込み Linux 環境で AI-G NPU を使用してニューラルネットワークの
推論を行えるように、NPU を制御するインターフェースを提供します。

本書では、AI-G SDK に含まれる NPU デバイスドライバと NPU API の使用方法について説明します。
<br/><br/><br/><br/>


# 2. NPU Linux デバイスドライバ
---
NPU デバイスドライバは以下を制御します。

- NPU HW の初期化
- コンパイル済みニューラルネットワークの NPU HW への転送
- NPU HW の実行
- NPU HW の処理（推論）結果の読み取り

NPU デバイスドライバが使用するバッファ（code、weight、work、input、output）には連続した物理メモリ空間が必要です。この 
ため、メモリ上のバッファは内部的に Continuous Memory Allocator（CMA）を使用して割り当てられます。
NPU デバイスドライバは、コンパイル済みニューラルネットワークの command ファイルと weight/bias ファイルを入力として受け取り、ネットワークファイル 
ディスクリプタ（fd）を生成します。また、ニューラルネットワークの入力と結果を格納するバッファを割り当て、各バッファにアクセスするための 
バッファ fd を生成します。 

推論を実行するには、
1. 入力バッファの buffer fd に対して mmap を実行し、ユーザー空間からアクセスできる入力バッファアドレスを取得します。
2. 手順 1 で取得した入力バッファアドレスを使用して、入力画像を入力バッファに格納します。
3. NPU_NET_IOCTL_RUN という IOCTL を network fd に渡します。

2 つ以上のニューラルネットワークを実行する場合、NPU デバイスドライバは時分割アルゴリズムでニューラルネットワークを実行します。 
この場合、実行順序は内部的に queue.f コマンドを使用してスケジューリングされるため、ニューラルネットワークはユーザー空間から要求された 
順序で実行されます。

## 2.2 デバイスツリー
---
以下は、AI-G で NPU デバイスドライバを使用するためのデバイスツリーの例です。

```
# NPU device tree example

 npu0: npu@11000000 {
                compatible = "telechips,npu";
                reg = <0x0 0x11000000 0x0 0x400>;
                interrupts = <GIC_SPI 153 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_0_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_0_CCLK &fbus_npu FBUS_NPU_0_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };


npu1: @11000400 {
                compatible = "telechips,";
                reg = <0x0 0x11000400 0x0 0x400>;
                interrupts = <GIC_SPI 154 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_1_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_1_CCLK &fbus_npu FBUS_NPU_1_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };

```

<br/>

| プロパティ | 説明 |
|------------------|---------------------------------------|
| compatible       | “telechips,npu” に固定 |
| reg              | NPU レジスタのベースアドレスとサイズ |
| disable-ue-fail  | UE エラーによる失敗を無効にします。 <br>disable-ue-fail が 0 の場合、UE エラーが検出されると fail が返されます。 <br>または <br>disable-ue-fail が 0x7 の場合、UE エラーは無視されます。 |
| disable-ce-fail  | CE エラーによる失敗を無効にします。 <br>disable-ce-fail が 0 の場合、CE エラーが検出されると fail が返されます。 <br>または <br>disable-ce-fail が 0x7 の場合、CE エラーは無視されます。 |
| disable-wdt      |  ウォッチドッグタイマーを無効にします |
| wdt-timeout-count| ウォッチドッグタイムアウトカウント |
| wdt-rearm-count  | ウォッチドッグ再アームカウント<br>この値はウォッチドッグタイムアウトカウントより小さくする必要があります。 |
| reg-names        | NPU レジスタ名 |
| work-buffer-size | ワークバッファの割り当てサイズ |
| interrupt-parent | 割り込みコントローラのデバイスツリーノード |
| interrupts       | 割り込み番号 |

### 2.3.1 NPU ファイルディスクリプタ用 IOCTL コマンド

NPU ファイルディスクリプタは、/dev/npu0 や /dev/npu1 などの NPU デバイスファイルを開くことで
取得できます。使用可能な IOCTL コマンドは次のとおりです。


| コマンド | 引数 | 説明 |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req*  | CMA バッファを割り当てます |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req*   | ネットワークをロードします |
| NPU_IOCTL_READ_REG     | struct reg_access_req* | レジスタから値を読み取ります |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req* | レジスタに値を書き込みます |
| NPU_IOCTL_RESET_NPU    | struct npu_init_req*   | NPU をリセットします |
| NPU_IOCTL_WRITE_TEST_CFG| test_cfg_wr_req_t*    | ecc_test を書き込みます |
| NPU_IOCTL_READ_NPU_ERR | npu_err_rd_req_t*      | ECC と WDT を読み取ります |

<br/>

NPU_IOCTL_ALLOC_BUFFER コマンドは 
- 構造体 buffer_alloc_req を通じて渡された
size 値を使用して CMA バッファを割り当て、
- バッファファイルディスクリプタを返します。

NPU_IOCTL_LOAD_NETWORK コマンドは 
- 構造体 net_load_req を通じて渡されたパラメータを格納する CMA バッファを割り当て、
- 割り当てられた CMA バッファにパラメータをコピーし、 
- ネットワークファイルディスクリプタを返します。

NPU_IOCTL_WRITE_TEST_CFG と NPU_IOCTL_READ_NPU_ERR は、test_cfg_wr_req_t を通じて送信される NPU テストパラメータ 
値であり、いずれもテスト結果値の読み取りに使用されます。

### 2.3.2 ネットワークファイルディスクリプタ用 IOCTL インターフェース

ネットワークファイルディスクリプタは、NPU ファイルディスクリプタに
NPU_IOCTL_LOAD_NETWORK コマンドを渡すことで作成できます。poll や close
などの操作をサポートします。使用可能な IOCTL コマンドは以下の
とおりです。

<br/>

|         コマンド            |         引数         |         説明      |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req*     | 推論の実行            |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req* | 推論サイクルのプロファイル |
| NPU_NET_IOCTL_SET_COLOR_FMT | int                      | 入力カラーフォーマットの設定   |

<br/>

NPU_NET_IOCTL_RUN が実行されると、NPU ドライバはネットワークを実行するための
コマンドを NPU HW に送信します。推論が終了する時点は
poll を呼び出すことで確認できます。

### 2.3.3 バッファファイルディスクリプタ用 IOCTL インターフェース

バッファファイルディスクリプタ: 
- NPU ファイルディスクリプタに NPU_IOCTL_ALLOC_BUFFER コマンドを送信することで生成できます。 
- mmap や close などの操作をサポートします。 
- IOCTL コマンドはサポートしません。 
- mmap 操作を通じてユーザーモードから CMA バッファを取得します。
- close 操作を通じて CMA バッファを解放します。
