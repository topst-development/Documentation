# 2. ไดรเวอร์อุปกรณ์ NPU LINUX

NPU ของ TOPST AI เป็นตัวเร่งความเร็วโครงข่ายประสาทเทียมแบบ HW ซึ่งได้รับ
การปรับให้เหมาะสมสำหรับการอนุมานของโครงข่ายประสาทเทียมในแอปพลิเคชันด้านวิชัน
เช่น การตรวจจับวัตถุ การจำแนกภาพ และการตรวจจับใบหน้า เอกสาร
“TOPST-AI-Common-SW-NPU-Toolkit Guide” อธิบายวิธีการ
ใช้งาน NPU Toolkit

1.  ไดรเวอร์อุปกรณ์ NPU ควบคุมการเริ่มต้นการทำงานของ NPU HW การส่งโครงข่ายประสาทเทียมที่คอมไพล์แล้วไปยัง NPU HW การทำงานของ
    NPU HW และการอ่านผลลัพธ์การประมวลผล (การอนุมาน) ของ NPU HW
2.  บัฟเฟอร์ (code, weight, work, input และ output) ที่อุปกรณ์ NPU
    ใช้งานต้องการพื้นที่หน่วยความจำทางกายภาพที่ต่อเนื่องกัน
    ด้วยเหตุนี้ บัฟเฟอร์บนหน่วยความจำจึงถูกจัดสรรภายในโดยใช้
    Continuous Memory Allocator (CMA)
3.  ไดรเวอร์อุปกรณ์ NPU รับไฟล์ command และไฟล์ weight/bias ของโครงข่ายประสาทเทียม
    ที่คอมไพล์แล้วเป็นอินพุต เพื่อสร้างไฟล์ดีสคริปเตอร์ของเครือข่าย
    (fd)
4.  นอกจากนี้ยังทำหน้าที่จัดสรรอินพุตของโครงข่ายประสาทเทียมและบัฟเฟอร์
    ที่จะใช้เก็บผลลัพธ์ พร้อมทั้งสร้างบัฟเฟอร์ fd เพื่อเข้าถึง
    แต่ละบัฟเฟอร์
5.  เพื่อดำเนินการอนุมาน ขั้นแรกให้เรียก mmap บนบัฟเฟอร์ fd ของ
    บัฟเฟอร์อินพุต เพื่อรับที่อยู่ของบัฟเฟอร์อินพุตที่สามารถ
    เข้าถึงได้จากยูเซอร์สเปซ ขั้นที่สองให้เก็บภาพอินพุตไว้ใน
    บัฟเฟอร์อินพุตที่ได้มา และสุดท้ายให้ส่ง **IOL ที่ชื่อว่า
    NPU_NET_IOCT_RUNCT** ไปยัง fd ของเครือข่าย
6.  เมื่อมีการทำงานของโครงข่ายประสาทเทียมตั้งแต่สองเครือข่ายขึ้นไป ไดรเวอร์อุปกรณ์ NPU
    จะดำเนินการโครงข่ายประสาทเทียมด้วยอัลกอริทึมแบ่งเวลา
7.  ในกรณีนี้ โครงข่ายประสาทเทียมจะถูกดำเนินการตามลำดับที่ร้องขอจาก
    ยูเซอร์สเปซ เนื่องจากลำดับการทำงานถูกจัดตารางภายในโดยใช้
    command queue

## 2.2 ดีไวซ์ทรี

ใน TOPST AI ข้อมูลสำหรับการใช้งานไดรเวอร์อุปกรณ์ NPU จะถูกตั้งค่าผ่าน
ดีไวซ์ทรีดังต่อไปนี้

```
# NPU device tree example

npu0: npu0 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000000 0x0 0x200>;
		interrupts = <GIC_SPI 146 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};

npu1: npu1 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000200 0x0 0x200>;
		interrupts = <GIC_SPI 147 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};
```

<br/>

|     คุณสมบัติ     |                 คำอธิบาย               |
|------------------|---------------------------------------|
| compatible       | คงที่เป็น “telechipss, npu”            |
| reg              | base address, size ของรีจิสเตอร์ NPU   |
| reg-names        | ชื่อรีจิสเตอร์ NPU                     |
| work-buffer-size | ขนาดการจัดสรรบัฟเฟอร์ Work            |
| interrupt-parent | โหนดดีไวซ์ทรีของตัวควบคุมอินเทอร์รัปต์ |
| interrupts       | หมายเลขอินเทอร์รัปต์                   |

### 2.3.1 คำสั่ง IOCTL

สามารถรับไฟล์ดีสคริปเตอร์ของ NPU ได้โดยการเปิดไฟล์อุปกรณ์ NPU เช่น
/dev/npu0 และ /dev/npu1 คำสั่ง IOCTL ที่ใช้งานได้มีดังนี้

<br/>

|         คำสั่ง         |        อาร์กิวเมนต์      |        คำอธิบาย         |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req\*  | จัดสรรบัฟเฟอร์ CMA      |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req\*   | โหลดเครือข่าย           |
| NPU_IOCTL_INIT_MLX     | struct mlx_init_req\*   | เริ่มต้นการทำงาน MLX     |
| NPU_IOCTL_READ_REG     | struct reg_access_req\* | อ่านค่าจากรีจิสเตอร์     |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req\* | เขียนค่าลงรีจิสเตอร์     |
| NPU_IOCTL_RESET_NPU    |                         | รีเซ็ต NPU              |

<br/>

คำสั่ง NPU_IOCTL_ALLOC_BUFFER จะจัดสรรบัฟเฟอร์ CMA โดยใช้ค่า size
ที่ส่งผ่านโครงสร้าง buffer_alloc_req และคืนค่าไฟล์ดีสคริปเตอร์ของ
บัฟเฟอร์
คำสั่ง NPU_IOCTL_LOAD_NETWORK จะจัดสรรบัฟเฟอร์ CMA เพื่อเก็บ
พารามิเตอร์ที่ส่งผ่านโครงสร้าง net_load_req คัดลอกพารามิเตอร์เหล่านั้น
ไปยังบัฟเฟอร์ CMA ที่จัดสรรไว้ และคืนค่าไฟล์ดีสคริปเตอร์ของ

### 2.3.2 อินเทอร์เฟซ IOCTL สำหรับไฟล์ดีสคริปเตอร์ของเครือข่าย

### 2.3.3 อินเทอร์เฟซ IOCTL สำหรับไฟล์ดีสคริปเตอร์ของบัฟเฟอร์

ไฟล์ดีสคริปเตอร์ของบัฟเฟอร์สามารถสร้างได้โดยการส่งคำสั่ง
NPU_IOCTL_ALLOC_BUFFER ไปยังไฟล์ดีสคริปเตอร์ของ NPU

ไฟล์ดีสคริปเตอร์ของบัฟเฟอร์รองรับการดำเนินการ เช่น mmap, close เป็นต้น

ไฟล์ดีสคริปเตอร์ของบัฟเฟอร์ไม่รองรับคำสั่ง IOCTL รับบัฟเฟอร์ CMA
จากยูเซอร์โหมดผ่าน mmap และปล่อยบัฟเฟอร์ CMA ด้วย close
