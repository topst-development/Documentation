# 1. บทนำ 
---
เอกสารนี้นำเสนอตัวอย่างการใช้งาน AI-G   
เอกสารนี้ประกอบด้วยข้อมูลต่อไปนี้:
- การแสดงผลวิดีโอ
  - MIPI DSI
- การเชื่อมต่อกล้อง
  - MIPI CSI
- การเชื่อมต่ออุปกรณ์จัดเก็บข้อมูล
  - NVMe M.2 SSD
- การเชื่อมต่ออีเทอร์เน็ต
- เฮดเดอร์ GPIO 40 พิน
  - เซ็นเซอร์และอุปกรณ์ที่ใช้งานได้
<br/><br/><br/><br/>


# 2. การแสดงผลวิดีโอ
---
AI-G รองรับการแสดงผลวิดีโอผ่านอินเทอร์เฟซ MIPI DSI-2
บอร์ดรองรับการเชื่อมต่อ DSI แบบ 2 เลนผ่านขั้วต่อ FFC 15 พิน ซึ่งเหมาะสำหรับการเชื่อมต่อกับแผงจอ LCD แบบ MIPI DSI ที่รองรับ อินเทอร์เฟซนี้ช่วยให้แสดงผลส่วนติดต่อผู้ใช้แบบกราฟิก เล่นวิดีโอ และแสดงผลการทำงานของ AI แบบเรียลไทม์บนจอแสดงผลแบบฝังตัวได้อย่างราบรื่น
<br/><br/><br/>

## 2.1 MIPI DSI
---
DSI ย่อมาจาก Display Serial Interface ซึ่งเป็นมาตรฐานที่กำหนดโดย MIPI Alliance สำหรับการส่งข้อมูลการแสดงผลจากโปรเซสเซอร์ไปยังหน้าจอภายนอก มาตรฐานนี้รองรับการสื่อสารความเร็วสูงและใช้พลังงานต่ำ ซึ่งเหมาะกับแผงจอ LCD แบบฝังตัว  
ตามที่กล่าวไว้ข้างต้น AI-G รองรับการเชื่อมต่อ DSI แบบ 2 เลนผ่านขั้วต่อ FFC 15 พิน จึงสามารถเชื่อมต่อกับโมดูลจอแสดงผล MIPI DSI ที่รองรับ เพื่อการแสดงผล GUI การเล่นวิดีโอ หรือการแสดงผลการอนุมานแบบเรียลไทม์
<br/><br/>

### 2.1.1 จอแสดงผล DSI ขนาด 5 นิ้ว
จอแสดงผล DSI ขนาด 5 นิ้วของ Elecrow เป็นจอ LCD ความละเอียด 800×480 พร้อมแผงจอแบบ IPS และรองรับระบบสัมผัสแบบ capacitive ออกแบบมาเพื่อใช้งานกับอินเทอร์เฟซ MIPI DSI ของ Raspberry Pi ด้วยความสามารถแบบ plug-and-play จึงไม่จำเป็นต้องติดตั้งไดรเวอร์เพิ่มเติม จอแสดงผลเชื่อมต่อกับบอร์ด AI-G ผ่านขั้วต่อ MIPI DSI 15 พิน และรับไฟเลี้ยงโดยตรงผ่านอินเทอร์เฟซดังกล่าว จึงไม่จำเป็นต้องใช้แหล่งจ่ายไฟภายนอก  
โมดูลนี้เหมาะสำหรับแอปพลิเคชันที่ใช้ GUI การตรวจสอบแบบเรียลไทม์ และการสาธิต AI แบบโต้ตอบบนแพลตฟอร์ม AI-G

| ------------------- | -------------------------------------------|
| ขนาดจอแสดงผล        | 5 นิ้ว                                     |
| ความละเอียด          | 800 x 480                                  |
| อัตรารีเฟรช        | 60 Hz                                      |
| อินเทอร์เฟซ (จอแสดงผล) | MIPI DSI                                   |
| อินเทอร์เฟซ (แผงจอ)   | พอร์ต RGB888                                |
| แรงดันไฟฟ้าใช้งาน   | 3.3V                                      |
| ช่วงอุณหภูมิใช้งาน| -20 °C ถึง 70 °C                            |

# 3. การเชื่อมต่อกล้อง
---
AI-G รองรับสัญญาณเข้าจากกล้องผ่านอินเทอร์เฟซ MIPI CSI-2
โดยค่าเริ่มต้น บอร์ดรองรับการเชื่อมต่อ CSI แบบ 2 เลนผ่านขั้วต่อ 15 พิน สำหรับแอปพลิเคชันที่ต้องการแบนด์วิดท์สูงขึ้น เช่น งานด้าน AI vision ที่ความละเอียดสูงหรืออัตราเฟรมสูง บอร์ดยังรองรับการกำหนดค่าแบบ 4 เลนผ่านขั้วต่อ 20 พินซึ่งเป็นอุปกรณ์เสริมด้วย
<br/><br/><br/>

## 3.1 MIPI CSI
---
CSI ย่อมาจาก Camera Serial Interface ซึ่งเป็นอินเทอร์เฟซมาตรฐานที่กำหนดโดย MIPI Alliance สำหรับการเชื่อมต่อโมดูลกล้องเข้ากับโปรเซสเซอร์หลัก อินเทอร์เฟซนี้รองรับการส่งข้อมูลภาพจากกล้องไปยังโปรเซสเซอร์ด้วยความเร็วสูงและใช้พลังงานต่ำ  
ตามที่อธิบายไว้ข้างต้น AI-G รองรับการเชื่อมต่อ CSI แบบ 2 เลนโดยค่าเริ่มต้น และรองรับการกำหนดค่าแบบ 4 เลนผ่านขั้วต่อ 20 พินเป็นตัวเลือกเสริม เพื่อให้ได้อัตราการส่งข้อมูลที่สูงขึ้น  

ปัจจุบัน AI-G รองรับเฉพาะโมดูล ArduCam (5 MP) และ Raspberry Pi v1 Camera (5 MP) เท่านั้น
<br/><br/>

### 3.1.1 ArduCam
ArduCam เป็นโมดูลกล้องอเนกประสงค์ที่ออกแบบมาสำหรับระบบฝังตัวและแอปพลิเคชัน AI รองรับเซ็นเซอร์ภาพและอินเทอร์เฟซหลากหลายรูปแบบ รวมถึง MIPI CSI จึงเหมาะสำหรับการนำไปใช้ร่วมกับบอร์ดพัฒนาอย่าง AI-G  
AI-G รองรับโมดูล ArduCam ที่ใช้อินเทอร์เฟซ MIPI CSI แบบ 2 เลนหรือ 4 เลน ทำให้ได้สัญญาณภาพเข้าที่เสถียรสำหรับงานด้าน AI vision เช่น การตรวจจับวัตถุและการจำแนกภาพ ด้วยความเข้ากันได้กับสาย FFC โมดูล ArduCam จึงเชื่อมต่อเข้ากับขั้วต่อ CSI ของบอร์ด AI-G ได้อย่างง่ายดาย นับเป็นโซลูชันที่เชื่อถือได้สำหรับสัญญาณภาพเข้าแบบเรียลไทม์ในระบบ edge AI

ข้อมูลจำเพาะของโมดูล ArduCam มีดังนี้:

| ข้อมูลจำเพาะ                     | รายละเอียด                                 |
| ------------------------ | ------------------------------------------- |
| เซ็นเซอร์                   | OV5647 (5 ล้านพิกเซล)                        |
| ความละเอียด               | 2592 × 1944 (Full 5MP)                      |
| รูปแบบเอาต์พุตที่รองรับ | RAW, YUV, JPEG (ขึ้นอยู่กับเซ็นเซอร์)           |
| อินเทอร์เฟซ                | MIPI CSI                                    |
| อัตราเฟรม               | สูงสุด 30fps ที่ 1080p และ 60fps ที่ 720p         |
| เมาท์เลนส์               | เลนส์โฟกัสคงที่ (มาตรฐาน)                 |
| มุมมองภาพ (FOV)      | ประมาณ 54° ถึง 70° (แตกต่างกันตามรุ่น)         |
| รูปแบบการเชื่อมต่อ          | FFC                   |
| แรงดันไฟฟ้าใช้งาน        | 3.3V (ค่าทั่วไป)                              |
| ขนาดรูปทรง              | PCB ขนาดกะทัดรัด ประมาณ 25 mm x 24 mm                   |
| ความเข้ากันได้            | Raspberry Pi และ AI-G (ผ่านพอร์ต MIPI CSI)      |
| คุณสมบัติเพิ่มเติม      | ใช้พลังงานต่ำ เป็นโมดูลแบบ plug-and-play |

### 3.1.2 Raspberry Pi v1 Camera
Raspberry Pi Camera Module v1 เป็นกล้องขนาดกะทัดรัดความละเอียด 5 MP ที่พัฒนาโดย Raspberry Pi Foundation โมดูลนี้ใช้เซ็นเซอร์ภาพ OmniVision OV5647 และเชื่อมต่อกับบอร์ดโฮสต์ผ่านอินเทอร์เฟซ MIPI CSI-2 โดยใช้สาย Flat Flexible Cable (FFC) 

แม้ว่าเดิมทีจะออกแบบมาสำหรับ Raspberry Pi ซีรีส์ แต่โมดูลนี้ยังใช้งานร่วมกับ AI-G ได้ผ่านขั้วต่อ MIPI CSI 15 พิน โมดูลนี้เป็นโซลูชันที่เชื่อถือได้สำหรับแอปพลิเคชันกล้องระดับเริ่มต้น เช่น การถ่ายภาพ การสตรีมวิดีโอ และงานคอมพิวเตอร์วิทัศน์ที่ขับเคลื่อนด้วย AI บนแพลตฟอร์ม AI-G

# 4. การเชื่อมต่ออุปกรณ์จัดเก็บข้อมูล
---
บทนี้อธิบายวิธีเชื่อมต่อบอร์ด AI-G เข้ากับอุปกรณ์จัดเก็บข้อมูลประเภทต่าง ๆ ตัวเลือกการจัดเก็บข้อมูลที่รองรับ ได้แก่ อุปกรณ์จัดเก็บข้อมูลภายนอกผ่าน PCIe
<br/><br/><br/>

## 4.1 NVMe M.2 SSD
---
AI-G รองรับอุปกรณ์จัดเก็บข้อมูลแบบ M.2 SSD ผ่านสล็อต PCIe

#### ขั้นตอนที่ 1. เชื่อมต่อ SSD
- NVMe SSD (M.2 PCIe): เสียบ NVMe M.2 SSD เข้ากับสล็อต PCIe ของบอร์ด AI-G

## 5.1 การเชื่อมต่อเครือข่ายผ่านเราเตอร์
---
วิธีนี้เชื่อมต่อ AI-G เข้ากับเครือข่ายภายในโดยใช้เราเตอร์มาตรฐาน บอร์ดสามารถรับที่อยู่ IP โดยอัตโนมัติผ่าน DHCP หรือกำหนดค่าด้วยที่อยู่ IP แบบคงที่ก็ได้
<br/><br/>

### 5.1.1 เมาต์ระบบไฟล์รูทใหม่เป็นแบบอ่าน/เขียน
ระบบไฟล์รูทถูกเมาต์เป็นแบบอ่านอย่างเดียว ให้เมาต์ใหม่พร้อมสิทธิ์การเขียนเพื่อให้สามารถแก้ไขไฟล์การกำหนดค่าได้ โดยใช้คำสั่งต่อไปนี้:

```
$ mount -o remount,rw /
```
<br/><br/>


### 5.1.2 สร้างไฟล์การกำหนดค่าเครือข่าย
1. IP แบบไดนามิกผ่าน DHCP
สร้างหรือแก้ไขไฟล์ /etc/systemd/network/20-wired.network ด้วยเนื้อหาต่อไปนี้เพื่อเปิดใช้งาน DHCP บนอินเทอร์เฟซ eth0

```
$ vi /etc/systemd/network/20-wired.network
 
[Match]
Name=eth0
 
[Network]
DHCP=yes
```

การกำหนดค่านี้สั่งให้ systemd-networkd รับที่อยู่ IP สำหรับอินเทอร์เฟซ eth0 โดยอัตโนมัติผ่าน DHCP

2. การกำหนดค่า IP แบบคงที่
หากต้องการกำหนดที่อยู่ IP แบบคงที่ (ตัวอย่างเช่น เมื่อเชื่อมต่อกับ PC โดยตรง หรือไม่มีเซิร์ฟเวอร์ DHCP ให้ใช้งาน) ให้แก้ไขไฟล์เดิมด้วยเนื้อหาต่อไปนี้:
```

Name=eth0

```

การตั้งค่านี้กำหนดที่อยู่ IP เป็น 192.168.137.2 ใช้ 192.168.137.1 เป็นเกตเวย์ (ซึ่งพบได้ทั่วไปใน Windows ICS) และกำหนดค่า Google DNS

### 5.1.3 รีสตาร์ตบริการเครือข่าย

### 6.1.1 LED

#### ขั้นตอนที่ 3. วิธีการดำเนินการ
หากต้องการสั่งงาน LED ที่เชื่อมต่อกับ GPIO72 บนบอร์ด AI-G ให้รันโค้ดต่อไปนี้:

```bash
#!/bin/bash

GPIO=72
INTERVAL=1

# GPIO export
if [ ! -e /sys/class/gpio/gpio$GPIO ]; then
    echo "$GPIO" > /sys/class/gpio/export
    sleep 0.1
fi

echo "out" > /sys/class/gpio/gpio$GPIO/direction

trap "echo $GPIO > /sys/class/gpio/unexport; echo -e '\nGPIO$GPIO unexported. Exit.'; exit" SIGINT

echo "Toggling GPIO$GPIO every $INTERVAL second(s). Press Ctrl+C to stop."

while true; do
    echo 1 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
    echo 0 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
done
```

#### ขั้นตอนที่ 4. ผลลัพธ์การทำงาน
รันโค้ดด้วยคำสั่งต่อไปนี้
```
$ ./AI_GPIO_LED_TEST
```

สคริปต์นี้กำหนดค่า GPIO72 เป็นเอาต์พุตแบบดิจิทัลและสลับสถานะอย่างต่อเนื่องทุก ๆ 1 วินาที เมื่อรัน LED ที่เชื่อมต่อกับ GPIO72 จะกะพริบซ้ำ ๆ โดยติด 1 วินาทีแล้วดับ 1 วินาทีในลูปไม่รู้จบ

หากต้องการหยุดสคริปต์ ให้กด **[Ctrl+C]**  
เมื่อสคริปต์สิ้นสุดลง GPIO72 จะถูก unexport และล้างค่าโดยอัตโนมัติ  
ตรวจสอบให้แน่ใจว่าได้ให้สิทธิ์การรันแก่สคริปต์ก่อนเรียกใช้งาน:

## 6.2 I2C
---
AI-G รองรับการสื่อสาร I2C ผ่านเฮดเดอร์ GPIO 40 พิน ทำให้สามารถเชื่อมต่อกับอุปกรณ์ต่อพ่วงต่าง ๆ เช่น เซ็นเซอร์ จอแสดงผล และโมดูลส่วนขยาย โดย Inter-integrated Circuit (I2C) เป็นโปรโตคอลการสื่อสารแบบสองสายที่ประกอบด้วยสายข้อมูล (SDA) และสายสัญญาณนาฬิกา (SCL) ซึ่งทำให้อุปกรณ์หลายตัวสื่อสารกันผ่านบัสร่วมได้

การสื่อสาร I2C ใช้สถาปัตยกรรมแบบมาสเตอร์-สเลฟ โดยอุปกรณ์มาสเตอร์หนึ่งตัวควบคุมการสื่อสาร และสามารถเชื่อมต่ออุปกรณ์สเลฟได้สูงสุด 127 ตัวบนบัสเดียวกัน สาย SDA ใช้สำหรับทั้งการส่งและรับข้อมูล ในขณะที่สาย SCL ทำหน้าที่ซิงโครไนซ์จังหวะเวลาของการถ่ายโอนข้อมูล รูปแบบการสื่อสารแบบซิงโครนัสนี้ทำให้อุปกรณ์แลกเปลี่ยนข้อมูลได้อย่างเป็นระบบตามสัญญาณนาฬิกา

#### ขั้นตอนที่ 3. วิธีการดำเนินการ
หากต้องการเข้าถึงอุปกรณ์ I2C บนบอร์ด AI-G คุณต้องเขียนโปรแกรมภาษา C โดยใช้อินเทอร์เฟซ i2c-dev และคอมไพล์ข้ามแพลตฟอร์มสำหรับสถาปัตยกรรมเป้าหมาย  
ต่อไปนี้เป็นตัวอย่างอย่างง่าย (I2C_TEST.c):

```
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <linux/i2c-dev.h>
#include <sys/ioctl.h>
#include <unistd.h>

#define I2C_DEV "/dev/i2c-1"
#define I2C_ADDR 0x27

// RS: 0 = command, 1 = data
void lcd_send_byte(int fd, unsigned char data, unsigned char mode) {
    unsigned char high = mode | (data & 0xF0) | 0x08; // backlight on
    unsigned char low  = mode | ((data << 4) & 0xF0) | 0x08;
    unsigned char buf[4] = { high | 0x04, high, low | 0x04, low }; // toggle EN bit

    for (int i = 0; i < 4; i++) {
        if (write(fd, &buf[i], 1) != 1) {
            perror("I2C write error");
        }
        usleep(1000); // 1ms delay
    }
}

void lcd_command(int fd, unsigned char cmd) {
    lcd_send_byte(fd, cmd, 0x00);
}

void lcd_data(int fd, unsigned char data) {
    lcd_send_byte(fd, data, 0x01);
}

void lcd_init(int fd) {
    usleep(50000); // wait for LCD power on
    lcd_command(fd, 0x33); // init
    lcd_command(fd, 0x32); // 4-bit mode
    lcd_command(fd, 0x28); // 2 line, 5x8 font
    lcd_command(fd, 0x0C); // display on, cursor off
    lcd_command(fd, 0x06); // entry mode
    lcd_command(fd, 0x01); // clear display
    usleep(2000);
}

void lcd_print(int fd, const char* str) {
    while (*str) {
        lcd_data(fd, *str++);
    }
}

int main() {
    int fd = open(I2C_DEV, O_RDWR);
    if (fd < 0) {
        perror("Failed to open I2C device");
        return 1;
    }

    if (ioctl(fd, I2C_SLAVE, I2C_ADDR) < 0) {
        perror("Failed to set I2C address");
        close(fd);
        return 1;
    }

    lcd_init(fd);
    lcd_print(fd, "test pass!");

    close(fd);
    return 0;
}
```

## 6.3 SPI
---
AI-G รองรับการสื่อสาร Serial Peripheral Interface (SPI) ผ่านเฮดเดอร์ GPIO 40 พิน ทำให้สามารถแลกเปลี่ยนข้อมูลระหว่างอุปกรณ์ภายนอกกับบอร์ดได้  

SPI เป็นโปรโตคอลการสื่อสารแบบอนุกรมชนิดซิงโครนัสที่รองรับการสื่อสารแบบฟูลดูเพล็กซ์ ซึ่งหมายความว่าสามารถส่งและรับข้อมูลได้พร้อมกัน โดยใช้สายสัญญาณหลักสี่เส้น ได้แก่ Master Out Slave In (MOSI), Master In Slave Out (MISO), Serial Clock (SCLK) และ Slave Select (SS)

ต่างจาก I2C ที่ใช้สายสัญญาณร่วมกันสำหรับอุปกรณ์หลายตัว SPI ต้องใช้สาย SS เฉพาะสำหรับอุปกรณ์สเลฟแต่ละตัว โครงสร้างแบบหนึ่งต่อหลายนี้ทำให้ SPI ทำงานได้รวดเร็วและนำไปใช้งานได้ง่าย แต่อาจต้องเดินสายจริงมากขึ้นเมื่อมีอุปกรณ์หลายตัว
<br/><br/><br/>

### 6.3.1 ดอตเมทริกซ์
---
จอแสดงผลแบบดอตเมทริกซ์ 8x8 มักใช้สำหรับการแสดงข้อความหรือรูปแบบอย่างง่ายในระบบสมองกลฝังตัว บน AI-G สามารถควบคุมโมดูลดอตเมทริกซ์ผ่าน SPI ได้โดยใช้ชิปไดรเวอร์ เช่น MAX7219

MAX7219 จัดการการสแกนแถวและคอลัมน์ภายในตัวเอง จึงทำให้ไมโครคอนโทรลเลอร์ควบคุมจอแสดงผลทั้งหมดได้โดยใช้สัญญาณ SPI เพียงไม่กี่เส้น ได้แก่ MOSI (DIN), SCLK และ CS (LOAD) เมื่อเชื่อมต่อแล้ว สามารถควบคุมจอแสดงผลได้ด้วยการสื่อสาร SPI ผ่านสคริปต์หรือไลบรารีที่ผู้ใช้กำหนดเอง

#### ขั้นตอนที่ 3. วิธีการดำเนินการ
หากต้องการสื่อสารกับอุปกรณ์ SPI บน AI-G คุณต้องเขียนโปรแกรมภาษา C โดยใช้อินเทอร์เฟซ spidev และคอมไพล์ข้ามแพลตฟอร์มสำหรับสถาปัตยกรรมเป้าหมาย  
ต่อไปนี้เป็นตัวอย่างอย่างง่าย (SPI_TEST.c) ที่ส่งข้อมูลไปยังจอแสดงผล LED เมทริกซ์ MAX7219:

```
#include <stdio.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>
#include <linux/spi/spidev.h>
#include <sys/ioctl.h>
#include <string.h>

#define SPI_DEV "/dev/spidev3.0"

int spi_fd = -1;

void spi_send(uint8_t address, uint8_t data) {
    uint8_t tx[2] = { address, data };
    struct spi_ioc_transfer tr = {
        .tx_buf = (uintptr_t)tx,
        .rx_buf = 0,
        .len = 2,
        .delay_usecs = 0,
        .speed_hz = 1000000,
        .bits_per_word = 8,
    };

    if (ioctl(spi_fd, SPI_IOC_MESSAGE(1), &tr) < 1) {
        perror("SPI send failed");
    }
}

void max7219_init() {
    spi_send(0x09, 0x00); // Decode mode off
    spi_send(0x0A, 0x08); // Brightness (0x00 ~ 0x0F)
    spi_send(0x0B, 0x07); // Scan limit: display all 8 digits
    spi_send(0x0C, 0x01); // Shutdown register: normal operation
    spi_send(0x0F, 0x00); // Display test: off
}

void max7219_clear() {
    for (int i = 1; i <= 8; i++) {
        spi_send(i, 0x00);
    }
}


const uint8_t letter_P[8] = {
    0b00000000,  
    0b01111110, 
    0b01000010,  
    0b01000010,  
    0b01111110,  
    0b01000000,  
    0b01000000,  
    0b01000000   
};


void draw_letter_P() {
    for (int row = 0; row < 8; row++) {
        spi_send(row + 1, letter_P[row]);
    }
}

int main() {
    spi_fd = open(SPI_DEV, O_RDWR);
    if (spi_fd < 0) {
        perror("Failed to open SPI device");
        return 1;
    }

    max7219_init();
    max7219_clear();
    draw_letter_P();

    close(spi_fd);
    return 0;
}
```

## 6.4 UART
---
AI-G รองรับการสื่อสาร Universal Asynchronous Receiver/Transmitter (UART) ผ่านเฮดเดอร์ GPIO 40 พิน ทำให้สามารถสื่อสารแบบอนุกรมกับอุปกรณ์ต่าง ๆ เช่น คอนโซลอนุกรมและไมโครคอนโทรลเลอร์อื่น ๆ ได้  

UART เป็นโปรโตคอลการสื่อสารแบบอะซิงโครนัสที่ใช้กันอย่างแพร่หลาย ซึ่งส่งข้อมูลครั้งละหนึ่งบิตผ่านสองเส้นสัญญาณ ได้แก่ TX (ส่ง) และ RX (รับ) ต่างจาก I2C หรือ SPI ตรงที่ UART ไม่ใช้เส้นสัญญาณนาฬิกา แต่อุปกรณ์ทั้งสองจะต้องใช้ความเร็วในการสื่อสารร่วมกันเพื่อกำหนดจังหวะเวลา
<br/><br/><br/>

#### ขั้นตอนที่ 3. วิธีการดำเนินการ
สคริปต์นี้จะส่งข้อความทดสอบไปยังพอร์ต UART และตรวจสอบว่าได้รับข้อความเดียวกันกลับมาหรือไม่  
หากต้องการทดสอบ UART Loopback บน AI-G ให้รันสคริปต์ต่อไปนี้หลังจากเชื่อมต่อพิน TX และ RX เข้าด้วยกันแล้ว

```bash
#!/bin/bash
# ===================== user setting =====================
UART_DEV="/dev/ttyAMA1"       # uart
BAUD=115200                   # Baudrate
TEST_MSG="Hello from UART"    # msg
TEMP_FILE="/tmp/uart_rx.txt"  # file
# =====================================================

if [ ! -e "$UART_DEV" ]; then
    echo "Error: $UART_DEV does not exist"
    exit 1
fi

chmod 666 $UART_DEV

stty -F $UART_DEV $BAUD cs8 -cstopb -parenb -icanon -echo -ixon -ixoff
echo "UART setup complete: port=$UART_DEV, speed=$BAUD"

cat $UART_DEV > $TEMP_FILE &
RX_PID=$!

sleep 0.2
echo -n "$TEST_MSG" > $UART_DEV
echo "Transmission complete: \"$TEST_MSG\""

sleep 1
kill $RX_PID 2>/dev/null

if [ -f "$TEMP_FILE" ]; then
    RECEIVED=$(cat $TEMP_FILE)
    rm $TEMP_FILE
    if [ "$RECEIVED" = "$TEST_MSG" ]; then
        echo "Loopback Success! Received Message: \"$RECEIVED\""
    else
        echo "Received mismatch"
        echo "Sent: \"$TEST_MSG\""
        echo "Received: \"$RECEIVED\""
    fi
else
    echo "Failed to receive: No received file"
fi
```
