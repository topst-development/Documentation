# 1. บทนำ
---
Neural Processing Unit (NPU) เป็นตัวเร่งความเร็วโครงข่ายประสาทเทียมแบบ HW และ NPU ใน AI-G ได้รับการปรับให้เหมาะสมสำหรับการอนุมานของ 
โครงข่ายประสาทเทียมสำหรับแอปพลิเคชันด้านวิชัน เช่น การตรวจจับวัตถุ การจำแนกภาพ และการตรวจจับใบหน้า ไดรเวอร์อุปกรณ์ NPU 
มีอินเทอร์เฟซสำหรับควบคุม NPU เพื่อให้แอปพลิเคชันโครงข่ายประสาทเทียมในพื้นที่ผู้ใช้สามารถใช้ AI-G NPU ในการอนุมาน 
โครงข่ายประสาทเทียมในสภาพแวดล้อม Linux แบบฝังตัวได้

เอกสารนี้อธิบายวิธีการใช้ไดรเวอร์อุปกรณ์ NPU และ NPU API ที่รวมอยู่ใน AI-G SDK
<br/><br/><br/><br/>


# 2. ไดรเวอร์อุปกรณ์ NPU Linux
---
ไดรเวอร์อุปกรณ์ NPU ควบคุมสิ่งต่อไปนี้:

- การเริ่มต้นการทำงานของ NPU HW
- การส่งโครงข่ายประสาทเทียมที่คอมไพล์แล้วไปยัง NPU HW
- การทำงานของ NPU HW
- การอ่านผลลัพธ์การประมวลผล (การอนุมาน) ของ NPU HW

บัฟเฟอร์ (code, weight, work, input และ output) ที่ไดรเวอร์อุปกรณ์ NPU ใช้งานต้องการพื้นที่หน่วยความจำกายภาพแบบต่อเนื่อง ด้วยเหตุนี้ 
บัฟเฟอร์ในหน่วยความจำจึงถูกจัดสรรภายในโดยใช้ Continuous Memory Allocator (CMA)
ไดรเวอร์อุปกรณ์ NPU รับไฟล์ command และไฟล์ weight/bias ของโครงข่ายประสาทเทียมที่คอมไพล์แล้วเป็นอินพุต เพื่อสร้างตัวระบุไฟล์ 
ของเน็ตเวิร์ก (fd) นอกจากนี้ยังจัดสรรอินพุตของโครงข่ายประสาทเทียมและบัฟเฟอร์สำหรับเก็บผลลัพธ์ และสร้าง buffer fd เพื่อเข้าถึง 
แต่ละบัฟเฟอร์ 

หากต้องการดำเนินการอนุมาน
1. เรียกใช้ mmap บน buffer fd ของบัฟเฟอร์อินพุต เพื่อรับที่อยู่บัฟเฟอร์อินพุตที่สามารถเข้าถึงได้จากพื้นที่ผู้ใช้
2. จัดเก็บภาพอินพุตไว้ในบัฟเฟอร์อินพุตโดยใช้ที่อยู่บัฟเฟอร์อินพุตที่ได้จากขั้นตอนที่ 1
3. ส่ง IOCTL ที่ชื่อ NPU_NET_IOCTL_RUN ไปยัง network fd

เมื่อมีการเรียกใช้โครงข่ายประสาทเทียมตั้งแต่สองโครงข่ายขึ้นไป ไดรเวอร์อุปกรณ์ NPU จะเรียกใช้โครงข่ายประสาทเทียมด้วยอัลกอริทึมแบ่งเวลา 
ในกรณีนี้ โครงข่ายประสาทเทียมจะถูกเรียกใช้ตามลำดับที่พื้นที่ผู้ใช้ร้องขอ เนื่องจากลำดับการทำงานถูกจัดตารางเวลา 
ภายในโดยใช้คำสั่ง queue.f

## 2.2 Device Tree
---
ตัวอย่างต่อไปนี้คือ device tree สำหรับการใช้ไดรเวอร์อุปกรณ์ NPU ใน AI-G

```
# NPU device tree example

 npu0: npu@11000000 {
                compatible = "telechips,npu";
                reg = <0x0 0x11000000 0x0 0x400>;
                interrupts = <GIC_SPI 153 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_0_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_0_CCLK &fbus_npu FBUS_NPU_0_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };


npu1: @11000400 {
                compatible = "telechips,";
                reg = <0x0 0x11000400 0x0 0x400>;
                interrupts = <GIC_SPI 154 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_1_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_1_CCLK &fbus_npu FBUS_NPU_1_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };

```

<br/>

| พร็อพเพอร์ตี | คำอธิบาย |
|------------------|---------------------------------------|
| compatible       | กำหนดตายตัวเป็น “telechips,npu” |
| reg              | ที่อยู่ฐานและขนาดของรีจิสเตอร์ NPU |
| disable-ue-fail  | ปิดการทำงานของความล้มเหลวจากข้อผิดพลาด UE <br>หาก disable-ue-fail เป็น 0 จะคืนค่า fail เมื่อตรวจพบข้อผิดพลาด UE <br>หรือ <br>หาก disable-ue-fail เป็น 0x7 ข้อผิดพลาด UE จะถูกละเว้น |
| disable-ce-fail  | ปิดการทำงานของความล้มเหลวจากข้อผิดพลาด CE <br>หาก disable-ce-fail เป็น 0 จะคืนค่า fail เมื่อตรวจพบข้อผิดพลาด CE <br>หรือ <br>หาก disable-ce-fail เป็น 0x7 ข้อผิดพลาด CE จะถูกละเว้น |
| disable-wdt      |  ปิดการทำงานของวอตช์ด็อกไทเมอร์ |
| wdt-timeout-count| จำนวนไทม์เอาต์ของวอตช์ด็อก |
| wdt-rearm-count  | จำนวนการรีอาร์มของวอตช์ด็อก<br>ค่านี้ต้องน้อยกว่าจำนวนไทม์เอาต์ของวอตช์ด็อก |
| reg-names        | ชื่อรีจิสเตอร์ NPU |
| work-buffer-size | ขนาดการจัดสรรบัฟเฟอร์งาน |
| interrupt-parent | โหนด device tree ของตัวควบคุมอินเทอร์รัปต์ |
| interrupts       | หมายเลขอินเทอร์รัปต์ |

## 2.3 คำสั่ง IOCTL
---
คำสั่ง IOCTL ที่มีให้สำหรับการใช้งาน NPU ของ AI-G มีดังนี้

<br/><br/>

### 2.3.1 คำสั่ง IOCTL สำหรับตัวระบุไฟล์ NPU

ตัวระบุไฟล์ NPU สามารถรับได้โดยการเปิดไฟล์อุปกรณ์ NPU เช่น
/dev/npu0 และ /dev/npu1 คำสั่ง IOCTL ที่ใช้ได้มีดังนี้


| คำสั่ง | อาร์กิวเมนต์ | คำอธิบาย |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req*  | จัดสรรบัฟเฟอร์ CMA |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req*   | โหลดเน็ตเวิร์ก |
| NPU_IOCTL_READ_REG     | struct reg_access_req* | อ่านค่าจากรีจิสเตอร์ |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req* | เขียนค่าไปยังรีจิสเตอร์ |
| NPU_IOCTL_RESET_NPU    | struct npu_init_req*   | รีเซ็ต NPU |
| NPU_IOCTL_WRITE_TEST_CFG| test_cfg_wr_req_t*    | เขียน ecc_test |
| NPU_IOCTL_READ_NPU_ERR | npu_err_rd_req_t*      | อ่าน ECC และ WDT |

<br/>

คำสั่ง NPU_IOCTL_ALLOC_BUFFER 
- จัดสรรบัฟเฟอร์ CMA โดยใช้
ค่า size ที่ส่งผ่านโครงสร้าง buffer_alloc_req และ
- คืนค่าตัวระบุไฟล์ของบัฟเฟอร์

คำสั่ง NPU_IOCTL_LOAD_NETWORK 
- จัดสรรบัฟเฟอร์ CMA เพื่อจัดเก็บพารามิเตอร์ที่ส่งผ่านโครงสร้าง net_load_req
- คัดลอกพารามิเตอร์ไปยังบัฟเฟอร์ CMA ที่จัดสรรไว้ และ 
- คืนค่าตัวระบุไฟล์ของเน็ตเวิร์ก

NPU_IOCTL_WRITE_TEST_CFG และ NPU_IOCTL_READ_NPU_ERR เป็นค่าพารามิเตอร์การทดสอบ NPU ที่ส่งผ่าน 
test_cfg_wr_req_t และทั้งสองใช้สำหรับอ่านค่าผลลัพธ์การทดสอบ

### 2.3.2 อินเทอร์เฟซ IOCTL สำหรับไฟล์ดีสคริปเตอร์ของเครือข่าย

ไฟล์ดีสคริปเตอร์ของเครือข่ายสามารถสร้างได้โดยการส่งคำสั่ง
NPU_IOCTL_LOAD_NETWORK ไปยังไฟล์ดีสคริปเตอร์ของ NPU และรองรับ
การดำเนินการ เช่น poll และ close คำสั่ง IOCTL ที่ใช้ได้มี
ดังต่อไปนี้

<br/>

|         คำสั่ง            |         อาร์กิวเมนต์         |         คำอธิบาย      |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req*     | รันการอนุมาน            |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req* | โปรไฟล์รอบการอนุมาน |
| NPU_NET_IOCTL_SET_COLOR_FMT | int                      | ตั้งค่ารูปแบบสีอินพุต   |

<br/>

เมื่อดำเนินการ NPU_NET_IOCTL_RUN ไดรเวอร์ NPU จะส่งคำสั่งเพื่อรัน
เครือข่ายไปยัง NPU HW และสามารถตรวจสอบจุดที่การอนุมานสิ้นสุดได้
โดยการเรียก poll

### 2.3.3 อินเทอร์เฟซ IOCTL สำหรับไฟล์ดีสคริปเตอร์ของบัฟเฟอร์

ไฟล์ดีสคริปเตอร์ของบัฟเฟอร์: 
- สามารถสร้างได้โดยการส่งคำสั่ง NPU_IOCTL_ALLOC_BUFFER ไปยังไฟล์ดีสคริปเตอร์ของ NPU 
- รองรับการดำเนินการ เช่น mmap, close และอื่น ๆ 
- ไม่รองรับคำสั่ง IOCTL 
- รับบัฟเฟอร์ CMA จากโหมดผู้ใช้ผ่านการดำเนินการ mmap
- ปล่อยบัฟเฟอร์ CMA ผ่านการดำเนินการ close
