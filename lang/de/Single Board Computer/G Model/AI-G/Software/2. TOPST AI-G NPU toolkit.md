Neural 
Processing Unit (NPU) ist ein HW-Beschleuniger für neuronale Netze, und die NPU im TCC750x ist für die Inferenz neuronaler Netze für Vision-Anwendungen wie Objekterkennung, Bildklassifizierung und Gesichtserkennung optimiert.

# 3. Build-Anleitung

In diesem Kapitel wird der Prozess des Konvertierens und Erstellens von Modellen neuronaler Netze für die Ausführung auf der AI-G NPU beschrieben. Er beginnt mit der Verwendung des Converter-Werkzeugs, das Standardmodelle in ein mit der NPU kompatibles Format umwandelt.

## 3.1 Converter
---
Der Converter liest eine Datei mit einem neuronalen Netz und konvertiert sie in eine ”bin”-
Datei, die das im AI-G NPU SW Toolkit verwendete Netzwerkdateiformat ist.
Er führt außerdem Netzwerk-Inferenzen durch und sammelt Statistiken der
Aktivierungsdaten, die später für die Netzwerkquantisierung verwendet werden.

<strong>1.  Darknet</strong>
```
$ python ./EnlightSDK/converter.py \
  ./input_networks/yolov4.cfg \
  --weight ./input_networks/yolov4.weights \
  --type obj \
  --dataset Custom \
  --dataset-root my_dataset_path \
  --output ./output_networks/yolov4.enlight \
  --enable-track \
  --mean 0 0 0 \
  --std 1 1 1 \
  --num-class 90
```

<strong>3.  ONNX</strong>

Diese Methode ist erforderlich, wenn Ihr ONNX-Modell nicht unterstützte Operatoren (z. B. NonMaxSuppression) enthält.

Der folgende Prozess umfasst eine dreistufige Transformation über die Befehlszeilenschnittstelle von tc-nn-toolkit.


Zunächst konvertieren wir das ONNX-Modell in das Format .enlight.

```
$ python ./EnlightSDK/converter.py \
  ./input_networks/mb2-ssd-lite.onnx \
  --type obj \
  --add-detection-post-process ./input_networks/mb2-ssd-lite.anchor \
  --logistic softmax \
  --dataset Custom \
  --dataset-root my_dataset_path \
  --output ./output_networks/mb2-ssd-lite.enlight \
  --enable-track \
  --mean 0.498 0.498 0.498 \
  --std 0.502 0.502 0.502 \
  --num-class 20 \
  --variance 0.1 0.2
```

Anschließend extrahieren wir das Modell mit den Zwischenschichten als Ausgabe mithilfe von --force-output, um die nicht unterstützten Operatoren zu entfernen.

```
python ./EnlightSDK/converter.py \
            ./input_networks/mb2-ssd-lite.onnx \
            --type unknown \
            --output ./output_networks/mb2-ssd-lite_wo_box_decode_score.enlight \
            --dataset-root my_dataset_path \
            --force-output Concat_0___Concat Concat_1___Concat_1
```

Wenden Sie abschließend Nachbearbeitungsoptionen wie Anchor-Boxen, logistische Aktivierung und Klasseneinstellungen auf das extrahierte Modell an, um das endgültige .enlight-Modell zu erzeugen.

```
$ python ./EnlightSDK/converter.py \
  ./output_networks/mb2-ssd-lite_wo_box_decode_score.enlight \
  --type obj \
  --add-detection-post-process ./input_networks/mb2-ssd-lite.anchor \
  --logistic softmax \
  --dataset Custom \
  --dataset-root my_dataset_path \
  --output ./output_networks/mb2-ssd-lite.enlight \
  --enable-track \
  --mean 0.498 0.498 0.498 \
  --std 0.502 0.502 0.502 \
  --num-class 20 \
  --variance 0.1 0.2
```

Die erzeugten Dateien werden unter “output_code/\<network_name\>” gespeichert
verzeichnis aufgeführt.

Compiler-Ausgabedatei:
- npu_cmd.bin: Inferenzcode für den Telechips NPU-Inferenzcode
- quantized_network.bin: Gewichts- und Bias-Parameter des Netzes
- network.h: Puffergrößen und Netzwerkparameter für die Nachbearbeitung
- post_process.c: Code für die Nachbearbeitung
- Weitere Dateien: Debugging-Informationen (nur intern)

In der Anwendung für neuronale Netze werden “npu_cmd.bin” und “quantized_network.bin”
mithilfe der Telechips NPU-APIs und des Linux-Geräte-
treibers in DMA-Puffer geladen. “network.h” und “post_process.c” werden als Netzwerkobjekt-
datei (.so) erstellt, wie unter Netzwerkobjekt-Build beschrieben.

## 3.4 Netzwerkobjekt-Build
---
In diesem Kapitel wird beschrieben, wie Sie mithilfe einer kompilierten
Datei eines neuronalen Netzes eine Netzwerkobjektdatei erstellen. Das Verzeichnis “build_network” enthält
die Kompilierungsumgebung zum Erstellen der Shared-Library-Datei (.so) eines Netz-
modells, das in AI-G verwendet wird.
<br/><br/>

### 3.4.1 Toolchain installieren(gcc-arm-9.2)
```
$ wget https://developer.arm.com/-/media/Files/downloads/gnu-a/9.2-2019.12/binrel/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu.tar.xz
$ tar -xvf gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu.tar.xz
$ echo "export PATH=~/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu/bin:\$PATH" >> ~/.bashrc
$ source ~/.bashrc
$ aarch64-none-linux-gnu-gcc --version

Copyright (C) 2019 Free Software Foundation, Inc.

```

### 3.4.2 Objekt erstellen
Kopieren Sie das Ausgabeverzeichnis des Compilers in das Verzeichnis “build_network”.  
Bevor Sie den Befehl make ausführen, müssen Sie die vorhandenen Dateien post_process.c und network.h im Ordner build_network löschen.  
Erstellen Sie anschließend symbolische Links auf die Dateien network.h und post_process.c aus dem kompilierten Verzeichnis <network_name>_quantized im Ordner build_network.

```
$ cd build_network
$ cp ../output_code/<network_name>_quantized/ ./ -ar
$ rm -rf network.h post_process.c
$ ln -s ./<network_name>_quantized/network.h
$ ln -s ./<network_name>_quantized/post_process.c
$ make
$ cp ./net.so ./<network_name>_quantized/
$ ls -l <network_name>_quantized/
compile_debug.log
net.so
network.h
network_buf.txt
network_group_info.csv
      ㆍ
      ㆍ
      ㆍ
```

## 5.1 Von der AI-G NPU unterstützte Layer-Typen
---
Die AI-G NPU unterstützt die folgenden Layer-Typen.

**Tabelle 5.1 Unterstützte Layer-Typen und Spezifikationen:**

|        Layer-Typ        |                        Spezifikation                        |
|-------------------------|-------------------------------------------------------------|
| Convolution             | Kernelgröße: 1x1 bis 7x7<br/>Stride: 1 bis 4<br/>Padding: 0 bis 3 <br/>Dilation: 1 bis 4 |
| ConvTranspose           | Kernelgröße: 2x2 bis 3x3<br/>Stride: 2<br/>Padding: 0 bis 1  |
| Depth-wise Convolution  | Kernelgröße: 1x1 bis 5x5<br/>Stride: 1 bis 2<br/>Padding: 0 bis 2|
| Aktivierungsfunktion    | Bypass<br/>ReLU<br/>ReLU6<br/>Leaky Relu <br/> Sigmoid <br/> Tanh <br/> Mish <br/> Swish <br/> Clip <br/> HardSwish <br/> HardSigmoid| 
| Max Pool 2D             | Kernelgröße: 2x2 bis 13x13<br/>Stride: 1 bis 2<br/>Padding: 0 bis 6| 
| Average Pool 2D         | Kernelgröße: 2x2 bis 19x19<br/>Stride: 1 bis 2<br/>Padding: 0 bis 6| 
| Global Average Pool     | Unterstützt                                                 | 
| Element-wise Operation  | Addition: Skalar + Tensor, Vektor + Tensor, Tensor + Tensor <br/>  Multiplikation: Skalar * Tensor, Vektor * Tensor, Tensor * Tensor                    |  
| Batch Normalization     | Unterstützt                                                 |  
| Concatenation           | Nur kanalweise                                              | 
| Slice                   | Unterstützt                                                 |
| Split                   | Unterstützt                                                 |
