# 1. Einführung
---
Die Neural Processing Unit (NPU) ist ein HW-Beschleuniger für neuronale Netze, und die NPU im AI-G ist für die Inferenz von 
neuronalen Netzen für Vision-Anwendungen wie Objekterkennung, Bildklassifizierung und Gesichtserkennung optimiert. Der NPU-Gerätetreiber 
stellt Schnittstellen zur Steuerung der NPU bereit, damit Anwendungen für neuronale Netze im User Space die AI-G NPU für die Inferenz neuronaler 
Netze in eingebetteten Linux-Umgebungen nutzen können.

In dieser Dokumentation wird beschrieben, wie der NPU-Gerätetreiber und die im AI-G SDK enthaltenen NPU-APIs verwendet werden.
<br/><br/><br/><br/>


# 2. NPU-Linux-Gerätetreiber
---
Der NPU-Gerätetreiber steuert:

- die Initialisierung der NPU-HW
- die Übertragung kompilierter neuronaler Netze an die NPU-HW
- die Ausführung der NPU-HW
- das Auslesen der Verarbeitungsergebnisse (Inferenzergebnisse) der NPU-HW.

Puffer (code, weight, work, input und output), die vom NPU-Gerätetreiber verwendet werden, benötigen zusammenhängenden physischen Speicher. Aus diesem 
Grund wird der Puffer im Speicher intern mithilfe eines Continuous Memory Allocator (CMA) zugewiesen.
Der NPU-Gerätetreiber erhält die Befehlsdatei und die Gewichts-/Bias-Datei des kompilierten neuronalen Netzes als Eingabe und erzeugt einen 
Netzwerk-Dateideskriptor (fd). Außerdem weist er die Eingaben des neuronalen Netzes sowie Puffer zu, in denen die Ergebnisse gespeichert werden, und erzeugt Puffer-fd für den Zugriff auf 
jeden Puffer. 

Um die Inferenz auszuführen,
1. führen Sie mmap auf dem Puffer-fd des Eingangspuffers aus, um eine Eingangspufferadresse zu erhalten, auf die aus dem User Space zugegriffen werden kann.
2. speichern Sie das Eingangsbild mithilfe der in Schritt 1 erhaltenen Eingangspufferadresse im Eingangspuffer.
3. übergeben Sie ein IOCTL namens NPU_NET_IOCTL_RUN an das Netzwerk-fd.

Wenn zwei oder mehr neuronale Netze ausgeführt werden, führt der NPU-Gerätetreiber das neuronale Netz mit einem Zeitmultiplex-Algorithmus aus. 
In diesem Fall werden die neuronalen Netze in der vom User Space angeforderten Reihenfolge ausgeführt, da die Ausführungsreihenfolge 
intern mithilfe des Befehls queue.f geplant wird.

## 2.2 Device Tree
---
Die folgenden Beispiele sind die Device Trees für die Verwendung des NPU-Gerätetreibers im AI-G.

```
# NPU device tree example

 npu0: npu@11000000 {
                compatible = "telechips,npu";
                reg = <0x0 0x11000000 0x0 0x400>;
                interrupts = <GIC_SPI 153 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_0_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_0_CCLK &fbus_npu FBUS_NPU_0_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };


npu1: @11000400 {
                compatible = "telechips,";
                reg = <0x0 0x11000400 0x0 0x400>;
                interrupts = <GIC_SPI 154 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_1_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_1_CCLK &fbus_npu FBUS_NPU_1_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };

```

<br/>

|   Eigenschaft    |              Beschreibung             |
|------------------|---------------------------------------|
| compatible       | Fest „telechips,npu“              |
| reg              | Basisadresse und Größe des NPU-Registers    |
| disable-ue-fail  | Fehlschlag durch UE-Fehler deaktivieren. <br>Wenn disable-ue-fail 0 ist, wird bei Erkennung eines UE-Fehlers ein Fehlschlag zurückgegeben. <br>ODER <br>Wenn disable-ue-fail 0x7 ist, wird der UE-Fehler ignoriert.                                      |
| disable-ce-fail  | Fehlschlag durch CE-Fehler deaktivieren. <br>Wenn disable-ce-fail 0 ist, wird bei Erkennung eines CE-Fehlers ein Fehlschlag zurückgegeben. <br>ODER <br>Wenn disable-ce-fail 0x7 ist, wird der CE-Fehler ignoriert.                                           |
| disable-wdt      |  Watchdog-Timer deaktivieren          |
| wdt-timeout-count| Watchdog-Timeout-Zähler               |
| wdt-rearm-count  | Watchdog-Rearm-Zähler<br>Dieser Wert muss kleiner als der Watchdog-Timeout-Zähler sein.   |
| reg-names        | Name des NPU-Registers                |
| work-buffer-size | Zuweisungsgröße des Arbeitspuffers    |
| interrupt-parent | Device-Tree-Knoten des Interrupt-Controllers |
| interrupts       | Interrupt-Nummer                      |

### 2.3.1 IOCTL-Befehle für den NPU-Dateideskriptor

Der NPU-Dateideskriptor kann durch Öffnen von NPU-Gerätedateien wie
/dev/npu0 und /dev/npu1 abgerufen werden. Die verfügbaren IOCTL-Befehle sind die folgenden.


|      Befehl            |        Argument         |      Beschreibung       |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req*  | CMA-Puffer zuweisen     |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req*   | Netzwerk laden          |
| NPU_IOCTL_READ_REG     | struct reg_access_req* | Wert aus Register lesen  |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req* | Wert in Register schreiben |
| NPU_IOCTL_RESET_NPU    | struct npu_init_req*   | NPU zurücksetzen        |
| NPU_IOCTL_WRITE_TEST_CFG| test_cfg_wr_req_t*    | ecc_test schreiben      |
| NPU_IOCTL_READ_NPU_ERR | npu_err_rd_req_t*      | ECC und WDT lesen       |

<br/>

Befehl NPU_IOCTL_ALLOC_BUFFER 
- weist den CMA-Puffer unter Verwendung des
Größenwerts zu, der über die Struktur buffer_alloc_req übergeben wird, und
- gibt den Puffer-Dateideskriptor zurück.

Befehl NPU_IOCTL_LOAD_NETWORK 
- weist einen CMA-Puffer zum Speichern der über die Struktur net_load_req übergebenen Parameter zu,
- kopiert die Parameter in den zugewiesenen CMA-Puffer und 
- gibt einen Netzwerk-Dateideskriptor zurück.

NPU_IOCTL_WRITE_TEST_CFG und NPU_IOCTL_READ_NPU_ERR sind NPU-Testparameterwerte, die über 
test_cfg_wr_req_t übertragen werden, und beide werden zum Lesen von Testergebniswerten verwendet.

### 2.3.2 IOCTL-Schnittstelle für den Netzwerk-Dateideskriptor

Der Netzwerk-Dateideskriptor kann erzeugt werden, indem der Befehl
NPU_IOCTL_LOAD_NETWORK an den NPU-Dateideskriptor übergeben wird. Er unterstützt
Operationen wie poll und close. Die verfügbaren IOCTL-Befehle sind die
folgenden.

<br/>

|         Befehl             |         Argument         |        Beschreibung      |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req*     | Inferenz ausführen       |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req* | Inferenzzyklen profilieren |
| NPU_NET_IOCTL_SET_COLOR_FMT | int                      | Eingangsfarbformat festlegen |

<br/>

Wenn NPU_NET_IOCTL_RUN ausgeführt wird, sendet der NPU-Treiber Befehle zum Ausführen
des Netzwerks an die NPU-HW, und der Zeitpunkt, zu dem die Inferenz endet, kann
durch Aufrufen von poll bestätigt werden.

### 2.3.3 IOCTL-Schnittstelle für den Puffer-Dateideskriptor

Puffer-Dateideskriptor: 
- kann durch Senden des Befehls NPU_IOCTL_ALLOC_BUFFER an den NPU-Dateideskriptor erzeugt werden. 
- unterstützt Operationen wie mmap, close und andere. 
- unterstützt keine IOCTL-Befehle 
- ruft über die Operation mmap einen CMA-Puffer aus dem User Mode ab
- gibt den CMA-Puffer über die Operation close frei.
