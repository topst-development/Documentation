# 2. Videoausgabe
---
Der AI-G unterstützt die Videoausgabe über eine MIPI DSI-2-Schnittstelle.
Er bietet eine 2-Lane-DSI-Verbindung über einen 15-poligen FFC-Anschluss, die sich für den Anschluss kompatibler MIPI DSI LCD-Panels eignet. Diese Schnittstelle ermöglicht die flüssige Darstellung grafischer Benutzeroberflächen, die Videowiedergabe und die Echtzeit-Visualisierung von KI-Ergebnissen auf eingebetteten Displays.
<br/><br/><br/>

## 2.1 MIPI DSI
---
DSI steht für Display Serial Interface, einen von der MIPI Alliance definierten Standard zur Übertragung von Anzeigedaten vom Prozessor an einen externen Bildschirm. Er ermöglicht eine schnelle und energiesparende Kommunikation, die sich für eingebettete LCD-Panels eignet.  
Wie oben erwähnt, bietet der AI-G eine 2-Lane-DSI-Verbindung über einen 15-poligen FFC-Anschluss, die den Anschluss kompatibler MIPI DSI-Displaymodule für die GUI-Darstellung, die Videowiedergabe oder die Echtzeit-Visualisierung von Inferenzergebnissen ermöglicht.
<br/><br/>

### 2.1.1 5-Zoll-DSI-Display
Das Elecrow 5-Zoll-DSI-Display ist ein LCD mit einer Auflösung von 800×480, einem IPS-Panel und Unterstützung für kapazitive Touch-Eingabe, das für die Verwendung mit der MIPI DSI-Schnittstelle des Raspberry Pi entwickelt wurde. Dank seiner Plug-and-Play-Funktionalität ist keine zusätzliche Treiberinstallation erforderlich. Das Display wird über den 15-poligen MIPI DSI-Anschluss mit dem AI-G-Board verbunden und direkt über die Schnittstelle mit Strom versorgt, sodass keine externe Stromversorgung erforderlich ist.  
Dieses Modul eignet sich für GUI-basierte Anwendungen, die Echtzeitüberwachung und interaktive KI-Demos auf der AI-G-Plattform.

Die technischen Daten des DSI-Displays sind wie folgt:

| Spezifikation                | Beschreibung                               |
| ------------------- | -------------------------------------------|
| Displaygröße        | 5 Zoll                                     |
| Auflösung           | 800 x 480                                  |
| Bildwiederholrate   | 60 Hz                                      |
| Schnittstelle (Display) | MIPI DSI                               |
| Schnittstelle (Panel)   | RGB888 Port                            |
| Betriebsspannung    | 3.3V                                      |
| Betriebstemperaturbereich| -20 °C bis 70 °C                       |
| Kabeltyp            | Flat Flexible Cable (FFC) (15-polig)                            |

# 3. Kameraanschluss
---
Der AI-G unterstützt die Kameraeingabe über eine MIPI CSI-2-Schnittstelle.
Standardmäßig bietet er eine 2-Lane-CSI-Verbindung über einen 15-poligen Anschluss. Für Anwendungen mit höherem Bandbreitenbedarf, wie zum Beispiel KI-Vision-Aufgaben mit hoher Auflösung oder hoher Bildrate, wird über einen optionalen 20-poligen Anschluss auch eine 4-Lane-Konfiguration unterstützt.
<br/><br/><br/>

## 3.1 MIPI CSI
---
CSI steht für Camera Serial Interface, eine von der MIPI Alliance definierte Standardschnittstelle zum Anschluss von Kameramodulen an Host-Prozessoren. Sie ermöglicht eine schnelle und energiesparende Übertragung von Bilddaten von der Kamera zum Prozessor.  
Wie oben erläutert, bietet der AI-G standardmäßig eine 2-Lane-CSI-Verbindung, mit optionaler Unterstützung einer 4-Lane-Konfiguration über einen 20-poligen Anschluss für einen höheren Datendurchsatz.  

Derzeit unterstützt der AI-G nur die Module ArduCam (5 MP) und Raspberry Pi v1 Camera (5 MP).
<br/><br/>

### 3.1.1 ArduCam
ArduCam ist ein vielseitiges Kameramodul für eingebettete Systeme und KI-Anwendungen. Es unterstützt verschiedene Bildsensoren und Schnittstellen, darunter MIPI CSI, und eignet sich daher für die Integration mit Entwicklungsboards wie dem AI-G.  
Der AI-G unterstützt ArduCam-Module mit 2-Lane- oder 4-Lane-MIPI CSI-Schnittstellen und ermöglicht so eine stabile Bildeingabe für KI-Vision-Aufgaben wie Objekterkennung und Bildklassifizierung. Dank der Kompatibilität mit FFC-Kabeln lässt sich das ArduCam-Modul einfach an den CSI-Anschluss des AI-G-Boards anschließen und bietet damit eine zuverlässige Lösung für die Echtzeit-Kameraeingabe in Edge-KI-Systemen.

Die technischen Daten des ArduCam-Moduls sind wie folgt:

| Spezifikation                     | Beschreibung                                |
| ------------------------ | ------------------------------------------- |
| Sensor                   | OV5647 (5 Megapixel)                        |
| Auflösung                | 2592 × 1944 (volle 5MP)                     |
| Unterstützte Ausgabeformate | RAW, YUV, JPEG (sensorabhängig)          |
| Schnittstelle            | MIPI CSI                                    |
| Bildrate                 | Bis zu 30fps bei 1080p, 60fps bei 720p      |
| Objektivfassung          | Objektiv mit Fixfokus (Standard)            |

| Betriebsspannung         | 3.3V (typisch)                              |
| Formfaktor               | Kompakte Platine, ungefähr 25 mm x 24 mm                   |
| Kompatibilität           | Raspberry Pi und AI-G (über MIPI CSI-Anschluss)    |
| Zusätzliche Merkmale     | Geringer Stromverbrauch, Plug-and-Play-Modul |

- o — Eine neue leere DOS-Partitionstabelle erstellen (optional, löscht die vorhandene Tabelle)

- Enter drücken — Den Standardwert für den letzten Sektor übernehmen (nutzt die gesamte Festplatte)

# 5. Ethernet-Verbindung
---
Der AI-G unterstützt Ethernet-Konnektivität über seinen integrierten RJ45-Ethernet-Anschluss. Dadurch kann das Board über standardmäßige TCP/IP-Protokolle mit lokalen Netzwerken oder dem Internet kommunizieren. Ethernet wird häufig für die Bereitstellung von KI-Anwendungen verwendet, die Fernzugriff, Daten-Streaming oder Software-Updates erfordern.
<br/><br/><br/>

## 5.1 Netzwerkverbindung über einen Router
---
Bei dieser Methode wird der AI-G über einen handelsüblichen Router mit einem lokalen Netzwerk verbunden. Das Board kann eine IP-Adresse automatisch über DHCP beziehen oder mit einer statischen IP-Adresse konfiguriert werden.
<br/><br/>

### 5.1.1 Das Root-Dateisystem mit Lese-/Schreibzugriff neu einhängen
Das Root-Dateisystem ist schreibgeschützt eingehängt. Hängen Sie es mit dem folgenden Befehl mit Schreibrechten neu ein, um das Bearbeiten von Konfigurationsdateien zu ermöglichen:

```
$ mount -o remount,rw /
```
<br/><br/>


### 5.1.2 Netzwerkkonfigurationsdatei erstellen
1. Dynamische IP über DHCP
Erstellen oder bearbeiten Sie die Datei /etc/systemd/network/20-wired.network mit dem folgenden Inhalt, um DHCP für die Schnittstelle eth0 zu aktivieren.

```
$ vi /etc/systemd/network/20-wired.network
 
[Match]
Name=eth0
 
[Network]
DHCP=yes
```

Diese Konfiguration weist systemd-networkd an, für die Schnittstelle eth0 automatisch eine IP-Adresse über DHCP zu beziehen.

2. Konfiguration einer statischen IP
Wenn Sie eine statische IP-Adresse vergeben möchten (zum Beispiel bei einer direkten PC-Verbindung oder wenn kein DHCP-Server verfügbar ist), bearbeiten Sie dieselbe Datei mit dem folgenden Inhalt:
```
$ vi /etc/systemd/network/20-wired.network

[Match]
Name=eth0

[Network]
Address=192.168.137.2/24
Gateway=192.168.137.1
DNS=8.8.8.8
```

Damit wird die IP-Adresse auf 192.168.137.2 gesetzt, 192.168.137.1 als Gateway verwendet (üblich bei Windows ICS) und der Google DNS konfiguriert.
<br/><br/>


### 5.1.3 Netzwerkdienst neu starten
Übernehmen Sie die neue Netzwerkkonfiguration, indem Sie den Dienst systemd-networkd neu starten:

```
sudo systemctl restart systemd-networkd
```
<br/><br/>

# 6. 40-Pin-GPIO-Header
---
Der AI-G verfügt über einen 40-Pin-GPIO-Header, der flexible I/O-Möglichkeiten für verschiedene Hardware-Projekte bietet.
Dieser Header ist mit General-Purpose-Input/Output-Operationen (GPIO) kompatibel und kann zum Anschluss von Sensoren, LEDs, Tastern und anderen Peripheriegeräten verwendet werden.

Jeder Pin unterstützt je nach Konfiguration digitale I/O-, I2C-, SPI- oder UART-Funktionalität.

<p align="center"><img src="https://raw.githubusercontent.com/topst-development/Documentation/refs/heads/main/Assets/TOPST%20AI-G/Available%20Applications/3.1%2040%20Pin%20GPIO%20Header%20Pinmap%20of%20AI-G.png" width="600"></p>
<p align="center"><strong>Abbildung 6.1 Pinbelegung des 40-Pin-GPIO-Headers des AI-G  </strong></p><br/>

**Hinweis**: Weitere Informationen zu den Pin-Funktionen und Spannungspegeln finden Sie im offiziellen Pinout-Diagramm, bevor Sie externe Hardware anschließen.
<br/><br/><br/><br/>

## 6.1 GPIO Digitaler Ein-/Ausgang
---
Das AI-G-Board unterstützt digitale Ein- und Ausgabe (GPIO) über seinen 40-Pin-Header, sodass Benutzer mit externen Geräten wie Tastern, LEDs und Sensoren interagieren können. 
<br/><br/><br/>

### 6.1.1 LED
---
Eines der einfachsten und häufigsten Beispiele für einen GPIO-Ausgang ist die Ansteuerung einer LED.

```bash
#!/bin/bash

GPIO=72
INTERVAL=1

# GPIO export
if [ ! -e /sys/class/gpio/gpio$GPIO ]; then
    echo "$GPIO" > /sys/class/gpio/export
    sleep 0.1
fi

echo "out" > /sys/class/gpio/gpio$GPIO/direction

trap "echo $GPIO > /sys/class/gpio/unexport; echo -e '\nGPIO$GPIO unexported. Exit.'; exit" SIGINT

echo "Toggling GPIO$GPIO every $INTERVAL second(s). Press Ctrl+C to stop."

while true; do
    echo 1 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
    echo 0 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
done
```

Führen Sie den Code mit dem folgenden Befehl aus.
```
$ ./AI_GPIO_LED_TEST
```

Dieses Skript konfiguriert GPIO72 als digitalen Ausgang und wechselt dessen Zustand fortlaufend jede Sekunde. Bei der Ausführung blinkt die an GPIO72 angeschlossene LED wiederholt, leuchtet 1 Sekunde lang und ist dann 1 Sekunde lang aus, in einer Endlosschleife.

Um das Skript zu beenden, drücken Sie **[Ctrl+C]**.  
Beim Beenden des Skripts wird GPIO72 automatisch mit unexport freigegeben und bereinigt.

```bash
$ chmod +x AI_GPIO_LED_TEST
```

**Hinweis**: Dieser Aufbau enthält keinen strombegrenzenden Widerstand. Für kurzzeitige Tests mag dies funktionieren, es wird jedoch empfohlen, einen Widerstand in Reihe zur LED zu verwenden, um mögliche Schäden am GPIO-Pin zu vermeiden.

Inter-integrated Circuit (I2C) ist ein Zweidraht-Kommunikationsprotokoll, das aus einer Datenleitung (SDA) und einer Taktleitung (SCL) besteht und es mehreren Geräten ermöglicht, über einen gemeinsam genutzten Bus zu kommunizieren.

Die I2C-Kommunikation folgt einer Master-Slave-Architektur, bei der ein Master-Gerät die Kommunikation steuert und bis zu 127 Slave-Geräte an denselben Bus angeschlossen werden können. Die SDA-Leitung wird sowohl zum Senden als auch zum Empfangen von Daten verwendet, während die SCL-Leitung das Timing der Datenübertragung synchronisiert. Dieses synchrone Kommunikationsmodell ermöglicht es Geräten, Informationen koordiniert und taktgesteuert auszutauschen.
<br/><br/><br/>

#### Schritt 3. Ausführung
Um auf I2C-Geräte des AI-G-Boards zuzugreifen, müssen Sie ein C-Programm schreiben, das die i2c-dev-Schnittstelle verwendet, und es für die Zielarchitektur cross-kompilieren.  
Nachfolgend finden Sie ein einfaches Beispiel (I2C_TEST.c):

```
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <linux/i2c-dev.h>
#include <sys/ioctl.h>
#include <unistd.h>

#define I2C_DEV "/dev/i2c-1"
#define I2C_ADDR 0x27

// RS: 0 = command, 1 = data
void lcd_send_byte(int fd, unsigned char data, unsigned char mode) {
    unsigned char high = mode | (data & 0xF0) | 0x08; // backlight on
    unsigned char low  = mode | ((data << 4) & 0xF0) | 0x08;
    unsigned char buf[4] = { high | 0x04, high, low | 0x04, low }; // toggle EN bit

    for (int i = 0; i < 4; i++) {
        if (write(fd, &buf[i], 1) != 1) {
            perror("I2C write error");
        }
        usleep(1000); // 1ms delay
    }
}

void lcd_command(int fd, unsigned char cmd) {
    lcd_send_byte(fd, cmd, 0x00);
}

void lcd_data(int fd, unsigned char data) {
    lcd_send_byte(fd, data, 0x01);
}

void lcd_init(int fd) {
    usleep(50000); // wait for LCD power on
    lcd_command(fd, 0x33); // init
    lcd_command(fd, 0x32); // 4-bit mode
    lcd_command(fd, 0x28); // 2 line, 5x8 font
    lcd_command(fd, 0x0C); // display on, cursor off
    lcd_command(fd, 0x06); // entry mode
    lcd_command(fd, 0x01); // clear display
    usleep(2000);
}

void lcd_print(int fd, const char* str) {
    while (*str) {
        lcd_data(fd, *str++);
    }
}

int main() {
    int fd = open(I2C_DEV, O_RDWR);
    if (fd < 0) {
        perror("Failed to open I2C device");
        return 1;
    }

    if (ioctl(fd, I2C_SLAVE, I2C_ADDR) < 0) {
        perror("Failed to set I2C address");
        close(fd);
        return 1;
    }

    lcd_init(fd);
    lcd_print(fd, "test pass!");

    close(fd);
    return 0;
}
```

## 6.3 SPI
---
Der AI-G unterstützt die Kommunikation über Serial Peripheral Interface (SPI) mittels eines 40-poligen GPIO-Headers und ermöglicht so den Datenaustausch zwischen externen Geräten und dem Board.  

SPI ist ein synchrones serielles Kommunikationsprotokoll, das Vollduplex-Kommunikation ermöglicht, das heißt, Daten können gleichzeitig gesendet und empfangen werden. Es verwendet vier Hauptleitungen: Master Out Slave In (MOSI), Master In Slave Out (MISO), Serial Clock (SCLK) und Slave Select (SS).

Anders als I2C, das gemeinsam genutzte Leitungen für mehrere Geräte verwendet, benötigt SPI für jedes Slave-Gerät eine eigene SS-Leitung. Diese Eins-zu-viele-Struktur macht SPI schnell und einfach zu implementieren, kann aber bei mehreren beteiligten Geräten mehr physische Verkabelung erfordern.
<br/><br/><br/>

```
#include <stdio.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>
#include <linux/spi/spidev.h>
#include <sys/ioctl.h>
#include <string.h>

#define SPI_DEV "/dev/spidev3.0"

int spi_fd = -1;

void spi_send(uint8_t address, uint8_t data) {
    uint8_t tx[2] = { address, data };
    struct spi_ioc_transfer tr = {
        .tx_buf = (uintptr_t)tx,
        .rx_buf = 0,
        .len = 2,
        .delay_usecs = 0,
        .speed_hz = 1000000,
        .bits_per_word = 8,
    };

    if (ioctl(spi_fd, SPI_IOC_MESSAGE(1), &tr) < 1) {
        perror("SPI send failed");
    }
}

void max7219_init() {
    spi_send(0x09, 0x00); // Decode mode off
    spi_send(0x0A, 0x08); // Brightness (0x00 ~ 0x0F)
    spi_send(0x0B, 0x07); // Scan limit: display all 8 digits
    spi_send(0x0C, 0x01); // Shutdown register: normal operation
    spi_send(0x0F, 0x00); // Display test: off
}

void max7219_clear() {
    for (int i = 1; i <= 8; i++) {
        spi_send(i, 0x00);
    }
}


const uint8_t letter_P[8] = {
    0b00000000,  
    0b01111110, 
    0b01000010,  
    0b01000010,  
    0b01111110,  
    0b01000000,  
    0b01000000,  
    0b01000000   
};


void draw_letter_P() {
    for (int row = 0; row < 8; row++) {
        spi_send(row + 1, letter_P[row]);
    }
}

int main() {
    spi_fd = open(SPI_DEV, O_RDWR);
    if (spi_fd < 0) {
        perror("Failed to open SPI device");
        return 1;
    }

    max7219_init();
    max7219_clear();
    draw_letter_P();

    close(spi_fd);
    return 0;
}
```

## 6.4 UART
---
Der AI-G unterstützt die Kommunikation über Universal Asynchronous Receiver/Transmitter (UART) mittels seines 40-poligen GPIO-Headers und ermöglicht so die serielle Kommunikation mit Geräten wie seriellen Konsolen und anderen Mikrocontrollern.  

UART ist ein weit verbreitetes asynchrones Kommunikationsprotokoll, das Daten bitweise über zwei Leitungen überträgt: TX (Senden) und RX (Empfangen). Anders als I2C oder SPI verwendet UART keine Taktleitung. Stattdessen müssen die beiden Geräte für das Timing eine gemeinsame Übertragungsgeschwindigkeit verwenden.
<br/><br/><br/>

### 6.4.1 UART-Loopback-Test
---
Der UART-Loopback-Test ist eine einfache Möglichkeit, um zu überprüfen, ob die UART-Kommunikation auf dem AI-G korrekt funktioniert.

Dieser Test kann über das Linux-Terminal durchgeführt werden, indem Daten auf das UART-Gerät geschrieben und wieder gelesen werden.

#### Schritt 3. Ausführung
Dieses Skript sendet eine Testmeldung an den UART-Port und prüft, ob dieselbe Meldung wieder empfangen wird.  
Um den UART-Loopback auf dem AI-G zu testen, führen Sie das folgende Skript aus, nachdem Sie die TX- und RX-Pins miteinander verbunden haben.

```bash
#!/bin/bash
# ===================== user setting =====================
UART_DEV="/dev/ttyAMA1"       # uart
BAUD=115200                   # Baudrate
TEST_MSG="Hello from UART"    # msg
TEMP_FILE="/tmp/uart_rx.txt"  # file
# =====================================================

if [ ! -e "$UART_DEV" ]; then
    echo "Error: $UART_DEV does not exist"
    exit 1
fi

chmod 666 $UART_DEV

stty -F $UART_DEV $BAUD cs8 -cstopb -parenb -icanon -echo -ixon -ixoff
echo "UART setup complete: port=$UART_DEV, speed=$BAUD"

cat $UART_DEV > $TEMP_FILE &
RX_PID=$!

sleep 0.2
echo -n "$TEST_MSG" > $UART_DEV
echo "Transmission complete: \"$TEST_MSG\""

sleep 1
kill $RX_PID 2>/dev/null

if [ -f "$TEMP_FILE" ]; then
    RECEIVED=$(cat $TEMP_FILE)
    rm $TEMP_FILE
    if [ "$RECEIVED" = "$TEST_MSG" ]; then
        echo "Loopback Success! Received Message: \"$RECEIVED\""
    else
        echo "Received mismatch"
        echo "Sent: \"$TEST_MSG\""
        echo "Received: \"$RECEIVED\""
    fi
else
    echo "Failed to receive: No received file"
fi
```
