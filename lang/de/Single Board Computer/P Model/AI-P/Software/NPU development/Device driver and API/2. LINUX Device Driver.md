# 2. NPU-LINUX-GERÄTETREIBER

Die NPU des TOPST AI ist ein HW-Beschleuniger für neuronale Netze. Sie ist
für die Inferenz von neuronalen Netzen für Vision-Anwendungen wie
Objekterkennung, Bildklassifizierung und Gesichtserkennung optimiert. Die
Dokumentation „TOPST-AI-Common-SW-NPU-Toolkit Guide“ beschreibt, wie das
NPU Toolkit verwendet wird.

1.  Der NPU-Gerätetreiber steuert die Initialisierung der NPU-HW, die Übergabe kompilierter neuronaler Netze an die NPU-HW, die Ausführung der
    NPU-HW und das Auslesen der Verarbeitungsergebnisse (Inferenz) der NPU-HW.
2.  Die vom NPU-Gerät verwendeten Puffer (code, weight, work, input und
    output) benötigen zusammenhängenden physischen Speicherbereich.
    Zu diesem Zweck wird der Puffer im Speicher intern über einen
    Continuous Memory Allocator (CMA) zugewiesen.
3.  Der NPU-Gerätetreiber erhält die Befehlsdatei und die Weight-/Bias-Datei
    des kompilierten neuronalen Netzes als Eingabe, um einen Network File
    Descriptor (fd) zu erzeugen.
4.  Er ist außerdem für die Zuweisung der Eingaben des neuronalen Netzes und
    der Puffer, in denen die Ergebnisse gespeichert werden, sowie für die
    Erzeugung des Buffer-fd für den Zugriff auf jeden Puffer zuständig.
5.  Um die Inferenz auszuführen, führen Sie zuerst mmap auf dem Buffer-fd
    des Eingabepuffers aus, um eine Eingabepufferadresse zu erhalten, die
    aus dem User Space zugänglich ist, speichern Sie zweitens das Eingabebild
    in dem so erhaltenen Eingabepuffer und übergeben Sie schließlich ein **IOL
    namens NPU_NET_IOCT_RUNCT** an den Network-fd.
6.  Wenn zwei oder mehr neuronale Netze ausgeführt werden, führt der
    NPU-Gerätetreiber das neuronale Netz mit einem Zeitmultiplex-Algorithmus aus.
7.  In diesem Fall werden die neuronalen Netze in der vom User Space
    angeforderten Reihenfolge ausgeführt, da die Ausführungsreihenfolge
    intern über die Command Queue geplant wird.

## 2.2 Device Tree

Beim TOPST AI werden die Informationen zur Verwendung des NPU-Gerätetreibers
wie folgt über den Device Tree festgelegt.

```
# NPU device tree example

npu0: npu0 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000000 0x0 0x200>;
		interrupts = <GIC_SPI 146 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};

npu1: npu1 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000200 0x0 0x200>;
		interrupts = <GIC_SPI 147 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};
```

<br/>

|    Eigenschaft   |             Beschreibung              |
|------------------|---------------------------------------|
| compatible       | Fest „telechipss, npu“                 |
| reg              | NPU-Registerbasisadresse, Größe       |
| reg-names        | NPU-Registername                      |
| work-buffer-size | Zuweisungsgröße des Work-Puffers      |
| interrupt-parent | Device-Tree-Knoten des Interrupt-Controllers |
| interrupts       | Interrupt-Nummer                      |

### 2.3.1 IOCTL-Befehle

Der NPU File Descriptor kann durch Öffnen von NPU-Gerätedateien wie
/dev/npu0 und /dev/npu1 abgerufen werden. Die verfügbaren IOCTL-Befehle lauten wie folgt.

<br/>

|      Befehl            |        Argument         |       Beschreibung      |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req\*  | CMA-Puffer zuweisen     |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req\*   | Netz laden              |
| NPU_IOCTL_INIT_MLX     | struct mlx_init_req\*   | MLX initialisieren      |
| NPU_IOCTL_READ_REG     | struct reg_access_req\* | Registerwert lesen      |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req\* | Registerwert schreiben  |
| NPU_IOCTL_RESET_NPU    |                         | NPU zurücksetzen        |

<br/>

Der Befehl NPU_IOCTL_ALLOC_BUFFER weist den CMA-Puffer anhand des
Größenwerts zu, der über die Struktur buffer_alloc_req übergeben wird, und
gibt den Buffer File Descriptor zurück.
Der Befehl NPU_IOCTL_LOAD_NETWORK weist einen CMA-Puffer zu, um die über die
Struktur net_load_req übergebenen Parameter zu speichern, kopiert die
Parameter in den zugewiesenen CMA-Puffer und gibt einen Network File
Descriptor zurück.

### 2.3.2 IOCTL-Schnittstelle für den Network File Descriptor

Der Network File Descriptor kann erstellt werden, indem der Befehl
NPU_IOCTL_LOAD_NETWORK an den NPU File Descriptor übergeben wird. Er unterstützt
Operationen wie poll und close. Die verfügbaren IOCTL-Befehle lauten wie
folgt.

<br/>

|         Befehl             |         Argument         |        Beschreibung      |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req\*     | Inferenz ausführen       |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req\* | Inferenzzyklen profilen  |
| PU_NET_IOCTL_SET_COLOR_FMT | int                      | Eingabefarbformat setzen |

<br/>

Wenn NPU_NET_IOCTL_RUN ausgeführt wird, sendet der NPU-Treiber Befehle zum
Ausführen des Netzes an die NPU-HW, und der Zeitpunkt, an dem die Inferenz endet,
kann durch Aufruf von poll bestätigt werden.

### 2.3.3 IOCTL-Schnittstelle für den Buffer File Descriptor

Der Buffer File Descriptor kann erzeugt werden, indem der Befehl
NPU_IOCTL_ALLOC_BUFFER an den NPU File Descriptor übergeben wird.

Der Buffer File Descriptor unterstützt Operationen wie mmap, close und so weiter.

Der Buffer File Descriptor unterstützt keinen IOCTL-Befehl. Rufen Sie den CMA-Puffer
aus dem User Mode über mmap ab. Geben Sie den CMA-Puffer mit close frei.
