Abbildung 5.1 zeigt die Software-Komponenten im TCC8050 MCU BSP. Das TCC8050 MCU BSP besteht aus Gerätetreiber, Real Time Operating System (RTOS), System Adaptation Layer (SAL) und Beispielanwendung. Das MCU BSP wird nach Verwendungszweck in drei Typen unterteilt (Sample, 3rd party und TC Support). Das Sample ist ein Beispielcode zum Testen des Gerätetreibers. ### 5.4.1 UART-Unterstützung

Das TCC8050 MICOM-Subsystem verfügt über einen 5-Kanal-UART, und jeder UART-Kanal besteht aus einem ARM® PrimeCell™ UART-Controller (PL011) und einem ARM® PrimeCell™ DMA-Controller (PL081). Daten, die über die UART-Kommunikation gesendet/empfangen werden, können vom UART-eigenen DMA-Controller aus dem bzw. in den internen Speicher (SRAM-0 oder SRAM-1) übertragen werden.

### 5.4.1.1 Funktionen

<br/>

### 5.4.1.1.1 UART-Controller

Die Funktionen des UART-Controllers sind folgende:

- Verwendung von programmierbaren UART-Ein-/Ausgängen
- Separate Speicherpuffer nach dem First-In-First-Out-Prinzip (FIFO) mit 32×8 für das Senden und 32×12 für das Empfangen, um CPU-Interrupts zu reduzieren.
- Programmierbares Deaktivieren des FIFO für eine Tiefe von 1 Byte.
- Programmierbarer Baudratengenerator. Dieser ermöglicht die Teilung der Referenztaktfrequenz > 3.6864 MHz.
- Standardmäßige asynchrone Kommunikationsbits (Start, Stopp und Parität).
- Unabhängige Maskierung der Interrupts für Sende-FIFO, Empfangs-FIFO, Empfangs-Timeout, Modemstatus und Fehlerzustand.
- Unterstützung von Direct Memory Access (DMA).
- Erkennung falscher Startbits
- Erzeugung und Erkennung von Line-Break-Signalen.
- Programmierbare Hardware-Flusssteuerung: Modemsteuerungsfunktionen von CTS und RTS
- Vollständig programmierbare Eigenschaften der seriellen Schnittstelle:
- Daten können mit 5, 6, 7 oder 8 Bit programmiert werden
- Erzeugung und Erkennung von gerader, ungerader, fester oder keiner Parität
- Erzeugung von 1 oder 2 Stoppbits
- Baudratenerzeugung bis zu UARTCLK/16
- Identifikationsregister, die den UART eindeutig identifizieren. Diese können von einem Betriebssystem verwendet werden, um sich selbst automatisch zu konfigurieren.

<br/>

### 5.4.1.1.2 UART-DMA-Controller

Die Funktionen des UART-DMA-Controllers sind folgende:

- Übertragungen von Speicher zu Speicher, von Speicher zu UART und von UART zu Speicher
- Der DMA-Controller verfügt über zwei Kanäle.
- Unterstützung von Scatter- oder Gather-DMA durch die Verwendung verketteter Listen. Das bedeutet, dass Quell- und Zielbereiche keine zusammenhängenden Speicherbereiche belegen müssen.
- Ein AHB-Bus-Master für die Datenübertragung. Diese Schnittstelle überträgt Daten, wenn eine DMA-Anforderung a
- 32-Bit-AHB-Master-Busbreite.
- Inkrementierende oder nicht inkrementierende Adressierung für Quelle und Ziel.
- Programmierbare DMA-Burst-Größe. Die DMA-Burst-Größe kann so programmiert werden, dass Daten effizienter übertragen werden. Üblicherweise wird die Burst-Größe auf die Hälfte der FIFO-Größe im Peripheriegerät eingestellt.
- Interner FIFO mit vier Wörtern pro Kanal.
- Unterstützung von Big-Endian und Little-Endian. Der DMA-Controller wechselt beim Reset standardmäßig in den Little-Endian-Modus.
- Kombinierte Interrupt-Anforderungen für DMA-Fehler und DMA-Zählerstand. Sie können bei einem DMA-Fehler oder wenn ein DMA-Zählerstand 0 erreicht hat einen Interrupt an den Prozessor auslösen. Dies wird üblicherweise verwendet, um anzuzeigen, dass eine Übertragung abgeschlossen ist. Drei Interrupt-Anforderungssignale übernehmen dies:
- INTTC signalisiert, wenn eine Übertragung abgeschlossen ist.
   * **Hinweis**: Das INTTC-Signal wird nicht in den Interrupt-Controller eingespeist, der Status kann jedoch über das Statusregister geprüft werden.
- INTERR signalisiert, wenn ein Fehler aufgetreten ist.
   * **Hinweis**: Das INTERR-Signal wird nicht in den Interrupt-Controller eingespeist, der Status kann jedoch über das Statusregister geprüft werden.
- INTR kombiniert die beiden Interrupt-Anforderungssignale INTTC und INTERR. Das INTR-Signal wird in den Interrupt-Controller eingespeist.
- Interrupt-Maskierung: Sie können die Interrupt-Anforderungen für DMA-Fehler und DMA-Endzählerstand maskieren.
- Roher Interrupt-Status: Sie können den rohen Interrupt-Status für DMA-Fehler und DMA-Zählerstand vor der Maskierung auslesen.

__attribute__ ((naked)) void DBG_SerialPrintf
(
    const int8 *                        format,
    ...
) 
{
    (void)format;
__asm volatile (
            "stmdb  sp!, {r1-r3}    \n"
            "mov    r1, r0          \n"     /* r1 = format string */
            "mov    r2, sp          \n"     /* r2 = arguments */

            "mov    pc, lr          \n"
            :::"r0", "r1", "r2", "r3" \
    );
}

### 5.4.2 CAN-Anwendung

Das Controller Area Network (CAN) führt die Kommunikation gemäß ISO 11898-1 durch (identisch mit der Bosch CAN Protokollspezifikation 2.0 Teil A, B). Darüber hinaus unterstützt CAN die Kommunikation gemäß der Spezifikation des CAN-Flexible-Data-rate-Protokolls (FD) 1.0.

Alle Funktionen zur Verarbeitung von Nachrichten werden vom Rx Handler und vom Tx Handler implementiert.

Der Rx Handler verwaltet die Akzeptanzfilterung von Nachrichten, die Übertragung empfangener Nachrichten vom CAN-Core in das Message RAM sowie die Bereitstellung von Statusinformationen zu empfangenen Nachrichten.

Der Tx Handler ist für die Übertragung von Sendenachrichten aus dem Message RAM an den CAN-Core sowie für die Bereitstellung von Sendestatusinformationen zuständig. Er implementiert alle Funktionen, die den Zeitplan und die globale Systemzeit betreffen.

Die Akzeptanzfilterung wird durch eine Kombination aus bis zu 128 Filterelementen umgesetzt, von denen jedes als Bereich, als Bitmaske oder als dedizierter ID-Filter konfiguriert werden kann.

Im TCC8050 MICOM-Subsystem sind insgesamt drei CAN-FD-Controller integriert. Die CPU kann jeden CAN-Controller über das AHB-zu-APB-Host-I/F konfigurieren. Jeder CAN-FD-Controller greift über die AHB-Bus-Matrix auf das im MICOM-Subsystem integrierte SRAM-0 oder SRAM-1 zu und verwendet SRAM-0 oder SRAM-1 als Nachrichtenspeicher.

### 5.4.2.1 Funktionen

Die Funktionen der CAN-Anwendung sind folgende:

- Konform mit CAN-Protokollversion 2.0 Teil A, B (ISO 11898-1), Bosch CAN FD Spezifikation V1.0, ISO 16845
- CAN FD mit bis zu 64 Datenbytes unterstützt
- CAN-Fehlererkennung und -protokollierung (Stuff/Bit/Format/CRC/ACK)
- Verbesserte Akzeptanzfilterung
- Zwei konfigurierbare Empfangs-FIFOs
- Separate Signalisierung beim Empfang von Nachrichten mit hoher Priorität
- Bis zu 64 dedizierte Empfangspuffer
- Bis zu 32 dedizierte Sendepuffer
- Konfigurierbarer Sende-FIFO
- Konfigurierbare Sende-Warteschlange
- Konfigurierbarer Transmit-Event-FIFO
- Programmierbarer Loopback-Testmodus
- Maskierbare Modul-Interrupts
- Zwei Taktdomänen (CAN-Takt und Bus-Takt)

CANErrorType_t CAN_DrvInitChannel
(
    CANController_t *                   psControllerInfo
)
{
    uint8               ucCh;
    uint32              uiMemSize;
    uint32              uiMemAddr;
    CANRegBaseAddr_t *  psConfigBaseRegAddr;
    CANErrorType_t      ret;

    uiMemAddr           = 0UL;
    ret                 = CAN_ERROR_NONE;

    if( ( psControllerInfo != NULL_PTR ) && ( psControllerInfo->cMode == CAN_MODE_NO_INITIALIZATION ) )
    {
        /* Set Config */
        ucCh = psControllerInfo->cChannelHandle;
        psControllerInfo->cRegister = ( CANControllerRegister_t * ) CAN_PortingGetControllerRegister( ucCh );

        /* Set HW_Init */
        ( void ) CAN_PortingInitHW( psControllerInfo );
        ( void ) CAN_PortingSetControllerClock( psControllerInfo, CAN_CONTROLLER_CLOCK );
        ( void ) CAN_PortingResetDriver( psControllerInfo );

        /* Set Memory */
        uiMemSize = CAN_DrvGetSizeOfRamMemory( psControllerInfo );

        if( 0UL < uiMemSize )
        {
            uiMemAddr = CAN_PortingAllocateNonCacheMemory( ucCh, uiMemSize );
        }

        if( uiMemAddr != 0UL )
        {
            psConfigBaseRegAddr = ( CANRegBaseAddr_t * ) CAN_PortingGetMessageRamBaseAddr( ucCh );

            if( psConfigBaseRegAddr != NULL_PTR )
            {
                psConfigBaseRegAddr->rFReg.rfBASE_ADDR = ( SALReg32 ) ( ( uint32 ) ( uiMemAddr >> ( uint32 ) 16UL ) & ( uint32 ) 0xFFFFUL );
            }

            ( void ) CAN_DrvRegisterParameterAll( psControllerInfo );

            ( void ) CAN_DrvStartConfigSetting( psControllerInfo );
            ( void ) CAN_DrvSetControlConfig( psControllerInfo );

            /* Set Buffer */
            ( void ) SAL_MemSet( ( void * ) uiMemAddr, 0, uiMemSize );
            ( void ) CAN_DrvInitBuffer( psControllerInfo, uiMemAddr, uiMemSize );
            ( void ) CAN_MsgInit( psControllerInfo );

            /* Set Filter */
            ( void ) CAN_DrvSetFilterConfig( psControllerInfo );

            /* Set Timing */
            ( void ) CAN_DrvInitTiming( psControllerInfo );

            /* Set Interrupt */
            ( void ) CAN_DrvSetInterruptConfig( psControllerInfo );

            /* Set TimeStamp */
            ( void ) CAN_DrvSetTimeStamp( psControllerInfo );

            /* Set TimeOut */
            ( void ) CAN_DrvSetTimeoutValue( psControllerInfo );

            /* Set WatchDog */
            ( void ) CAN_DrvSetWatchDog( psControllerInfo );

            ( void ) CAN_DrvFinishConfigSetting( psControllerInfo );

            psControllerInfo->cMode = CAN_MODE_OPERATION;
        }
        else
        {
            ret = CAN_ERROR_ALLOC;
        }
    }
    else
    {
        ret = CAN_ERROR_BAD_PARAM;
    }

    return ret;
}

CANErrorType_t CAN_PortingInitHW
(
    const CANController_t *             psControllerInfo
)
{
    CANErrorType_t ret;

    ret = CAN_ERROR_NONE;

    if( psControllerInfo != NULL_PTR )
    {
        switch( psControllerInfo->cChannelHandle )
        {
            case 0:
            {
                PMIO_SetGPK(CAN_0_FS); //Set to normal k-port

                ( void ) GPIO_Config( CAN_0_TX,    ( uint32 ) ( GPIO_FUNC( 2U ) | GPIO_OUTPUT ) ); //can0 tx
                ( void ) GPIO_Config( CAN_0_RX,    ( uint32 ) ( GPIO_FUNC( 2U ) | GPIO_INPUT ) ); //can0 rx
                ( void ) GPIO_Config( CAN_0_STB,   ( uint32 ) ( GPIO_FUNC( 0U ) | GPIO_OUTPUT ) ); //can0 stb
                ( void ) GPIO_Config( CAN_0_INH,   ( uint32 ) ( GPIO_FUNC( 0U ) | GPIO_INPUT ) ); //can0 INH

                ( void ) GPIO_Set( CAN_0_STB, 0UL ); //Set to Low

                break;
            }

            case 1:
            {
                PMIO_SetGPK(CAN_1_FS); //Set to normal k-port

                ( void ) GPIO_Config( CAN_1_TX,    ( uint32 ) ( GPIO_FUNC( 2U ) | GPIO_OUTPUT ) ); //can1 tx
                ( void ) GPIO_Config( CAN_1_RX,    ( uint32 ) ( GPIO_FUNC( 2U ) | GPIO_INPUT ) ); //can1 rx

                /* //CAN_1_STB is not used on EVB
                ( void ) GPIO_Config( CAN_1_STB,   ( uint32 ) ( GPIO_FUNC( 0U ) | GPIO_OUTPUT ) ); //can1 stb

                ( void ) GPIO_Set( CAN_1_STB, 0UL ); //Set to Low
                */

                break;
            }

            case 2:
            {
                PMIO_SetGPK(CAN_2_FS); //Set to normal k-port

                ( void ) GPIO_Config( CAN_2_TX,     ( uint32 ) ( GPIO_FUNC( 2U ) | GPIO_OUTPUT ) ); //can2 tx
                ( void ) GPIO_Config( CAN_2_RX,     ( uint32 ) ( GPIO_FUNC( 2U ) | GPIO_INPUT ) ); //can2 rx

                /* //CAN_2_STB is not used on EVB
                ( void ) GPIO_Config( CAN_2_STB,    ( uint32 ) ( GPIO_FUNC( 0U ) | GPIO_OUTPUT ) ); //can2 stb

                ( void ) GPIO_Set( CAN_2_STB, 0UL ); //Set to Low
                */

                break;
            }

            default:
            {
                ret = CAN_ERROR_BAD_PARAM;

                break;
            }
        }
    }
    else
    {
        ret = CAN_ERROR_NOT_INIT;
    }

    return ret;
}
