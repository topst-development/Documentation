# 2. 视频输出
---
AI-G 支持通过 MIPI DSI-2 接口进行视频输出。
它通过 15 针 FFC 连接器提供 2 通道 DSI 连接，适用于连接兼容的 MIPI DSI LCD 面板。该接口可在嵌入式显示屏上流畅地渲染图形用户界面、播放视频以及实现实时 AI 可视化。
<br/><br/><br/>

## 2.1 MIPI DSI
---
DSI 是 Display Serial Interface 的缩写，是 MIPI Alliance 定义的标准，用于将显示数据从处理器传输到外部屏幕。它可实现适用于嵌入式 LCD 面板的高速、低功耗通信。  
如上所述，AI-G 通过 15 针 FFC 连接器提供 2 通道 DSI 连接，可连接兼容的 MIPI DSI 显示模块，用于 GUI 渲染、视频播放或实时推理可视化。
<br/><br/>

### 2.1.1 5 英寸 DSI 显示屏
Elecrow 5 英寸 DSI 显示屏是一款分辨率为 800×480 的 LCD，采用 IPS 面板并支持电容式触摸，专为 Raspberry Pi 的 MIPI DSI 接口设计。得益于即插即用功能，无需额外安装驱动程序。该显示屏通过 15 针 MIPI DSI 连接器连接到 AI-G 开发板，并直接由该接口供电，无需外部电源。  
该模块适用于 AI-G 平台上基于 GUI 的应用、实时监控和交互式 AI 演示。

DSI 显示屏的规格如下：

| 规格                | 说明                                |
| ------------------- | -------------------------------------------|
| 显示屏尺寸        | 5 英寸                                     |
| 分辨率          | 800 x 480                                  |
| 刷新率        | 60 Hz                                      |
| 接口 (显示端) | MIPI DSI                                   |
| 接口 (面板端)   | RGB888 端口                                |
| 工作电压   | 3.3V                                      |
| 工作温度范围| -20 °C 至 70 °C                            |
| 线缆类型          | Flat Flexible Cable (FFC) (15 针)                               |
| 兼容性       | Raspberry Pi 和 AI-G (通过 MIPI DSI 接口)|

# 3. 摄像头连接
---
AI-G 支持通过 MIPI CSI-2 接口进行摄像头输入。
默认情况下，它通过 15 针连接器提供 2 通道 CSI 连接。对于需要更高带宽的应用，例如高分辨率或高帧率的 AI 视觉任务，还可通过可选的 20 针连接器支持 4 通道配置。
<br/><br/><br/>

## 3.1 MIPI CSI
---
CSI 是 Camera Serial Interface 的缩写，是 MIPI Alliance 定义的标准接口，用于将摄像头模块连接到主处理器。它可实现从摄像头到处理器的高速、低功耗图像数据传输。  
如上所述，AI-G 默认提供 2 通道 CSI 连接，并可选支持通过 20 针连接器实现的 4 通道配置，以获得更高的数据吞吐量。  

目前，AI-G 仅支持 ArduCam (5 MP) 和 Raspberry Pi v1 Camera (5 MP) 模块。
<br/><br/>

### 3.1.1 ArduCam
ArduCam 是一款专为嵌入式系统和 AI 应用设计的多功能摄像头模块。它支持多种图像传感器和接口，包括 MIPI CSI，因此适合与 AI-G 等开发板集成。  
AI-G 支持具有 2 通道或 4 通道 MIPI CSI 接口的 ArduCam 模块，可为目标检测和图像分类等 AI 视觉任务提供稳定的图像输入。得益于与 FFC 线缆的兼容性，ArduCam 模块可以轻松连接到 AI-G 开发板的 CSI 连接器，为边缘 AI 系统中的实时摄像头输入提供可靠的解决方案。

ArduCam 模块的规格如下：

| 规格                     | 说明                                 |
| ------------------------ | ------------------------------------------- |
| 传感器                   | OV5647 (500 万像素)                        |
| 分辨率               | 2592 × 1944 (Full 5MP)                      |
| 支持的输出格式 | RAW、YUV、JPEG (取决于传感器)           |
| 接口                | MIPI CSI                                    |
| 帧率               | 1080p 下最高 30fps，720p 下 60fps         |
| 镜头接口               | 定焦镜头 (标准)                 |
| 视场角 (FOV)      | 约 54° 至 70° (因型号而异)         |
| 连接方式          | FFC                   |
| 工作电压        | 3.3V (典型值)                              |
| 外形尺寸              | 紧凑型 PCB，约 25 mm x 24 mm                   |
| 兼容性            | Raspberry Pi 和 AI-G (通过 MIPI CSI 端口)      |
| 附加特性      | 低功耗、即插即用模块 |

---
AI-G 通过其 PCIe 插槽支持 M.2 SSD 存储设备。

```
$ fdisk /dev/nvme0n1

Be careful before using the write command.

Command (m for help): 
```

在 fdisk 提示符下依次输入以下按键：

- o — 创建新的空 DOS 分区表 (可选，将清除现有分区表)

- n — 添加新分区

- p — 选择主分区

- 1 — 将分区编号设置为 1

- 按 Enter 键 — 接受默认的起始扇区

- 按 Enter 键 — 接受默认的结束扇区 (使用整个磁盘)

- w — 写入分区表并退出

```
$ mkfs.ext4 /dev/nvme0n1p1

$ mkdir -p /mnt/nvme

$ mount /dev/nvme0n1p1 /mnt/nvme
```

# 5. 以太网连接
---
AI-G 通过板载 RJ45 以太网端口支持以太网连接。这使开发板能够使用标准 TCP/IP 协议与本地网络或互联网通信。以太网通常用于部署需要远程访问、数据流传输或软件更新的 AI 应用程序。
<br/><br/><br/>

## 5.1 通过路由器进行网络连接
---
此方法使用标准路由器将 AI-G 连接到本地网络。开发板可以通过 DHCP 自动获取 IP 地址，也可以配置为静态 IP 地址。
<br/><br/>

### 5.1.1 以读/写方式重新挂载根文件系统
根文件系统以只读方式挂载。请使用以下命令以写入权限重新挂载，以便编辑配置文件：

```
$ mount -o remount,rw /
```
<br/><br/>


### 5.1.2 创建网络配置文件
1. 通过 DHCP 获取动态 IP
要在 eth0 接口上启用 DHCP，请使用以下内容创建或编辑 /etc/systemd/network/20-wired.network 文件。

```
$ vi /etc/systemd/network/20-wired.network
 
[Match]
Name=eth0
 
[Network]
DHCP=yes
```

该配置指示 systemd-networkd 通过 DHCP 为 eth0 接口自动获取 IP 地址。

2. 静态 IP 配置
如果希望分配静态 IP 地址（例如直接与 PC 连接或没有可用的 DHCP 服务器时），请使用以下内容编辑同一文件：
```
$ vi /etc/systemd/network/20-wired.network

[Match]
Name=eth0

[Network]
Address=192.168.137.2/24
Gateway=192.168.137.1
DNS=8.8.8.8
```

此设置将 IP 地址设为 192.168.137.2，使用 192.168.137.1 作为网关（在 Windows ICS 中较为常见），并配置 Google DNS。
<br/><br/>


### 5.1.3 重启网络服务
重启 systemd-networkd 服务以应用新的网络配置：

```
sudo systemctl restart systemd-networkd
```
<br/><br/>

## 6.1 GPIO 数字输入/输出

AI-G 开发板通过其 40 针排针支持数字输入和输出 (GPIO)，使用户能够与按钮、LED 和传感器等外部设备交互。 
<br/><br/><br/>

### 6.1.1 LED
---
最简单也最常见的 GPIO 输出示例之一是控制 LED。  
为演示数字输出，可以将 LED 连接到 40 针排针上的某个 GPIO 引脚。在此示例中，LED 的负极（短脚）连接到 AI-G 开发板的 GND 引脚，正极（长脚）直接连接到 GPIO72。

#### 步骤 1. 硬件要求
- AI-G 开发板 (x1)
- 面包板 (x1)
- LED (x1)
- 公对母跳线 (x2)
- DC 5V 电源适配器 (x1)
- USB 转 TTL 串口线 (x1)

#### 步骤 2. 示例电路
- LED
    - (+) 引脚连接到 AI-G 开发板的 26 号引脚。
    - (-) 引脚连接到 AI-G 开发板上作为 GND 的 14 号引脚。

#### 步骤 3. 执行方法
要驱动连接到 AI-G 开发板 GPIO72 的 LED，请运行以下代码：

```bash
#!/bin/bash

GPIO=72
INTERVAL=1

# GPIO export
if [ ! -e /sys/class/gpio/gpio$GPIO ]; then
    echo "$GPIO" > /sys/class/gpio/export
    sleep 0.1
fi

echo "out" > /sys/class/gpio/gpio$GPIO/direction

trap "echo $GPIO > /sys/class/gpio/unexport; echo -e '\nGPIO$GPIO unexported. Exit.'; exit" SIGINT

echo "Toggling GPIO$GPIO every $INTERVAL second(s). Press Ctrl+C to stop."

while true; do
    echo 1 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
    echo 0 > /sys/class/gpio/gpio$GPIO/value
    sleep $INTERVAL
done
```

#### 步骤 4. 执行结果
使用以下命令运行代码。
```
$ ./AI_GPIO_LED_TEST
```

该脚本将 GPIO72 配置为数字输出，并每隔 1 秒持续切换其状态。运行后，连接到 GPIO72 的 LED 会反复闪烁，以无限循环的方式亮 1 秒、灭 1 秒。

要停止脚本，请按 **[Ctrl+C]**。  
脚本终止后，GPIO72 会自动取消导出并被清理。  
运行前请确保已为脚本赋予执行权限：
```bash
$ chmod +x AI_GPIO_LED_TEST
```

**注意**：此设置未包含限流电阻。虽然短时间测试时可能正常工作，但建议在 LED 上串联一个电阻，以避免可能损坏 GPIO 引脚。

    if [ "$VALUE" = "1" ] && [ "$PREV_VALUE" = "0" ]; then
        echo "Gas detected! (value: 1)"
    fi
    PREV_VALUE=$VALUE
    sleep 0.1
done
```

## 6.2 I2C
---
AI-G 通过 40 引脚 GPIO 排针提供 I2C 通信，可与传感器、显示器和扩展模块等各种外围设备连接。Inter-integrated Circuit (I2C) 是一种由数据线 (SDA) 和时钟线 (SCL) 组成的两线制通信协议，允许多个设备通过共享总线进行通信。

I2C 通信采用主从架构，由一个主设备控制通信，同一总线上最多可连接 127 个从设备。SDA 线用于数据的发送和接收，SCL 线用于同步数据传输的时序。这种同步通信模型使设备能够以时钟驱动的协调方式交换信息。
<br/><br/><br/>

要访问 AI-G 开发板上的 I2C 设备，需要使用 i2c-dev 接口编写 C 程序，并针对目标架构进行交叉编译。  
以下是一个简单的示例 (I2C_TEST.c)：

```
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <linux/i2c-dev.h>
#include <sys/ioctl.h>
#include <unistd.h>

#define I2C_DEV "/dev/i2c-1"
#define I2C_ADDR 0x27

// RS: 0 = command, 1 = data
void lcd_send_byte(int fd, unsigned char data, unsigned char mode) {
    unsigned char high = mode | (data & 0xF0) | 0x08; // backlight on
    unsigned char low  = mode | ((data << 4) & 0xF0) | 0x08;
    unsigned char buf[4] = { high | 0x04, high, low | 0x04, low }; // toggle EN bit

    for (int i = 0; i < 4; i++) {
        if (write(fd, &buf[i], 1) != 1) {
            perror("I2C write error");
        }
        usleep(1000); // 1ms delay
    }
}

void lcd_command(int fd, unsigned char cmd) {
    lcd_send_byte(fd, cmd, 0x00);
}

void lcd_data(int fd, unsigned char data) {
    lcd_send_byte(fd, data, 0x01);
}

void lcd_init(int fd) {
    usleep(50000); // wait for LCD power on
    lcd_command(fd, 0x33); // init
    lcd_command(fd, 0x32); // 4-bit mode
    lcd_command(fd, 0x28); // 2 line, 5x8 font
    lcd_command(fd, 0x0C); // display on, cursor off
    lcd_command(fd, 0x06); // entry mode
    lcd_command(fd, 0x01); // clear display
    usleep(2000);
}

void lcd_print(int fd, const char* str) {
    while (*str) {
        lcd_data(fd, *str++);
    }
}

int main() {
    int fd = open(I2C_DEV, O_RDWR);
    if (fd < 0) {
        perror("Failed to open I2C device");
        return 1;
    }

    if (ioctl(fd, I2C_SLAVE, I2C_ADDR) < 0) {
        perror("Failed to set I2C address");
        close(fd);
        return 1;
    }

    lcd_init(fd);
    lcd_print(fd, "test pass!");

    close(fd);
    return 0;
}
```

## 6.3 SPI
---
AI-G 通过 40 引脚 GPIO 排针支持 Serial Peripheral Interface (SPI) 通信，可实现外部设备与开发板之间的数据交换。  

SPI 是一种同步串行通信协议，支持全双工通信，即可以同时发送和接收数据。它使用四条主要信号线：Master Out Slave In (MOSI)、Master In Slave Out (MISO)、Serial Clock (SCLK) 和 Slave Select (SS)。

与多个设备共用信号线的 I2C 不同，SPI 需要为每个从设备提供专用的 SS 线。这种一对多结构使 SPI 速度快且易于实现，但在连接多个设备时可能需要更多的物理接线。
<br/><br/><br/>

```
#include <stdio.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>
#include <linux/spi/spidev.h>
#include <sys/ioctl.h>
#include <string.h>

#define SPI_DEV "/dev/spidev3.0"

int spi_fd = -1;

void spi_send(uint8_t address, uint8_t data) {
    uint8_t tx[2] = { address, data };
    struct spi_ioc_transfer tr = {
        .tx_buf = (uintptr_t)tx,
        .rx_buf = 0,
        .len = 2,
        .delay_usecs = 0,
        .speed_hz = 1000000,
        .bits_per_word = 8,
    };

    if (ioctl(spi_fd, SPI_IOC_MESSAGE(1), &tr) < 1) {
        perror("SPI send failed");
    }
}

void max7219_init() {
    spi_send(0x09, 0x00); // Decode mode off
    spi_send(0x0A, 0x08); // Brightness (0x00 ~ 0x0F)
    spi_send(0x0B, 0x07); // Scan limit: display all 8 digits
    spi_send(0x0C, 0x01); // Shutdown register: normal operation
    spi_send(0x0F, 0x00); // Display test: off
}

void max7219_clear() {
    for (int i = 1; i <= 8; i++) {
        spi_send(i, 0x00);
    }
}


const uint8_t letter_P[8] = {
    0b00000000,  
    0b01111110, 
    0b01000010,  
    0b01000010,  
    0b01111110,  
    0b01000000,  
    0b01000000,  
    0b01000000   
};


void draw_letter_P() {
    for (int row = 0; row < 8; row++) {
        spi_send(row + 1, letter_P[row]);
    }
}

int main() {
    spi_fd = open(SPI_DEV, O_RDWR);
    if (spi_fd < 0) {
        perror("Failed to open SPI device");
        return 1;
    }

    max7219_init();
    max7219_clear();
    draw_letter_P();

    close(spi_fd);
    return 0;
}

## 6.4 UART
---
AI-G 通过其 40 引脚 GPIO 排针支持 Universal Asynchronous Receiver/Transmitter (UART) 通信，可与串行控制台和其他微控制器等设备进行串行通信。  

UART 是一种广泛使用的异步通信协议，通过 TX（发送）和 RX（接收）两条线路每次传输一位数据。与 I2C 或 SPI 不同，UART 不使用时钟线。取而代之的是，两个设备必须使用相同的通信速率来保证时序一致。
<br/><br/><br/>

#### 步骤 3. 执行方法
该脚本向 UART 端口发送测试消息，并检查是否接收到相同的消息。  
要在 AI-G 上测试 UART 回环，请在将 TX 与 RX 引脚连接在一起后运行以下脚本。

```bash
#!/bin/bash
# ===================== user setting =====================
UART_DEV="/dev/ttyAMA1"       # uart
BAUD=115200                   # Baudrate
TEST_MSG="Hello from UART"    # msg
TEMP_FILE="/tmp/uart_rx.txt"  # file
# =====================================================

if [ ! -e "$UART_DEV" ]; then
    echo "Error: $UART_DEV does not exist"
    exit 1
fi

chmod 666 $UART_DEV

stty -F $UART_DEV $BAUD cs8 -cstopb -parenb -icanon -echo -ixon -ixoff
echo "UART setup complete: port=$UART_DEV, speed=$BAUD"

cat $UART_DEV > $TEMP_FILE &
RX_PID=$!

sleep 0.2
echo -n "$TEST_MSG" > $UART_DEV
echo "Transmission complete: \"$TEST_MSG\""

sleep 1
kill $RX_PID 2>/dev/null

if [ -f "$TEMP_FILE" ]; then
    RECEIVED=$(cat $TEMP_FILE)
    rm $TEMP_FILE
    if [ "$RECEIVED" = "$TEST_MSG" ]; then
        echo "Loopback Success! Received Message: \"$RECEIVED\""
    else
        echo "Received mismatch"
        echo "Sent: \"$TEST_MSG\""
        echo "Received: \"$RECEIVED\""
    fi
else
    echo "Failed to receive: No received file"
fi
```
