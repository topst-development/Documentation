# 1. 简介
---
Neural Processing Unit (NPU) 是一种 HW 神经网络加速器，AI-G 中的 NPU 针对目标检测、图像分类和人脸检测等 
视觉应用的神经网络推理进行了优化。NPU 设备驱动程序提供了控制 NPU 的接口，
使用户空间的神经网络应用程序能够在嵌入式 Linux 环境中使用 AI-G NPU 进行 
神经网络推理。

本文档介绍如何使用 AI-G SDK 中包含的 NPU 设备驱动程序和 NPU API。
<br/><br/><br/><br/>


# 2. NPU Linux 设备驱动程序
---
NPU 设备驱动程序控制以下内容：

- NPU HW 的初始化
- 将编译后的神经网络传输到 NPU HW
- NPU HW 的执行
- 读取 NPU HW 处理（推理）结果。

NPU 设备驱动程序使用的缓冲区（code、weight、work、input 和 output）需要连续的物理内存空间。因此， 
内存上的缓冲区在内部使用 Continuous Memory Allocator (CMA) 进行分配。
NPU 设备驱动程序接收编译后神经网络的 command 文件和 weight/bias 文件作为输入，以生成网络文件描述符 
(fd)。它还会分配神经网络的输入以及用于存储结果的缓冲区，并生成用于访问 
各缓冲区的 buffer fd。 

要执行推理，
1. 对输入缓冲区的 buffer fd 执行 mmap，以获取可从用户空间访问的输入缓冲区地址。
2. 使用步骤 1 中获取的输入缓冲区地址，将输入图像存储到输入缓冲区中。
3. 将名为 NPU_NET_IOCTL_RUN 的 IOCTL 传递给 network fd。

当执行两个或更多神经网络时，NPU 设备驱动程序采用时分算法执行神经网络。 
在这种情况下，由于执行顺序在内部使用 queue.f 命令进行调度，因此神经网络按用户空间请求的 
顺序执行。

## 2.2 设备树
---
以下示例是在 AI-G 中使用 NPU 设备驱动程序的设备树。

```
# NPU device tree example

 npu0: npu@11000000 {
                compatible = "telechips,npu";
                reg = <0x0 0x11000000 0x0 0x400>;
                interrupts = <GIC_SPI 153 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_0_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_0_CCLK &fbus_npu FBUS_NPU_0_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };


npu1: @11000400 {
                compatible = "telechips,";
                reg = <0x0 0x11000400 0x0 0x400>;
                interrupts = <GIC_SPI 154 IRQ_TYPE_LEVEL_HIGH>;
                clocks = <&fbus_npu FBUS_NPU_1_ACLK &fbus_npu FBUS_NPU_PCLK
                &fbus_npu FBUS_NPU_1_CCLK &fbus_npu FBUS_NPU_1_CPUCLK >;
                clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
                disable-ue-fail = <0>;
                disable-ce-fail = <0>;
                disable-wdt = <0>;
                /* <800000000> is 1000ms for timeout at 800MHz of MLX */
                wdt-timeout-count = <800000000>;
                /* <400000000> is 500ms for re-arm interval at 800Mhz of MLX */
                wdt-rearm-count = <400000000>;
                work-buffer-size = <200000000>;
                status = "disabled";
        };

```

<br/>

| 属性 | 说明 |
|------------------|---------------------------------------|
| compatible       | 固定为 “telechips,npu” |
| reg              | NPU 寄存器的基地址和大小 |
| disable-ue-fail  | 禁用由 UE 错误导致的失败。 <br>如果 disable-ue-fail 为 0，则检测到 UE 错误时返回 fail。 <br>或 <br>如果 disable-ue-fail 为 0x7，则忽略 UE 错误。 |
| disable-ce-fail  | 禁用由 CE 错误导致的失败。 <br>如果 disable-ce-fail 为 0，则检测到 CE 错误时返回 fail。 <br>或 <br>如果 disable-ce-fail 为 0x7，则忽略 CE 错误。 |
| disable-wdt      |  禁用看门狗定时器 |
| wdt-timeout-count| 看门狗超时计数 |
| wdt-rearm-count  | 看门狗重新装载计数<br>该值应小于看门狗超时计数。 |
| reg-names        | NPU 寄存器名称 |
| work-buffer-size | 工作缓冲区分配大小 |
| interrupt-parent | 中断控制器设备树节点 |
| interrupts       | 中断编号 |

### 2.3.1 用于 NPU 文件描述符的 IOCTL 命令

NPU 文件描述符可通过打开 /dev/npu0 和 /dev/npu1 等
NPU 设备文件来获取。可用的 IOCTL 命令如下。


| 命令 | 参数 | 说明 |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req*  | 分配 CMA 缓冲区 |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req*   | 加载网络 |
| NPU_IOCTL_READ_REG     | struct reg_access_req* | 从寄存器读取值 |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req* | 向寄存器写入值 |
| NPU_IOCTL_RESET_NPU    | struct npu_init_req*   | 复位 NPU |
| NPU_IOCTL_WRITE_TEST_CFG| test_cfg_wr_req_t*    | 写入 ecc_test |
| NPU_IOCTL_READ_NPU_ERR | npu_err_rd_req_t*      | 读取 ECC 和 WDT |

<br/>

NPU_IOCTL_ALLOC_BUFFER 命令 
- 使用通过结构体 buffer_alloc_req 传递的
size 值分配 CMA 缓冲区，并且
- 返回缓冲区文件描述符。

NPU_IOCTL_LOAD_NETWORK 命令 
- 分配用于存储通过结构体 net_load_req 传递的参数的 CMA 缓冲区，
- 将参数复制到已分配的 CMA 缓冲区，并且 
- 返回网络文件描述符。

NPU_IOCTL_WRITE_TEST_CFG 和 NPU_IOCTL_READ_NPU_ERR 是通过 test_cfg_wr_req_t 传输的 NPU 测试参数 
值，两者均用于读取测试结果值。

### 2.3.2 网络文件描述符的 IOCTL 接口

网络文件描述符可以通过向 NPU 文件描述符传递
NPU_IOCTL_LOAD_NETWORK 命令来创建。它支持
poll 和 close 等操作。可用的 IOCTL 命令如下
所示。

<br/>

|         命令            |         参数         |         说明      |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req*     | 运行推理            |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req* | 分析推理周期 |
| NPU_NET_IOCTL_SET_COLOR_FMT | int                      | 设置输入颜色格式   |

<br/>

执行 NPU_NET_IOCTL_RUN 时，NPU 驱动程序会向 NPU HW 发送运行
网络的命令，推理结束的时间点可以
通过调用 poll 来确认。

### 2.3.3 缓冲区文件描述符的 IOCTL 接口

缓冲区文件描述符: 
- 可以通过向 NPU 文件描述符发送 NPU_IOCTL_ALLOC_BUFFER 命令来生成。 
- 支持 mmap、close 等操作。 
- 不支持 IOCTL 命令 
- 通过 mmap 操作从用户模式获取 CMA 缓冲区
- 通过 close 操作释放 CMA 缓冲区。
