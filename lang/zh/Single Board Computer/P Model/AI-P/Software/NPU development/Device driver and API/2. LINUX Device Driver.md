# 2. NPU LINUX 设备驱动程序

TOPST AI 的 NPU 是一个 HW 神经网络加速器。它针对目标检测、图像分类和
人脸检测等视觉应用神经网络的推理进行了
优化。“TOPST-AI-Common-SW-NPU-Toolkit Guide” 文档介绍了如何
使用 NPU Toolkit
的方法。

1.  NPU 设备驱动程序控制 NPU HW 的初始化、将编译后的神经网络传送至 NPU HW、NPU
    HW 的执行以及 NPU HW 处理（推理）结果的读取。
2.  NPU 设备使用的缓冲区（code、weight、work、input 和 output）
    需要连续的物理内存空间。
    为此，内存上的缓冲区在内部使用 Continuous Memory Allocator (CMA)
    进行分配。
3.  NPU 设备驱动程序接收编译后的神经网络的 command 文件和 weight/bias 文件
    作为输入，以生成网络文件
    描述符（fd）。
4.  它还负责分配神经网络的输入以及用于保存结果的缓冲区，并生成用于访问
    各缓冲区的缓冲区 fd 的
    工作。
5.  为了执行推理，首先对输入缓冲区的缓冲区 fd 执行 mmap，
    以获取可从用户空间访问的输入缓冲区地址；其次，
    将输入图像保存到以此方式获取的输入缓冲区中；
    最后向网络 fd 传递 **名为 NPU_NET_IOCT_RUNCT
    的 IOL**。
6.  当执行两个或两个以上的神经网络时，NPU 设备驱动程序
    以时分算法执行神经网络。
7.  在这种情况下，由于执行顺序在内部使用 command queue 进行调度，
    神经网络将按照用户空间请求的顺序
    执行。

## 2.2 设备树

在 TOPST AI 中，使用 NPU 设备驱动程序所需的信息按如下方式
通过设备树进行设置。

```
# NPU device tree example

npu0: npu0 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000000 0x0 0x200>;
		interrupts = <GIC_SPI 146 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};

npu1: npu1 {
		compatible = "telechips,npu";
		reg = <0x0 0x11000200 0x0 0x200>;
		interrupts = <GIC_SPI 147 IRQ_TYPE_LEVEL_HIGH>;
		clocks = <&clk_npu NPUB_ACLK &clk_npu NPUB_PCLK
		&clk_npu NPUB_CCLK &clk_npu NPUB_CPUCLK >;
		clock-names = "npubus_aclk", "npubus_pclk", "npubus_cclk", "npubus_cpu";
		status = "disabled";
		work-buffer-size = <100000000>;
	};
```

<br/>

|       属性       |                 说明                  |
|------------------|---------------------------------------|
| compatible       | 固定为 “telechipss, npu”              |
| reg              | NPU 寄存器 base address、size         |
| reg-names        | NPU 寄存器名称                        |
| work-buffer-size | Work 缓冲区分配大小                   |
| interrupt-parent | 中断控制器设备树节点                  |
| interrupts       | 中断编号                              |

### 2.3.1 IOCTL 命令

可通过打开 /dev/npu0 和 /dev/npu1 等 NPU 设备文件来获取
NPU 文件描述符。可用的 IOCTL 命令如下。

<br/>

|          命令          |          参数           |          说明           |
|------------------------|-------------------------|-------------------------|
| NPU_IOCTL_ALLOC_BUFFER | struct buf_alloc_req\*  | 分配 CMA 缓冲区         |
| NPU_IOCTL_LOAD_NETWORK | struct net_load_req\*   | 加载网络                |
| NPU_IOCTL_INIT_MLX     | struct mlx_init_req\*   | 初始化 MLX              |
| NPU_IOCTL_READ_REG     | struct reg_access_req\* | 从寄存器读取值          |
| NPU_IOCTL_WRITE_REG    | struct reg_access_req\* | 向寄存器写入值          |
| NPU_IOCTL_RESET_NPU    |                         | 复位 NPU                |

<br/>

NPU_IOCTL_ALLOC_BUFFER 命令使用通过结构体 buffer_alloc_req 传递的
size 值分配 CMA 缓冲区，并返回缓冲区文件
描述符。
NPU_IOCTL_LOAD_NETWORK 命令分配用于保存通过结构体 net_load_req
传递的参数的 CMA 缓冲区，将这些参数复制到所分配的 CMA 缓冲区，
并返回网络文件
描述符。

### 2.3.2 用于网络文件描述符的 IOCTL 接口

网络文件描述符可通过向 NPU 文件描述符传递
NPU_IOCTL_LOAD_NETWORK 命令来创建。它支持
poll 和 close 等操作。可用的 IOCTL 命令
如下。

<br/>

|            命令            |           参数           |           说明           |
|----------------------------|--------------------------|--------------------------|
| NPU_NET_IOCTL_RUN          | struct net_run_req\*     | 执行推理                 |
| NPU_NET_IOCTL_PROFILE      | struct net_profile_req\* | 分析推理周期             |
| PU_NET_IOCTL_SET_COLOR_FMT | int                      | 设置输入颜色格式         |

<br/>

执行 NPU_NET_IOCTL_RUN 时，NPU 驱动程序会向 NPU HW 发送运行
网络的命令，而推理结束的时间点可通过调用 poll
来确认。

### 2.3.3 用于缓冲区文件描述符的 IOCTL 接口

缓冲区文件描述符可通过向 NPU 文件描述符传递
NPU_IOCTL_ALLOC_BUFFER 命令来生成。

缓冲区文件描述符支持 mmap、close 等操作。

缓冲区文件描述符不支持 IOCTL 命令。在用户模式下通过 mmap
获取 CMA 缓冲区。通过 close 释放 CMA 缓冲区。
